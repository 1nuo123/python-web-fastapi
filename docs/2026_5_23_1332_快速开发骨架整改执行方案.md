# 快速开发骨架整改执行方案

## 任务目标
交付一套面向后续真实改码与测试回归的骨架整改方案，解决本地直启不顺、异常日志敏感信息风险、配置与资源装配过重、应用层依赖基础设施、Web 模块新增不够集中等问题。

完成判定：
- 本地 `uvicorn src.main:app` 可在开发环境下按明确规则读取本地 `.env` 或环境变量完成启动。
- 异常日志、数据库日志和降级日志不落明文密码、token、连接串凭据和完整敏感 traceback。
- 配置加载和资源挂载至少完成第一轮热点拆分，后续新增配置或资源无需持续堆入巨型文件。
- 应用层用例不再直接依赖基础设施实现类型。
- 新增 Web 模块有集中注册入口，不再必须改核心枚举与硬编码导入清单。

## 全局约束
- 以源码为准；若文档、图谱、历史方案与源码冲突，以源码为准，并在文档回归中说明历史文档可能过期。
- 不提交真实 `.env`、真实密钥、真实密码、真实 token、真实生产连接串。
- 生产环境禁止从仓库 `.env` 自动补齐密钥；生产敏感值只允许来自进程环境变量、Compose Secret 或外部 Secret Manager。
- 契约设计统一采用“公共头字段 + 强类型扩展字段”；外层公共字段承载稳定字段，扩展字段使用 Pydantic 判别联合。
- 所有扩展字段必须包含 `kind`、`schema_version`，必须启用 `extra="forbid"`。
- 禁止用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议字段。
- 外层类型与内层扩展类型必须一致，例如 `redaction.header.kind` 必须与 `redaction.detail.kind` 语义一致。
- 兼容现有接口响应结构、现有测试工厂、现有 Compose 开发路径。
- 拆分优先做边界提取，不做无关重写；每阶段完成后必须能独立校验。

## 验收标准
- 清空 `JWT_SECRET`、`AUTH_BOOTSTRAP_ADMIN_PASSWORD` 后，本地开发环境能按 `.env` 规则启动；生产环境仍因缺失外部密钥失败。
- 异常响应和结构化日志均不包含明文连接串密码、Bearer token、JWT、`password=`、`*_PASSWORD=` 等敏感值。
- `app_settings_loader.py` 不再承载 dotenv 读取、递归 merge、安全校验全部实现细节。
- `shared_resource_mount.py` 至少完成资源构建/释放或访问器刷新逻辑的独立模块提取。
- `src/application/*` 不再直接 import `src.infrastructure.auth.*` 或 `src.infrastructure.settings.*`。
- 新增一个示例 Web 模块时，只需在集中 manifest/registry 中登记，不需要改核心模块枚举。
- 单元、契约、异常、接口、路径和集成回归测试通过。
- 相关设计文档、使用说明和测试说明与源码一致。

4. 回归修复

- Phase 1 是本地启动基线，Phase 2 至 Phase 5 均依赖稳定配置加载入口。
- Phase 2 可在 Phase 1 后独立实施，但日志测试依赖测试环境能稳定创建 app。
- Phase 3 依赖 Phase 1 的配置加载边界，优先拆分配置，再拆分资源挂载。
- Phase 4 依赖 Phase 3 固定后的端口与资源访问边界。
- Phase 5 依赖 Phase 3 的配置模型和 Phase 4 的应用层隔离结果。
- 新增或修改测试依赖 Phase 1 至 Phase 5 的源码改造完成。
- 真实测试依赖测试补齐完成。
- 回归修复依赖真实测试失败结果。
- 文档回归依赖最终源码和测试结果固定。

## Phase 1 本地直启与环境加载收口
### 目标
解决本地 `uvicorn src.main:app` 因缺失进程环境变量而启动失败的问题。

阶段完成后：开发环境可读取本地 `.env`，生产环境仍必须依赖外部环境变量。

### 依赖
- 当前 `AppSettingsLoader`。
- 当前 `.env`、`.env.docker.example`、`.env.production.example`。
- 当前 `config/runtime/auth_runtime/auth_runtime_base.toml` 不提供默认 `jwt_secret` 的安全基线。

### 模拟用法
```powershell
$env:APP_ENV="development"
uvicorn src.main:app --reload
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `SettingsSourceHeader` | 配置来源公共头 | 承载 `kind`、`schema_version`、`environment`、`source_name`。 |
| `ProcessEnvironmentSourceDetail` | 进程环境变量来源扩展 | `kind="process_environment"`，描述从 `os.environ` 读取的配置来源。 |
| `DotenvSourceDetail` | 本地 dotenv 来源扩展 | `kind="dotenv_file"`，描述开发/测试环境允许读取的 `.env` 文件路径与启用状态。 |
| `SettingsSourceEnvelope` | 配置来源信封 | 外层公共头 + 判别联合扩展；扩展含 `kind`、`schema_version`，`extra="forbid"`。 |
| `LocalStartupPolicy` | 本地启动策略 | 声明开发/测试允许 `.env` 补齐，生产禁止 `.env` 补齐。 |

### 任务清单
- [ ] 新增 `dotenv_settings_loader.py`，用标准库解析简单 `KEY=VALUE`，不记录值。
- [ ] 调整 `AppSettingsLoader.load()`，先解析有效环境，再按 `process env > local .env > TOML` 合并。
- [ ] 生产环境显式跳过仓库 `.env`，缺失 `JWT_SECRET` 继续失败。
- [ ] 开发环境缺失 `JWT_SECRET`、`AUTH_BOOTSTRAP_ADMIN_PASSWORD` 时可由 `.env` 补齐。
- [ ] `.env.docker.example` 补充本地直启变量说明。
- [ ] `.env.production.example` 明确生产不读取仓库 `.env`。

### 关键代码片段
```python
SettingsSourceDetail = Annotated[
    ProcessEnvironmentSourceDetail | DotenvSourceDetail,
    Field(discriminator="kind"),
]

class SettingsSourceEnvelope(BaseModel):
    model_config = ConfigDict(extra="forbid")
    header: SettingsSourceHeader
    detail: SettingsSourceDetail
```

### 校验
- 清空进程级 `JWT_SECRET` 后，开发环境能从 `.env` 构建 `ApplicationSettings`。
- `APP_ENV=production` 且缺失进程级 `JWT_SECRET` 时仍启动失败。
- 日志不输出 `.env` 中的具体值。

## Phase 2 异常日志脱敏

### 依赖

- 当前 `LogEventBuilder`、`DatabaseLogWriter`、异常呈现器。
- 当前异常响应脱敏测试作为回归基础。

### 契约

|---|---|---|
| `LogRedactionHeader` | 日志脱敏公共头 | 承载 `kind`、`schema_version`、`rule_set_name`。 |
| `CredentialUrlRedactionDetail` | 凭据 URL 脱敏扩展 | `kind="credential_url_redaction"`，用于连接串用户名密码脱敏。 |
| `BearerTokenRedactionDetail` | Bearer Token 脱敏扩展 | `kind="bearer_token_redaction"`，用于 HTTP Authorization 与 JWT 类文本脱敏。 |
