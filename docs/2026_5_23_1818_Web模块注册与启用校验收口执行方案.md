# Web模块注册与启用校验收口执行方案

## 任务目标
交付一套面向后续真实改码与测试回归的执行方案，解决 Web provider 注册存在装饰器注册与 manifest 导入路径双机制、`app.modules.enabled` 中未知模块被静默忽略的问题。

完成判定：
- `WebBundleCatalog` 只以 `src/api/web_module_manifest.py` 中的 manifest 导入路径作为 provider 主加载路径。
- 路由 provider 类不再通过 `WebBundleCatalog.register_provider_type` 装饰器注册。
- 应用启动时发现 `app.modules.enabled` 包含未知模块必须直接失败，不能被 `FastApiRouteComposer` 静默过滤。
- 单元、边界、路径和全量回归测试通过。

## 全局约束
- 以源码为准；当前历史文档已声明 manifest 收口完成，但源码仍保留 `register_provider_type` 装饰器注册入口，相关历史说明可能过期。
- 保持现有 `/health/*`、`/auth/*`、`/system/info` 路径、OpenAPI 路径和响应结构不变。
- 保留 `ApplicationModuleName` 作为内置模块常量，不能让它重新成为新增模块必改入口。
- `WebBundleCatalog` 是 manifest 加载、provider 导入、一致性校验和启用模块校验的边界；避免在配置模型中反向硬编码 API provider 清单。
- 配置错误必须在应用创建或启动阶段明确失败，错误信息需包含未知模块名与可用模块范围。
- 契约继续遵循“公共头字段 + 强类型扩展字段”规则。
- 扩展字段必须使用 Pydantic 判别联合，必须包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止新增 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议字段。
- 外层类型与内层扩展类型的 `kind`、`schema_version` 必须一致。
- 不做无关重构，不改真实密钥、环境变量示例值和非 Web 模块行为。

## 验收标准
- `rg "register_provider_type" src/api -S` 无命中。
- `WebBundleCatalog().list_provider_envelopes()` 仍能按 manifest 加载健康、鉴权、系统概览 provider。
- `TestAppFactory().create(overrides={"app": {"modules": {"enabled": ["unknown_module"]}}})` 或等价启动入口失败。
- 未知模块失败信息包含 `unknown_module`，并能定位到 `app.modules.enabled`。
- 已有模块禁用行为保持：未出现在 `app.modules.enabled` 的已知模块不挂载路由。
- `python -m compileall -q src test` 通过。
- 相关单元、边界、路径、集成和全量 pytest 回归通过。
- `docs/design_docs/FastAPI统一Web基础设施实现规格.md` 中的 Web 模块注册说明与源码一致。

## Phase 1
### 目标
收敛 Web provider 注册机制，删除装饰器注册路径，让 manifest provider import path 成为唯一主加载路径。

阶段完成后：新增或调整 Web 模块只需要维护 `WebModuleManifestRegistry` 中的 manifest 条目，`register_provider_type` 不再存在。

### 依赖
- `src/api/web_module_manifest.py` 已能声明内置模块 provider 导入路径。
- `WebBundleCatalog._load_provider_type()` 已能按 import path 动态导入 provider。
- 三个现有 provider 类仍保留 `module_name` 与 `provide()` 契约。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `WebModuleHeader` | Web 模块公共头 | manifest 外层公共头，承载 `kind`、`schema_version`、`module_name`、`enabled`；与扩展字段类型一致。 |
| `RouterProviderDetail` | 路由提供者扩展 | Pydantic 判别联合扩展，`kind="router_provider"`，承载 `provider_import_path`、`route_tags`，`extra="forbid"`。 |
| `WebModuleManifestEnvelope` | Web 模块清单信封 | 公共头 + 强类型扩展字段；校验 header/detail 的 `kind` 与 `schema_version` 一致。 |
| `WebBundleProviderEnvelope` | Web Bundle 提供者信封 | provider 输出信封，继续校验 `module_name` 与 manifest、bundle 一致。 |
| `WebBundleCatalog` | Web Bundle 目录 | 只从 manifest 加载 provider，不再维护 `_provider_types` 注册表。 |

### 任务清单
- [x] 删除 `WebBundleCatalog._provider_types`。
- [x] 删除 `WebBundleCatalog.register_provider_type()`。
- [x] 移除健康、鉴权、系统概览 provider 类上的 `@WebBundleCatalog.register_provider_type`。
- [x] 清理 route provider 文件中仅为装饰器存在的 `WebBundleCatalog` 依赖。
- [x] 保留并复用 `_load_provider_type()` 的 manifest 动态导入逻辑。
- [x] 保留重复模块名、provider 缺失、provider 类型错误、provider 与 manifest 模块名不一致校验。

### 关键代码片段
```python
class WebBundleCatalog:
    def list_provider_envelopes(self) -> list[WebBundleProviderEnvelope]:
        envelopes = []
        for entry in self._manifest_entries:
            if not entry.header.enabled:
                continue
            provider_type = self._load_provider_type(entry)
            envelope = provider_type().provide()
            self._validate_provider_envelope(entry=entry, envelope=envelope)
            envelopes.append(envelope)
        return envelopes
```

### 校验
- `rg "register_provider_type" src/api -S` 无命中。
- `WebBundleCatalog().list_provider_envelopes()` 返回三类内置模块 provider。
- 禁用 manifest 条目仍不会进入 `build()` 结果。

## Phase 2
### 目标
新增启动期未知模块校验，确保 `app.modules.enabled` 中不存在 manifest 未登记模块。

阶段完成后：`enabled_modules` 包含未知值时应用创建失败；已知但未启用的模块仍按配置不挂载。

### 依赖
- Phase 1 已确认 manifest 是唯一 provider 来源。
- `FastApiAppAssembler` 已在路由装配前创建 `WebBundleCatalog`。
- `FastApiRouteComposer` 当前会按 `enabled_modules` 过滤 bundle，需要避免继续静默吞掉未知项。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `enabled_modules` | 启用模块列表 | 来自 `app.modules.enabled`，元素必须是 manifest 已登记 `module_name`。 |
| `known_module_names` | 已知模块名集合 | 来自 `WebBundleCatalog` 当前 manifest 条目，用于启动期校验。 |
| `UNKNOWN_ENABLED_MODULE_MESSAGE` | 未知启用模块错误 | 当启用项不在 manifest 中时抛出，错误需包含未知模块名与配置路径。 |
| `WebModuleManifestEnvelope` | Web 模块清单信封 | 继续作为可用模块范围的唯一契约来源，遵守公共头 + 强类型扩展字段规则。 |

### 任务清单
- [x] 在 `WebBundleCatalog` 增加列出 manifest 模块名的方法。
- [x] 在 `WebBundleCatalog` 增加 `validate_enabled_modules(enabled_modules: list[str])` 或等价校验入口。
- [x] 校验未知项时保留原始顺序，错误信息列出所有未知模块。
- [x] 在 `FastApiAppAssembler` 调用 `web_bundle_catalog.build()` 和 `FastApiRouteComposer.compose()` 前执行校验。
- [x] 保留 `ApplicationModuleSwitchSettings` 对重复值、空字符串的已有校验。
- [x] 将 `test_runtime_boundary.py` 中未知模块“应加载”的预期改为启动失败。

### 关键代码片段
```python
class WebBundleCatalog:
    def list_module_names(self) -> list[str]:
        return [entry.header.module_name for entry in self._manifest_entries]

    def validate_enabled_modules(self, enabled_modules: list[str]) -> None:
        known = set(self.list_module_names())
        unknown = [name for name in enabled_modules if name not in known]
        if unknown:
            raise ValueError(
                f"app.modules.enabled 包含未知 Web 模块: {', '.join(unknown)}"
            )
```

### 校验
- 手动创建 catalog 并调用 `validate_enabled_modules(["health_probe"])` 不报错。
- 调用 `validate_enabled_modules(["health_probe", "unknown_module"])` 抛出明确错误。
- `FastApiRouteComposer` 对已知模块禁用行为不变。
