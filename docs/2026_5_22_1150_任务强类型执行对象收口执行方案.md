# 任务强类型执行对象收口执行方案

## 任务目标
将任务消费链路从“仅校验 payload、handler 仍接收原始信封”收口为“校验即解析、handler 接收强类型执行对象”。

完成判定：
- handler 侧统一接收 `TypedTaskInvocation[T]`
- 注册侧一次性返回“已解析 payload + binding + message”的对象
- `TaskDispatchCommand.payload_model` 完成命名纠偏为 `payload`
- 相关测试、真实回归、文档说明与源码一致

## 全局约束
- 以源码为准；若文档与源码冲突，以源码为准并在回归文档中注明文档可能过期。
- 契约必须遵守“公共头字段 + 强类型扩展字段”规则。
- 扩展字段必须使用 Pydantic 判别联合，且必须包含 `kind`、`schema_version`。
- 扩展字段必须启用 `extra="forbid"`。
- 禁止 `dict[str, Any]`、`metadata`、`extra_payload` 作为扩展承载。
- 外层类型与内层扩展类型必须一致，不能出现命名与语义分离。
- 保持统一错误码、日志结构、消息信封语义不退化。

## Phase 1
### 目标
完成契约收口：引入强类型执行对象，统一 handler 泛型签名，并让注册侧返回“解析后的 payload + binding + message”。

### 依赖
- 依赖现有 `TaskMessageEnvelope`、`TaskRegistrationEnvelope`、`TaskHandler`、`RegisteredTaskBinding`。
- 依赖 Pydantic 判别联合和现有 `payload_model` 注册机制。
- 依赖当前调用链未改名的源码状态，用于一次性完成契约替换。

### 模拟用法
```python
invocation = registry.resolve_task_invocation(message)
handler.handle(invocation)
assert invocation.payload.model_dump()
assert invocation.message.header.message_id
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `TypedTaskInvocation` | 强类型任务执行对象 | 统一承载 `payload`、`message`、`binding`，作为 handler 唯一入参 |
| `TaskInvocationBinding` | 任务执行绑定 | 描述已解析的注册项与 handler 绑定关系 |
| `TaskInvocationResolution` | 任务执行解析结果 | 注册侧一次性返回解析后的 payload、binding、message |
| `TaskHandler[T]` | 泛型任务处理器 | handler 与 `payload_model` 强绑定，禁止弱类型原始信封入参 |

### 关键代码片段
```python
class TaskHandler(Generic[T], ABC):
    @abstractmethod
    def handle(self, invocation: TypedTaskInvocation[T]) -> None: ...

@dataclass(slots=True, frozen=True, kw_only=True)
class TypedTaskInvocation(Generic[T]):
    payload: T
    message: TaskMessageEnvelope
    binding: TaskInvocationBinding[T]
```
