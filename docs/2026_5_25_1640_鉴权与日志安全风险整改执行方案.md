# 鉴权与日志安全风险整改执行方案

## 任务目标
交付一组可真实落地的安全整改方案，覆盖普通异常日志脱敏绕过、鉴权失败节流非原子、JWT `jti` / `sid` 契约过宽、refresh token 持久层约束不足、路由级鉴权约束不足、中间件故障隔离不足、运行时安全配置漂移、敏感配置生命周期、账号枚举、公共路由无效 Bearer 语义、session 生命周期、capability 噪音、命名、OpenAPI 安全元数据和 bootstrap admin 环境漂移风险。

完成判定：源码、契约、测试、真实回归和相关文档均体现最终安全语义；未通过放宽断言、吞异常、跳过原始功能或无依据修改来制造通过。

## 全局约束
- 若文档、图谱、历史方案与源码冲突，以源码为准；历史文档可能过期，文档回归时必须标注。
- 不糊墙：每个风险必须有可定位的源码约束、契约约束或测试断言支撑。
- 不在无依据情况下修改原始功能：外部响应结构、错误码、状态码、数据库表语义和配置默认值只做必要安全收敛。
- 日志不得输出明文 access token、refresh token、Bearer、JWT、数据库 URL 密码、bootstrap admin 密码、`jwt_secret`、连接串密码。
- 鉴权失败节流在 Redis 可用时必须使用原子递增语义；内存实现只能用于 dev/test，并需明确并发边界。
- JWT `token_id` / `token_session_id` 的契约宽度必须与执行路径一致，非法 UUID 必须稳定返回 `401 / auth.token.invalid`。
- refresh token session 状态必须同时考虑撤销、轮换、过期和数据一致性，不允许脏数据直接放大为未映射 `500`。
- 路由保护必须从 handler 手工调用收口到路由级依赖或 Security 声明，OpenAPI 安全元数据必须与真实行为一致。
- 运行时安全配置必须从“硬编码环境分支”收敛为“配置声明 + 校验器强制 + 测试证明”。
- 契约设计必须遵守“公共头字段 + 强类型扩展字段”规则：扩展字段使用 Pydantic 判别联合，扩展字段必须有 `kind`、`schema_version`，必须启用 `extra="forbid"`，禁止 `dict[str, Any]`、`metadata`、`extra_payload`，外层类型与内层扩展类型必须一致。

## 验收标准
- 普通 `logger.exception(...)` 不再绕过脱敏；stdout/stderr、结构化日志、异常日志测试均不能出现敏感原文。
- Redis 鉴权失败计数在并发失败请求下不丢计数，达到阈值后稳定锁定。
- 合法签名但非法 UUID 的 `jti` / `sid` 返回 `401 / auth.token.invalid`，不会返回未映射 `500`。
- refresh token 表具备必要外键、自关联或等价一致性约束；session 状态查询不会因重复/脏数据放大成 `MultipleResultsFound`。
- 受保护路由通过路由级依赖或 Security 强制鉴权；OpenAPI 安全声明与真实保护一致。
- 鉴权中间件对仓储、数据库、资源故障有明确隔离策略，不把基础设施故障误报成 token 无效。
- `jwt_secret` 使用 `SecretStr` 或等价秘密类型，快照、reload、异常、日志路径不泄漏原值。
- 禁用账号登录不再提供比错误密码更强的用户名状态枚举信号。
- 全量 `pytest -q` 通过；新增安全回归测试在修复前能暴露问题，在修复后稳定通过。
