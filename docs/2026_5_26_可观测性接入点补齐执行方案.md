# 可观测性接入点补齐执行方案

## 任务目标

交付一套轻量可观测性接入点，使当前项目在不部署完整监控系统的前提下，具备后续接入 OpenTelemetry、Prometheus、Grafana 的真实代码基础。

完成判定：

- OpenTelemetry 保持默认关闭，但配置和桥接能力更完整。
- Prometheus 提供可开关的 `/metrics` 指标出口。
- Grafana 不直接接代码，但具备基于 Prometheus 数据源的接入说明。
- 日志、健康检查、结构化日志事件保持现有行为不回退。

## 全局约束

- 若文档、历史方案、源码冲突，以当前源码为准；历史文档可能过期。
- 不引入完整 Grafana/Prometheus/Loki/Tempo/Alertmanager 部署栈，只补应用侧接入点。
- 默认配置必须保持轻量：OpenTelemetry 默认关闭，Prometheus metrics 默认可配置关闭或按环境开启。
- 新增契约必须遵守“公共头字段 + 强类型扩展字段”规则。
- 扩展字段必须使用 Pydantic 判别联合。
- 扩展字段必须包含 `kind`、`schema_version`。
- 扩展字段必须启用 `extra="forbid"`。
- 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议。
- 外层类型与内层扩展类型必须一致。
- 新增指标不能暴露密码、token、连接串、完整请求体、完整异常堆栈。
- `/metrics` 不进入统一 JSON 响应信封，按 Prometheus 文本格式返回。

## 验收标准

- `/health/live`、`/health/ready` 现有行为不变。
- 结构化日志事件、数据库日志落库、日志脱敏现有测试通过。
- OpenTelemetry 默认关闭时不阻塞应用启动。
- OpenTelemetry 开启时仍可通过 `FastAPIInstrumentor` 注入 FastAPI 应用。
- Prometheus 开启时 `/metrics` 返回 `text/plain` 指标文本。
- Prometheus 关闭时 `/metrics` 不暴露或返回 404。
- Grafana 文档说明如何以 Prometheus 为数据源接入。
- 相关单元测试、接口测试、初始化测试、回归测试全部通过。

## Phase 1

### 目标

补齐可观测性运行时契约和配置加载能力，让 OpenTelemetry 与 Prometheus 的开关、路径、服务名、指标策略都有稳定配置入口。

阶段完成后，应用可读取 `runtime.metrics`，并保持 `runtime.otel` 默认关闭语义不变。

### 依赖

- 当前 `src/infrastructure/fastapi_otel_bridge.py`
- 当前 `config/runtime/otel_runtime/otel_runtime_base.toml`
- 当前 `src/infrastructure/settings/app_settings_loader.py`
- 当前配置解析规则和运行时配置目录规范

### 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| MetricsRuntimeEnvelope | 指标运行时信封 | 外层公共头字段，声明 metrics 运行时配置类型、版本、启用状态 |
| MetricsRuntimeHeader | 指标运行时公共头 | 承载 `kind`、`schema_version`、`mode`、`enabled`、`policy_name` |
| PrometheusMetricsRuntimeDetail | Prometheus 指标扩展 | 强类型扩展字段，包含 `kind`、`schema_version`、`metrics_path`、`include_http_metrics` |
| MetricsRuntimeMode | 指标运行时模式 | 第一版只包含 `prometheus_metrics` |
| OtelRuntimeSettings | OTel 运行时配置 | 保留现有配置，补充可选 service name、endpoint、采样配置字段 |

### 关键代码片段

```python
class PrometheusMetricsRuntimeDetail(BaseModel):
    model_config = ConfigDict(extra="forbid")

    kind: Literal["prometheus_metrics"] = "prometheus_metrics"
    schema_version: Literal["1.0"] = "1.0"
    metrics_path: str = "/metrics"
    include_http_metrics: bool = True
    include_runtime_metrics: bool = True
```

### 校验

- `ApplicationSettings.model_validate()` 能解析 `runtime.metrics`。
- `metrics_runtime` 多余字段会失败。
- 外层 `mode` 与内层 `kind` 不一致会失败。
- OTel 默认关闭时 `FastApiOtelBridge.get_state().no_op is True`。

## Phase 2

### 目标

新增 Prometheus 指标出口，使应用在配置开启时提供 `/metrics` 文本格式输出，并保留现有健康检查、日志和业务路由行为。

阶段完成后，Grafana 可以通过 Prometheus 间接消费应用指标。

### 依赖

- Phase 1 的 `runtime.metrics` 契约和配置加载
- FastAPI app 装配流程
- `prometheus-client` 依赖

### 模拟用法

```text
GET /metrics

响应：
# HELP fastapi_request_total Total HTTP requests
# TYPE fastapi_request_total counter
fastapi_request_total{method="GET",path="/health/live",status_code="200"} 1.0
```

### 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| PrometheusMetricsRegistry | Prometheus 指标注册器 | 统一创建、复用和输出 Prometheus 指标 |
| PrometheusMetricsRoute | Prometheus 指标路由 | 按配置暴露 `/metrics` 文本响应 |
| HttpRequestMetric | HTTP 请求指标 | 记录方法、路径模板、状态码、耗时等低敏标签 |
| RuntimeMetric | 运行时指标 | 记录应用 ready 状态、日志缓冲数量等运行时状态 |

### 关键代码片段

```python
def mount_prometheus_metrics(app: FastAPI, registry: CollectorRegistry, path: str) -> None:
    @app.get(path, include_in_schema=False)
    def read_metrics() -> Response:
        return Response(
            content=generate_latest(registry),
            media_type=CONTENT_TYPE_LATEST,
        )
```

### 校验

- 开启 metrics 时 `/metrics` 返回 200。
- 关闭 metrics 时 `/metrics` 返回 404。
- `/metrics` 不出现在 OpenAPI。
- 指标文本中不包含 Authorization、JWT、password、secret。
