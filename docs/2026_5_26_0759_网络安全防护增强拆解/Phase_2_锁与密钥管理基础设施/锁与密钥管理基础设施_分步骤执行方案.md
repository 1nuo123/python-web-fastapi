# Phase 2 锁与密钥管理基础设施分步骤执行方案

## 阶段目标

实现独立分布式锁基础设施和统一密钥管理基础设施。分布式锁由 `infrastructure/concurrency` 独立管理，供限流封禁、密钥管理、后续任务调度等场景复用；密钥管理由 `infrastructure/key_management` 统一管理密钥族、密钥版本、密钥环快照、当前密钥读取、旧密钥兼容和轮转。

## 相关全局约束

- 若文档、图谱、源码冲突，以当前源码为准，历史文档可能过期。
- 必须遵守 `docs/standard/编码规范.md`、`docs/standard/测试规范.md`、`docs/standard/命名规范.md`。
- 分布式锁必须作为独立基础设施管理，不挂靠安全防护模块；安全防护、密钥管理、任务调度等模块只能通过 Provider 消费锁能力。
- 密钥轮转必须纳入统一密钥管理基础设施，不允许在业务模块内各自实现轮转、密钥环、当前密钥索引或旧密钥兼容逻辑。
- `runtime.security` 只承载安全防护策略；`runtime.distributed_lock` 和 `runtime.key_management` 是独立运行时配置入口。
- 高频流控计数、临时锁、封禁缓存、Token-IP 绑定状态放缓存；明确 IP 封禁记录必须落数据库。
- 缓存 key 必须符合 `key_prefix:namespace:segment...`，令牌、密码、密钥、IP、User-Agent 参与 key 构造前必须摘要化。
- 认证、鉴权、限流、封禁、分布式锁关键路径缓存不可用时必须 fail-closed，不得放行。
- 不记录明文密码、Bearer、JWT、refresh token、secret、完整请求体、完整 URL 查询串。
- IP、User-Agent、token、host 相关标识默认只保存摘要。
- 日志、异常、注释使用中文；不得使用 `print`。
- 测试必须覆盖资源释放，不能通过跳过测试、放宽断言或回退实现规避失败。

## 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| DistributedLockRuntimeEnvelope | 分布式锁运行时信封 | Phase 1 冻结的独立锁运行时配置，定义锁后端、租约时长、等待时长、失败模式 |
| KeyManagementRuntimeEnvelope | 密钥管理运行时信封 | Phase 1 冻结的独立密钥管理运行时配置，定义密钥后端、密钥族、用途、轮转策略、有效密钥数量 |
| DistributedLockProvider | 分布式锁提供者 | 统一 acquire/release/refresh，隐藏 Redis 锁实现 |
| RedisDistributedLockAdapter | Redis 锁适配器 | 已承载 acquire/release/refresh，并由 `DistributedLockProvider` 接入主流程 |
| DistributedLockRequest | 分布式锁请求 | 承载 namespace、key_digest、lease_seconds、wait_seconds |
| DistributedLockLease | 分布式锁租约 | 表达锁 key 摘要、owner、过期时间、释放状态 |
| KeyManagementService | 密钥管理服务 | 统一提供密钥族初始化、当前密钥读取、有效密钥快照、轮转调度入口 |
| KeyRotationService | 密钥轮转服务 | 作为密钥管理子能力，执行轮转判断、current key 切换、旧密钥保留 |
| RedisKeyRingStore | Redis 密钥环存储 | 存储 key family、key ring、current key id、next rotation epoch |
| ManagedKeyDescriptor | 托管密钥描述 | 表达 key id、用途、状态、生效时间、过期时间、摘要 |
| KeyRingSnapshot | 密钥环快照 | 表达当前 key id、候选 key id、有效 key 集合摘要 |
| SensitiveDigestService | 敏感摘要服务 | 对 IP、token、User-Agent、host 生成稳定摘要 |

## 原始模拟用法

```python
lease = distributed_lock_provider.acquire(lock_request)
try:
    key_ring = key_management_service.rotate_key_family_if_due(rotation_command)
finally:
    distributed_lock_provider.release(lease)
```

## 分步骤执行

### 步骤 1：实现独立分布式锁基础设施

- 新增 `DistributedLockProvider`。
- `RedisDistributedLockAdapter` 承载 acquire/release/refresh，并接入 `DistributedLockProvider` 主流程。
- 锁 key 统一使用缓存 key builder 与摘要片段。
- 锁获取失败或 Redis 不可用时按配置 fail-closed。
- 同一 lock key 并发获取时只有一个成功。
- 释放非 owner 锁失败且不影响原锁。

### 步骤 2：实现敏感摘要能力

- 新增 `SensitiveDigestService`。
- 对 IP、token、User-Agent、host 等敏感标识生成稳定摘要。
- 参与缓存 key 构造前必须摘要化。
- 日志、事件、指标中不得输出明文敏感标识。

### 步骤 3：实现统一密钥管理基础设施

- 新增 `KeyManagementService`。
- 新增 `KeyRotationService`。
- 新增 `RedisKeyRingStore`。
- 密钥族初始化必须幂等，重复启动不得覆盖仍有效密钥。
- 密钥读取必须通过统一密钥管理服务，不允许业务模块直接读写密钥环存储。
- 支持读取当前 key、有效 key 快照和指定 key family。

### 步骤 4：接入密钥轮转与锁保护

- 密钥轮转必须由密钥管理服务调度。
- 轮转流程必须通过独立分布式锁保护，避免多实例重复轮转。
- 密钥轮转后 current key 改变，旧 key 在有效窗口内仍可通过统一密钥管理服务读取。
- 轮转流程不记录明文密钥。

原始关键代码片段：

```python
rotation_lock = distributed_lock_provider.acquire(rotation_lock_request)
key_ring = key_ring_store.load_key_ring(key_family)
rotated_ring = key_rotation_service.rotate_if_due(key_ring, rotation_policy)
key_ring_store.save_key_ring(rotated_ring)
distributed_lock_provider.release(rotation_lock)
```

### 步骤 5：挂载生命周期资源

- `SharedResourceMount` 挂载锁 Provider 与密钥管理服务。
- 按当前生命周期释放 Redis/cache 连接、锁租约和密钥管理相关资源。
- 分布式锁和密钥管理必须可在安全防护之外独立初始化、独立测试、独立复用。

## 验收标准

- Redis/cache 不可用时，认证节流、通用限流、分布式锁、封禁判断均 fail-closed。
- 分布式锁可在安全防护之外独立初始化、独立测试、独立复用。
- 安全防护代码不直接创建 Redis 锁，只依赖 `DistributedLockProvider`。
- 密钥管理可在认证、安全防护之外独立初始化、独立测试、独立复用；本轮未保留 URL 签名运行时接入口径。
- 业务代码不直接读写密钥环存储，只依赖统一密钥管理服务读取当前 key 或有效 key 快照。
- 密钥轮转后，新密钥用于 JWT 签发，旧有效密钥仍可在配置窗口内验签。
- 日志、安全事件、指标中不出现明文敏感信息。

## 校验点

- 同一 lock key 并发获取时只有一个成功。
- 释放非 owner 锁失败且不影响原锁。
- Redis 不可用时锁关键路径 fail-closed。
- 密钥管理服务可读取当前 key、有效 key 快照和指定 key family。
- 密钥轮转后 current key 改变，旧 key 在有效窗口内仍可通过统一密钥管理服务读取。
- 轮转流程不记录明文密钥。
