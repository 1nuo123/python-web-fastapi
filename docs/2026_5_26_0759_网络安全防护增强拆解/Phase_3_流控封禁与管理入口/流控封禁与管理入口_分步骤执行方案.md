# 流控封禁与管理入口_分步骤执行方案

## 阶段目标

实现通用流控、IP 封禁链路和封禁管理入口，覆盖所有 HTTP 请求入口。

Phase 3 依赖 Phase 1、Phase 2，实现通用限流、IP 封禁缓存/数据库链路和封禁管理入口。

## 全局约束

- 若文档、图谱、源码冲突，以当前源码为准，历史文档可能过期。
- 必须遵守 `docs/standard/编码规范.md`、`docs/standard/测试规范.md`、`docs/standard/命名规范.md`。
- 本次不引入完整 SIEM、WAF、规则引擎或审计平台；安全事件复用现有结构化日志/事件链路扩展。
- 分布式锁必须作为独立基础设施管理，不挂靠安全防护模块；安全防护、密钥管理、任务调度等模块只能通过 Provider 消费锁能力。
- `runtime.security` 只承载安全防护策略；`runtime.distributed_lock` 和 `runtime.key_management` 是独立运行时配置入口。
- 高频流控计数、临时锁、封禁缓存、Token-IP 绑定状态放缓存；明确 IP 封禁记录必须落数据库。
- UoW 是唯一事务边界；Repository 不得 `commit()`、`rollback()` 或释放外层会话。
- 缓存 key 必须符合 `key_prefix:namespace:segment...`，令牌、密码、密钥、IP、User-Agent 参与 key 构造前必须摘要化。
- 认证、鉴权、限流、封禁、分布式锁关键路径缓存不可用时必须 fail-closed，不得放行。
- 新增契约统一采用“公共头字段 + 强类型扩展字段”。
- 扩展字段必须使用 Pydantic 判别联合，包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议。
- 外层类型与内层扩展类型必须一致。
- 不记录明文密码、Bearer、JWT、refresh token、secret、完整请求体、完整 URL 查询串。
- IP、User-Agent、token、host 相关标识默认只保存摘要。
- 日志、异常、注释使用中文；不得使用 `print`。
- 测试必须覆盖资源释放，不能通过跳过测试、放宽断言或回退实现规避失败。

## 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| SecurityProtectionGuard | 安全防护门面 | 统一串联 IP 封禁、限流、风险信号和事件构建 |
| RateLimitGuard | 限流守卫 | 按 IP 摘要、subject、path、method、认证字段摘要执行窗口计数 |
| IpBlockGuard | IP 封禁守卫 | 优先读缓存，缓存缺失查库并回填缓存 |
| SecurityIpBlockRecord | IP 封禁记录 | 数据库持久化封禁摘要、原因、状态、过期与释放信息 |
| SecurityIpBlockRepository | IP 封禁仓储 | 只负责封禁记录读写，不提交事务 |
| RateLimitMiddleware | 限流中间件 | 在请求入口执行 IP 封禁和限流决策，超限返回 429 |
| SecurityProtectionAdminRoute | 安全防护管理路由 | 查询封禁记录、释放封禁并清理缓存 |

## 分步骤规划

### 1. 建立 IP 封禁持久化链路

- 新增 `security_ip_block_record_orm_model.py`，持久化封禁摘要、原因、状态、过期时间、释放信息。
- 新增 Alembic 迁移创建 `security_ip_block_record`。
- 新增 `SecurityIpBlockRepository`，只负责封禁记录读写，事务由 UoW 管理。
- IP、User-Agent、token 相关字段只保存摘要，不写入明文。

### 2. 实现封禁缓存判断与回填

- 新增 `IpBlockGuard`。
- 运行时优先读取封禁缓存。
- 缓存缺失时查询数据库有效封禁记录，并回填缓存。
- Redis/cache 不可用时，封禁判断必须 fail-closed。
- 释放封禁时同步删除封禁缓存，保证数据库状态与缓存状态一致。

### 3. 实现通用限流守卫

- 新增 `RateLimitGuard`。
- 使用 Phase 1 的运行时配置和限流策略。
- 按 IP 摘要、subject、path、method、认证字段摘要执行窗口计数。
- 使用当前缓存 Store 与 `rate_limit` namespace policy。
- 限流标签和键只使用摘要或低基数字段。
- 缓存不可用时通用限流必须 fail-closed。

### 4. 串联安全防护门面

- 新增 `SecurityProtectionGuard`。
- 统一串联 IP 封禁、限流、风险信号和事件构建。
- 限流触发封禁时，使用 Phase 2 独立 `DistributedLockProvider` 保护写库，避免并发重复封禁。
- 使用 Phase 2 `SensitiveDigestService` 生成稳定摘要。

### 5. 接入 HTTP 请求入口

- 新增 `RateLimitMiddleware`。
- 在请求入口执行 IP 封禁和限流决策。
- 超限响应返回 `429`，并包含 `Retry-After`。
- 修改 `fastapi_middleware_plan.py` 装配限流中间件，注意与既有 FastAPI 中间件顺序兼容。

关键代码片段：

```python
decision = security_guard.evaluate_request(request_context)
if decision.action == SecurityAction.RETURN_429:
    return rate_limit_response_factory.build(decision)
```

### 6. 增加封禁管理入口

- 新增封禁查询/释放 API 契约与路由。
- 新增 `src/api/endpoint_security_protection/__init__.py`。
- 新增 `contract_security_protection.py`。
- 新增 `route_security_protection.py`。
- 修改 `fastapi_route_composer.py` 装配安全防护管理路由。
- 管理释放封禁后，同步更新数据库状态并删除封禁缓存。

### 7. 补充测试与回归

- 新增限流单元、路径、异常、边界测试，覆盖 IP、subject、path+method、认证字段摘要维度。
- 新增 IP 封禁单元和集成测试，覆盖落库、缓存命中、缓存缺失回填、释放状态、并发重复封禁。
- 新增封禁管理接口测试，覆盖查询、释放、权限、缓存同步删除。
- 新增 HTTP 接口测试，覆盖 `429`、封禁拒绝、OpenAPI 不回退。
- 新增初始化测试，覆盖安全防护资源按配置装配。
- 回跑认证、刷新令牌复用、日志脱敏、健康检查、metrics 既有测试。

## 校验与验收点

- 单 IP 超过全局阈值返回 `429`，响应包含 `Retry-After`。
- `/auth/token` 超过认证策略阈值返回 `429`。
- Redis/cache 不可用时，认证节流、通用限流、分布式锁、封禁判断均 fail-closed。
- 安全防护代码不直接创建 Redis 锁，只依赖 `DistributedLockProvider`。
- 明确封禁 IP 写入数据库，并同步写入封禁缓存。
- 封禁缓存缺失时能从数据库封禁记录回填。
- 并发触发同一 IP 封禁时只产生一条有效封禁记录。
- 管理端可查询封禁记录并释放封禁，释放后缓存同步失效。
- 日志、安全事件、指标中不出现明文敏感信息。
- 超限请求返回 `429`。
- 明确封禁 IP 被拒绝。
- 缓存缺失时可从数据库封禁记录回填。
- 并发触发封禁只写入一条有效封禁记录。
- 管理释放封禁后，数据库状态与缓存状态一致。
- 限流标签和键只使用摘要或低基数字段。

## 回归修复

- 若限流行为失败，修正 key 维度、窗口 TTL、fail_mode 和中间件顺序。
- 若 IP 封禁失败，修正数据库状态过滤、缓存回填、释放逻辑和并发写入保护。
- 若封禁管理接口失败，修正权限、查询过滤、释放事务和缓存同步删除。
- 若安全事件泄露敏感信息，优先修正摘要与脱敏链路。
- 修复后回跑失败用例所在测试文件。
- 最终回跑完整真实测试清单。
