# 安全事件与认证风险_分步骤执行方案

## 阶段目标

接入统一安全事件、轻量认证风险信号和可选 Token-IP 绑定，不新建完整审计体系。

## 全局约束

- 必须遵守 `docs/standard/编码规范.md`、`docs/standard/测试规范.md`、`docs/standard/命名规范.md`。
- 本次不引入完整 SIEM、WAF、规则引擎或审计平台；安全事件复用现有结构化日志/事件链路扩展。
- `runtime.security` 只承载安全防护策略；`runtime.distributed_lock` 和 `runtime.key_management` 是独立运行时配置入口。
- 高频流控计数、临时锁、封禁缓存、Token-IP 绑定状态放缓存；明确 IP 封禁记录必须落数据库。
- 缓存 key 必须符合 `key_prefix:namespace:segment...`，令牌、密码、密钥、IP、User-Agent 参与 key 构造前必须摘要化。
- 认证、鉴权、限流、封禁、分布式锁关键路径缓存不可用时必须 fail-closed，不得放行。
- 新增契约统一采用“公共头字段 + 强类型扩展字段”。
- 扩展字段必须使用 Pydantic 判别联合，包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议。
- 外层类型与内层扩展类型必须一致。
- 不记录明文密码、Bearer、JWT、refresh token、secret、完整请求体、完整 URL 查询串。
- IP、User-Agent、token、host 相关标识默认只保存摘要。
- Token-IP 绑定只做可选高风险策略，不作为全站默认强制策略。
- 日志、异常、注释使用中文；不得使用 `print`。
- 测试必须覆盖资源释放，不能通过跳过测试、放宽断言或回退实现规避失败。

## 阶段依赖

- Phase 4 依赖 Phase 1-3，接入统一安全事件、认证风险信号和可选 Token-IP 绑定。
- Phase 1 的 `SecurityEventEnvelope`、`TokenBindingEnvelope`。

- Phase 3 的限流与封禁决策。
- 当前结构化日志、数据库日志写入器、认证用例、payload guard。

## 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| SecurityEventBuilder | 安全事件构建器 | 统一构建安全事件信封并复用现有日志写入链路 |
| RiskSignalGuard | 风险信号守卫 | 聚合登录失败、密码喷洒、refresh token 复用等轻量风险信号 |
| TokenBindingGuard | Token-IP 绑定守卫 | 按配置对高风险 token 使用场景校验 IP 摘要 |
| AuthFailureSecurityEventDetail | 认证失败事件扩展 | 记录认证失败、认证节流、密码喷洒疑似事件 |

| TokenBindingSecurityEventDetail | Token 绑定事件扩展 | 记录 token IP 摘要不匹配、绑定清理等事件 |

## 分步骤执行

### 步骤 1：安全事件构建链路

新增 `SecurityEventBuilder`，统一构建 `SecurityEventEnvelope`，并复用现有结构化日志/事件写入链路。构建过程中必须复用现有日志脱敏能力，敏感标识只保留摘要。

### 步骤 2：认证风险信号

新增 `RiskSignalGuard`，聚合登录失败、密码喷洒、refresh token 复用等轻量风险信号。登录失败接入安全事件，新增 `auth.password_spray_suspected` 风险信号，refresh token reused 接入高风险事件。

### 步骤 3：限流与请求体事件接入

将 `RateLimitMiddleware` 拦截接入安全事件。将 `PayloadGuardMiddleware` 的 `413` 接入安全事件，保留请求体过大时的原有拒绝语义。

### 步骤 4：可选 Token-IP 绑定

新增 `TokenBindingGuard`。Token-IP 绑定默认关闭；开启时写入 token 摘要与 IP 摘要映射，并只对配置声明场景生效。Token-IP 不匹配时拒绝请求、删除绑定并生成安全事件。

### 步骤 5：测试与回归

补齐安全事件构建测试，覆盖脱敏、摘要字段、`request_id`、`trace_id`。补齐 Token-IP 绑定测试，覆盖默认关闭、开启绑定、IP 摘要不匹配、绑定清理。补齐安全事件接口路径测试，并回跑认证、刷新令牌复用、日志脱敏、健康检查、metrics 既有测试。

## 校验点

- 安全事件包含 `request_id`、`trace_id`、`path`、`method`、`policy_name`。
- 安全事件不包含明文 token、password、secret、IP、User-Agent。
- refresh token 复用仍撤销 token session。
- Token-IP 绑定默认关闭；开启后只对配置声明场景生效。
- Token-IP 不匹配时缓存绑定被清理。

## 验收点

- 认证失败、refresh token 复用、限流拦截、请求体过大、Token-IP 异常能生成统一安全事件。
- refresh token 复用后继续撤销对应 token session，并生成高风险安全事件。
- Token-IP 绑定开启时，异常 IP 使用 token 会拒绝、清理绑定并生成安全事件。
- 超大请求体在 `Content-Length` 与 chunked 路径下均返回 `413`，并生成安全事件。
- 日志、安全事件、指标中不出现明文敏感信息。
- 限流、封禁、Token-IP 绑定、payload、认证风险路径符合验收标准。
- 现有认证、日志、健康检查、metrics、OpenTelemetry 行为不回退。
- 测试结束后释放数据库 session、缓存连接、HTTP client、锁租约和 TestClient。

## 回归修复

- 若安全事件泄露敏感信息，优先修正摘要与脱敏链路。
- 若 Token-IP 绑定误拦截，修正适用策略、可信代理 IP 解析和摘要维度。
