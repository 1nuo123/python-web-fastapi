# 统一心智模型代码检查修复清单

生成日期：2026-07-02

审查范围：`src/`、`config/`、`compose*.yml`、`Dockerfile`、关键安全与运行时文档。

审查方式：本地代码扫描 + 5 个 `gpt-5.5`、`reasoning_effort=xhigh` 子智能体分模块只读审查。

## 总体判断

本轮未发现需要按 P0 处理的直接发布阻断问题。主要风险不是单个语法错误，而是四条心智模型分叉：

1. 安全边界没有完全前移到入口和策略层。
2. 运行时资源热更新不是原子切换模型。
3. 任务派发缺少事务 outbox，执行记录与消息投递可能分裂。
4. core contract 与 infrastructure 实现边界仍有泄漏。

全局最优修复路线：先收紧生产安全和运行时一致性，再做契约边界重构。不要用局部 if/try 糊墙；这些问题适合用统一策略对象、不可变 RuntimeBundle、事务 outbox、强类型配置校验来一次性收口。
