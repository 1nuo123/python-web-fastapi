## 全局约束
- 若源码、既有文档、图谱冲突，以当前源码为准，并在文档中注明旧文档可能过期。
- 所有新增或修改契约必须遵循“公共头字段 + 强类型扩展字段”规则。
- 扩展字段必须使用 Pydantic 判别联合，必须包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议。
- 外层类型与内层扩展类型必须一致，例如 `header.kind == detail.kind`、`header.schema_version == detail.schema_version`。
- Repository 只负责持久化读写与不可恢复数据库异常抛出；事务提交、回滚、释放由 UoW 边界负责。
- 路由层只负责鉴权、请求契约、响应封装；同步业务统一经 `RequestExecutionBridge` 或等价桥接执行。
- 安全链路中的客户端 IP、发布结果、运行时角色、配置入口必须各自存在唯一事实源。
- 测试必须按“最小失败集 -> 阶段集 -> 依赖型集成 -> 全量回归”顺序执行。
- Docker / PostgreSQL / Redis / RabbitMQ 未启用时，相关测试只能显式 `skip`，不得假通过。

## 验收标准
- `create_app()`、assembler、task binding provider 的真实入口语义一致。
- 管理端任务运行时返回的节点角色、任务后端、传输后端、注册可见性与真实装配一致。
- `/security/ip-blocks` 管理接口统一走桥接主链路，不再在 async route 内直接操作同步仓储/UoW。
- token binding、限流、IP block、安全事件统一使用同一客户端 IP 解析器。
- RabbitMQ 发布结果准确区分“发布成功”与“路由成功/失败”。
- Funboost 失败回调在执行记录缺失时仍可观察、可落日志、可落失败记录。
- `config/.env.example` 不再作为有效入口；开发、Docker、测试数据库入口保持一致。
- 生产 web runtime 不再隐式继承 localhost CORS。
- 相关源码、契约、测试、文档回归全部一致。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `TaskRuntimeHeader` | 任务运行时公共头 | 外层公共头，固定 `kind`、`schema_version`、`operation_name`。 |
| `TaskRuntimeDetailUnion` | 任务运行时扩展联合 | 判别联合，统一表达 `task_runtime_mode`、`task_backend`、`transport_backend`。 |
| `TaskRuntimeMode` | 任务运行时模式 | 统一节点角色枚举，如 `local_inline`、`local_queued`、`funboost_producer`、`funboost_consumer`。 |
| `TaskRegistrationRuntimeDetailUnion` | 任务注册运行时扩展联合 | 判别联合，表达注册项 backend、当前 runtime backend、是否对当前 runtime 生效。 |
| `TaskBindingSource` | 任务绑定来源 | 区分默认 binding 与显式 binding，避免 `None`/空列表承载双重语义。 |
