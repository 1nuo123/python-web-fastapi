# 安全基线加固执行方案

## 任务目标
交付一套可用于生产公网基线的安全加固改造方案，覆盖容器暴露面、密钥注入、OpenAPI 关闭、系统信息鉴权、异常脱敏、认证运行态和测试/文档回归。

完成判定：
- 生产环境不会继承可预测 JWT 密钥。
- 生产 OpenAPI 文档入口真实不可访问。
- `/system/info` 不再对匿名公网暴露。
- 客户端异常响应不回传内部异常详情。
- 生产部署不默认暴露 Postgres、Redis、RabbitMQ 内部端口，不使用 RabbitMQ `guest/guest`。
- 安全相关测试、真实测试和文档回归全部通过。

## 全局约束
- 以源码为准；若文档、图谱、历史方案与源码冲突，以源码为准，并在文档回归中说明历史文档可能过期。
- 禁止把生产密钥、默认密码、真实连接串写入仓库配置；生产敏感值只允许通过环境变量、Compose Secret 或外部 Secret Manager 注入。
- 契约设计统一采用“公共头字段 + 强类型扩展字段”：外层公共字段承载稳定字段，扩展字段使用 Pydantic 判别联合。
- 所有扩展字段必须包含 `kind`、`schema_version`，必须启用 `extra="forbid"`。
- 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议或安全策略。
- 外层类型与内层扩展类型必须一致，例如 `runtime.security.mode` 必须与 `runtime.security.detail.kind` 一致。
- 客户端响应只返回稳定错误码、HTTP 状态、通用消息和请求标识；内部异常详情只进入结构化日志。
- 健康探针保持最小可用：`/health/live` 可匿名，`/health/ready` 只返回必要就绪状态，不返回模块清单、版本和资源细节。
- 认证链路保留 Argon2、JWT `issuer` / `audience` / `exp` 校验、刷新令牌轮换和失败节流。
- 生产认证节流必须使用 Redis 或外部缓存，禁止回退到进程内内存态。
- 测试必须遵循 `docs/standard/测试规范.md`；真实测试需包含单元、边界、异常、初始化、接口和集成回归。

## 验收标准
- `APP_ENV=production` 且缺失 `JWT_SECRET` 时应用启动失败。
- `config/runtime/auth_runtime/auth_runtime_base.toml` 不再包含可预测 `jwt_secret`。
- 生产环境 `GET /docs`、`GET /redoc`、`GET /openapi.json` 返回不可访问状态。
- 匿名访问 `GET /system/info` 返回 `401` 或 `403`，管理员携带有效令牌可访问受控信息。
- 异常响应体不包含 Python 异常类名、堆栈、SQL、连接串、JWT、密码或内部配置路径。
- `docker compose -f compose.yml -f compose.production.yml config` 中生产服务不发布 Postgres、Redis、RabbitMQ 管理端口到公网宿主机。
- RabbitMQ 生产配置不允许 `guest/guest`，Redis 生产配置必须启用认证或使用受控内网 Secret。
- 登录、刷新、吊销、`/auth/me`、健康探针和任务运行时回归通过。
- 文档中生产部署、安全配置、测试入口与最终源码一致。

## Phase 1
### 目标
收口生产部署和配置安全基线，避免开发态配置被直接用于生产公网。

阶段完成后：
- 开发与生产 Compose 边界明确。
- 生产内部服务端口不默认发布到宿主机。
- 生产敏感配置必须显式注入，漏配直接失败。
- JWT 默认弱密钥从仓库运行时配置中移除。

### 依赖
- 当前 `compose.yml`、`Dockerfile`、`.env.docker.example`。
- 当前配置加载器 `src/infrastructure/settings/app_settings_loader.py`。
- 当前运行时配置目录 `config/runtime/*`。
- Docker Compose 环境可执行 `docker compose config`。

### 模拟用法
```powershell
docker compose -f compose.yml up -d
docker compose -f compose.yml -f compose.production.yml config
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `SecurityRuntimeHeader` | 安全运行时公共头 | 承载 `mode`、`enabled`、`schema_version` 等稳定公共字段，用于区分开发/生产安全策略。 |
| `ProductionSecurityRuntimeDetail` | 生产安全运行时扩展 | `kind="production_security"`，声明生产必须关闭文档入口、隐藏系统信息、强制外部密钥、启用安全头。 |
| `DevelopmentSecurityRuntimeDetail` | 开发安全运行时扩展 | `kind="development_security"`，允许本地调试公开 OpenAPI，但不得影响生产覆盖配置。 |
| `SecurityRuntimeEnvelope` | 安全运行时信封 | 外层 `header + detail`；`detail` 使用 Pydantic 判别联合，`kind`、`schema_version` 必填且 `extra="forbid"`。 |
| `JwtSecretSource` | JWT 密钥来源 | 表达 JWT 密钥只允许来自 `JWT_SECRET` 或外部 Secret，生产禁止使用仓库默认值。 |
| `ComposeExposurePolicy` | Compose 暴露策略 | 表达应用端口与内部服务端口发布规则，生产只允许应用入口按需发布。 |

## Phase 2
### 目标
收口 Web 公开信息面，确保生产关闭文档入口、保护系统信息路由，并对异常响应做客户端脱敏。

阶段完成后：
- OpenAPI UI 和 schema 入口在生产真实关闭，而不是返回空 schema。
- `/system/info` 需要管理员角色或 `system:read` 权限。
- 系统信息响应按权限返回最小必要内容。
- 客户端异常响应不再携带 `detail=str(exc)`。

### 依赖
- Phase 1 的 `SecurityRuntimeEnvelope` 和生产环境判定。
- 当前 `FastApiAppAssembler`、`FastApiOpenApiSurface`、`FastApiExceptionPresenter`。
- 当前 `DependencyContextAccessor` 和 `AuthorizationGuard`。
- 当前 `AuthRoleKey.ADMIN`、`AuthScopeCode.SYSTEM_READ` 或等价授权枚举。

### 模拟用法
```http
GET /system/info
Authorization: Bearer <admin-access-token>
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `OpenApiExposurePolicy` | OpenAPI 暴露策略 | 声明 `openapi_url`、`docs_url`、`redoc_url` 在生产必须为 `None`。 |
| `SystemInfoAuthorizationRequirement` | 系统信息授权要求 | 表达 `/system/info` 必须满足管理员角色或 `system:read` 权限。 |
| `SystemOverviewPublicPayload` | 系统概览公开载荷 | 只包含最小公开字段，禁止返回模块清单、资源状态和内部版本细节。 |
| `SystemOverviewAdminPayload` | 系统概览管理员载荷 | 管理员可见字段，仍不得包含密钥、连接串和敏感配置。 |
| `HttpFaultPublicPayload` | HTTP 故障公开载荷 | 客户端可见错误载荷，包含 `kind`、`schema_version`、`status_code`、`error_code`，默认不包含内部 `detail`。 |
| `HttpFaultLogDetail` | HTTP 故障日志扩展 | 内部日志使用的强类型扩展，记录异常类、内部详情和 traceback 开关，不进入客户端响应。 |

## Phase 3
### 目标
加固认证运行态和令牌生命周期，确保生产节流、bootstrap admin 和密钥轮换策略可落地。

阶段完成后：
- bootstrap admin 只允许一次性初始化，不作为生产常驻入口。
- 认证节流在生产使用 Redis 或外部缓存。
- 密钥轮换后旧刷新令牌失效策略明确。
- 登录、刷新、吊销仍保持兼容。

### 依赖
- Phase 1 的密钥注入和缓存生产配置。
- 当前认证用例 `IssueAccessTokenUsecase`、`RefreshAccessTokenUsecase`、`RevokeAccessTokenUsecase`。
- 当前 `AuthFailureThrottle` 和缓存服务。
- 当前刷新令牌持久化仓储。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `BootstrapAdminPolicy` | Bootstrap 管理员策略 | 声明生产默认关闭，若启用必须一次性执行，成功后不应长期保留明文密码环境变量。 |
| `AuthThrottleBackendPolicy` | 认证节流后端策略 | 生产要求节流后端为 Redis 或外部缓存，禁止使用内存缓存。 |
| `JwtKeyRotationPolicy` | JWT 密钥轮换策略 | 声明密钥轮换后需吊销或失效旧刷新令牌会话。 |
| `RefreshTokenInvalidationCommand` | 刷新令牌失效命令 | 强类型表达按用户、会话或全量失效刷新令牌的内部命令。 |
| `SecurityAuditEventDetail` | 安全审计事件扩展 | 记录密钥缺失、弱密钥、bootstrap 初始化、令牌失效等安全事件，禁止记录明文 token 和密码。 |

## 真实测试
### 目标

### 依赖
- 测试代码补齐。
- `.venv` 可用。

- 需要集成依赖时先启动对应服务。

### 执行顺序
1. `.\.venv\Scripts\python.exe -m pytest -q test\contract_test\test_security_runtime_contract.py test\contract_test\test_http_contract.py`
2. `.\.venv\Scripts\python.exe -m pytest -q test\unit_test\test_settings_security_unit.py test\unit_test\test_fastapi_openapi_surface_unit.py test\unit_test\test_fastapi_exception_presenter_unit.py`
3. `.\.venv\Scripts\python.exe -m pytest -q test\boundary_test\test_security_boundary.py test\exception_test\test_security_exception.py test\initialization_test\test_security_initialization.py`
4. `.\.venv\Scripts\python.exe -m pytest -q test\interface_test\test_security_http_interface.py test\interface_test\test_http_interface.py`
5. `docker compose -f compose.yml config`
6. `docker compose -f compose.yml -f compose.production.yml config`
7. `docker compose -f compose.yml up -d postgres redis rabbitmq`
8. `.\.venv\Scripts\python.exe -m pytest -q test\integration_test\test_security_production_integration.py test\integration_test\test_app_integration.py`
9. `.\.venv\Scripts\python.exe -m pytest -q`

### 通过标准
- 所有 pytest 命令退出码为 `0`。
- Compose config 命令退出码为 `0`。
- 生产 Compose config 中不存在 Postgres、Redis、RabbitMQ 管理端口的公网发布。
- 测试日志不包含明文密码、JWT、刷新令牌、连接串密码。
- 失败时不得通过降低安全约束、跳过测试或放宽断言完成回归。
