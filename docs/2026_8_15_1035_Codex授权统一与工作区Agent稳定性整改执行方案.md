# Codex 工作区绑定与 Windows Agent 稳定性整改执行方案

## 任务目标

交付可上线的 Codex Remote Agent 工作区与进程稳定性整改：

- 修复注册角色同步器在重启时补回管理员已删除 scopes 的问题；除此之外不修改鉴权基建、授权模型、权限码或权限边界。
- 让普通非 Git 工作区、Git 仓库和隔离 worktree 都能正确读取线程、恢复线程和发送消息。
- 修复项目详情进入任务页、直接打开任务 URL 时工作区选择丢失或串项目的问题。
- 消除 Windows Agent 子进程导致的命令行窗口闪现，保证启动、暂停、重启、退出和异常恢复稳定。
- 完成后端、前端、Agent、MSI、Docker 和浏览器真实回归，不遗留 P0/P1 缺陷。

完成判定：管理员删除的注册角色 scope 在重启后不会恢复；`test` 等普通目录可完成远程任务闭环；路由始终显示线程所属工作区；Agent 无可见命令行闪窗、无重复 worker；生产构建和真实回归全部通过。

## 全局约束

- 后端路径为 `E:\python_web_fastapi\work`，前端路径为 `E:\python_web_fastapi\typescript-web-nuxt`；严格遵守 `work\docs\standard` 的编码、命名和测试规范。
- 鉴权基建冻结。唯一允许改动是注册角色同步器：新角色首次创建时保留现有默认 scopes；角色已存在时，启动同步不得新增、删除或覆盖任何 scope。
- 不修改 `auth_user`、`auth_role`、`auth_scope` 数据模型，不新增权限码，不调整 Codex API 的现有权限要求，不修改管理员授权接口。
- 普通工作区与 Git worktree 隔离必须解耦；隔离关闭时不得调用 Git worktree API，隔离开启时才执行 Git 能力和路径校验。
- 工作区、线程和执行根均以服务端/Agent 已持久化的权威标识为准；不得通过界面默认值或 `git rev-parse` 猜测归属。
- 跨边界契约采用“公共头字段 + 强类型扩展字段”。扩展字段使用 Pydantic 判别联合，必须包含 `kind`、`schema_version` 并启用 `extra="forbid"`；禁止 `dict[str, Any]`、`metadata`、`extra_payload`；外层与内层类型、版本必须一致。
- Windows 子进程统一使用 `shell=False`、stdout/stderr 管道、超时、取消和日志关联；禁止继承可见控制台，禁止记录密码、令牌和敏感命令参数。
- 源码、测试、数据库事实与文档冲突时以源码和真实测试结果为准，并在文档回归中标注过期内容。
- 不使用放宽权限、吞异常、跳过路径校验、强制选择第一个工作区或增加无条件重试作为修复方案。

## 验收标准

- 新建 `registered_user` 角色仍获得当前默认 `codex:read`、`codex:host_manage`；角色存在后，管理员新增或删除的 scopes 在应用重启后保持不变。
- 未启用 worktree 隔离的普通目录执行 `thread.read`、`thread.resume`、`turn.start` 时不调用 Git worktree 接口，不产生 `command_rejected` 或 502。
- Git 仓库和隔离 worktree 保持可用；执行根绑定可恢复、不可越过 workspace 白名单，`thread.read` 不注入 Codex 0.145 不支持的 `cwd`。
- 从项目详情进入任务页及直接打开线程 URL 均恢复正确 host、workspace、thread；失效选择显示明确错误，不回退到其他项目。
- Agent 运行期间 PowerShell、Git、Node、Codex、whoami、icacls 和计划任务控制均无可见命令行闪窗；重复启动不产生第二个逻辑 worker。
- 后端相关测试和全量回归、前端 `pnpm verify`、Windows Agent/MSI 回归、Docker 生产联调、浏览器消息与审批闭环全部通过，无 P0/P1。

## Phase 2

### 目标

将普通 workspace 与 Git worktree 隔离解耦，并建立可持久化、可验证的线程执行根绑定，消除非 Git 目录的 502 根因。

### 依赖

现有 workspace 配置、worktree 隔离开关、Agent 本地持久化、`AgentCommandExecutor`、`GitWorktreeAdapter` 和 Codex App Server 0.145 协议。

### 模拟用法

```text
普通目录：workspace_root → thread.read/resume/turn，不执行 git 命令
Git 仓库：workspace_root → 正常 Codex 命令，可检测隔离能力
隔离 worktree：thread_id → 已绑定 execution_root → 路径归属校验 → 执行
```

### 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `ExecutionRootBinding` | 执行根绑定 | 保存 `thread_id`、`workspace_key`、`execution_root`、`root_kind`、`kind`、`schema_version`。 |
| `RootKind` | 执行根类型 | 强类型枚举 `workspace`、`git_repository`、`isolated_worktree`。 |
| `WorktreeIsolationMode` | Worktree 隔离模式 | `disabled` 时禁止调用 Git worktree API，`enabled` 时才解析和校验 worktree。 |
| `ExecutionRootExtension` | 执行根扩展 | Pydantic 判别联合，`extra="forbid"`；外层与内层 `kind`、`schema_version` 必须一致。 |
