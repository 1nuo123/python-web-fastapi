# PostgreSQL 与鉴权基建执行方案

## 任务目标
最终要交付一套以 PostgreSQL 为默认数据库后端的数据库基建与鉴权体系，补齐真实表结构、SQLAlchemy 映射、Alembic 迁移、事务边界、数据库配置、数据库驱动的认证与授权链路，并保持当前 FastAPI 接口层的统一响应风格。

完成判定是：
- 数据库运行时不再停留在 SQLite 占位与空迁移入口。
- 鉴权不再依赖 `demo_users` 配置常驻认证，而是改为数据库用户、角色、scope 与 refresh token 会话驱动。
- 迁移、映射、测试、文档与源码一致。

## 全局约束
- 以源码为准。当前源码已切换为 PostgreSQL 运行时、真实 Alembic 迁移入口与数据库驱动鉴权；若文档与源码冲突，视为文档过期，必须在回归阶段修正。
- 严格遵守 `docs/standard/编码规范.md`、`docs/standard/命名规范.md`、`docs/standard/测试规范.md`。
- 继续使用 `Python 3.11+`、`SQLAlchemy 2.x`、`Alembic`、`Pydantic v2`、`FastAPI`、`psycopg`。
- 数据库默认后端切到 PostgreSQL；保留测试态独立库，不保留业务依赖 SQLite 的实现路径。
- 数据库相关代码统一收口到 `src/infrastructure/persistence/`，所有表映射文件统一放在同一目录 `src/infrastructure/persistence/orm_model/`。
- 统一使用 `MetaData(naming_convention=...)`、时区感知时间、显式索引、显式唯一约束、显式事务边界；仓储内禁止隐式 `commit()`。
- 鉴权保持“简单但完整”：用户名密码登录、JWT access token、数据库持久化 refresh token、refresh 轮换、主动吊销、角色与 scope 授权。
- 稳定结构必须遵守“公共头字段 + 强类型扩展字段”规则：扩展字段使用 Pydantic 判别联合；扩展模型必须包含 `kind`、`schema_version`；必须 `extra="forbid"`；禁止 `dict[str, Any]`、`metadata`、`extra_payload`；外层类型与内层扩展类型一致。
- 密码不得以明文长期保留在配置中；仅允许开发或测试环境用受控 bootstrap 方式注入初始管理员。

## 验收标准
- PostgreSQL 运行时配置完整，开发、测试、生产模板齐全，环境变量覆盖链路可用。
- `alembic upgrade head` 可在空库上一次性建出所需鉴权表、索引与约束，再次执行为无副作用。
- SQLAlchemy Engine、Session、Unit of Work、Repository 链路可真实读写 PostgreSQL。
- `/auth/token`、`/auth/refresh`、`/auth/revoke`、`/auth/me` 基于数据库身份数据可完整跑通。
- Refresh token 支持持久化、轮换、吊销与过期校验；不再依赖仅缓存态黑名单。
- 自动化测试、迁移验证、接口契约、文档回归全部通过。

## Phase 1
### 目标
完成 PostgreSQL 数据库基建改造，落地统一的数据库配置、SQLAlchemy 元数据与表映射、Alembic 迁移、Session 与 Unit of Work，实现“空库可迁移、应用可连接、事务边界清晰”的中间结果。

### 依赖
- 依赖当前 `src/infrastructure/settings/app_settings_loader.py` 的配置聚合能力。
- 依赖当前 `src/infrastructure/persistence/` 与 `src/infrastructure/shared_resource_mount.py` 的资源装配入口。
- 依赖 PostgreSQL 测试库或等效测试实例。

### 模拟用法
```python
settings = AppSettingsLoader().load()
engine = SqlAlchemyEngineFactory().build(settings.runtime.database)
AlembicRunner().upgrade_head()
session_factory = SqlAlchemySessionFactory(engine)
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| DatabaseRuntimeSettings | 数据库运行时配置 | 强类型 PostgreSQL 配置，至少包含 `backend`、`url`、`schema`、`pool_size`、`max_overflow`、`pool_recycle_seconds`、`connect_timeout_seconds`、`auto_upgrade_on_startup`，并启用 `extra="forbid"` |
| SqlAlchemyUnitOfWork | SQLAlchemy 工作单元 | 统一事务边界，提供 `commit`、`rollback`、`dispose`，仓储只消费 session，不自行提交事务 |
| AuthUserOrmModel | 用户表映射 | `auth_user` 表，保存登录名、密码哈希、启用状态与审计时间，使用 UUID 主键与唯一索引 |
| AuthRefreshTokenOrmModel | Refresh Token 表映射 | `auth_refresh_token` 表，保存 `session_id`、`token_id`、用户标识、过期时间、吊销时间、轮换来源，支撑 refresh 轮换与吊销 |

### 关键代码片段
```python
sqlalchemy_metadata = MetaData(
    naming_convention={
        "ix": "ix_%(table_name)s_%(column_0_name)s",
        "uq": "uq_%(table_name)s_%(column_0_name)s",
        "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
        "pk": "pk_%(table_name)s",
    }
)


class DatabaseRuntimeSettings(BaseModel):
    model_config = ConfigDict(extra="forbid")

    backend: Literal["postgresql"]
    url: str
    schema: str
    pool_size: int
    max_overflow: int
    auto_upgrade_on_startup: bool
```

### 校验
- 配置加载后 `settings.runtime.database.backend` 固定为 `postgresql`。
- 在空 PostgreSQL 库执行一次迁移后，五张表、主键、唯一约束与核心索引全部存在。
- `SqlAlchemyUnitOfWork` 能正常提交、回滚、关闭，仓储内无隐式提交。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| AuthenticatedPrincipal | 认证主体 | `kind="authenticated_principal"`，`schema_version` 固定，`extra="forbid"`，作为 `/auth/me` 与请求上下文的主体扩展体 |
| TokenPayload | 令牌载荷 | `kind="token"`，新增 `token_session_id`，区分 access / refresh 用途，`extra="forbid"` |
| TokenIssuePayload | 令牌签发扩展体 | `kind="token_issue"`，作为 `ResponseEnvelope[TokenIssuePayload]` 的强类型 `data` 字段 |
| TokenRevokePayload | 令牌吊销扩展体 | `kind="token_revoke"`，至少返回 `revoked` 与 `revoked_at_epoch`，`extra="forbid"` |
| RefreshTokenSessionPayload | Refresh 会话扩展体 | `kind="refresh_token_session"`，用于仓储与应用层之间传递 refresh 会话状态，禁止裸 `dict` |

class TokenPayload(BaseModel):
    model_config = ConfigDict(extra="forbid")

    kind: Literal["token"] = "token"
    schema_version: Literal["1.1"] = "1.1"

    token_session_id: str

```python
class RefreshTokenSessionPayload(BaseModel):
    model_config = ConfigDict(extra="forbid")

    kind: Literal["refresh_token_session"] = "refresh_token_session"
    schema_version: Literal["1.0"] = "1.0"
    session_id: str
    subject_id: str
    refresh_token_id: str
    revoked: bool
```

### 校验
- 使用数据库中的有效用户可成功登录并获取 access / refresh token。
- 使用已轮换或已吊销的 refresh token 会返回稳定错误码，不会再次签发新 token。
- `/auth/me` 返回的主体信息来自 JWT + 数据库授权结果，而非配置态 demo 用户。
