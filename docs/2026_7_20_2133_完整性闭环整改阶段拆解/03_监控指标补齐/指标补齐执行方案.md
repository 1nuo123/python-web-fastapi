# Phase 3 监控指标补齐 · 执行方案

> 本方案为**硬迁移方案**：一次性重构到最佳实践状态，不保留旧路径兼容层，不做渐进式迁移（1.0 配置直接升级 1.1，升级路径明确报错而非兼容）。
>
> 溯源：《2026_7_20_2133_生产级完整性闭环审查与整改执行方案》「Phase 3 监控指标补齐」，只做结构化归并，不改写原始口径。配套清单见 [指标补齐勾选清单](指标补齐勾选清单.md)。

## 阶段目标

- 直接问题（代码现状）：`PrometheusMetricsRegistry` 仅有 HTTP 请求数、耗时、ready 三个指标；安全事件、日志缓冲失败/积压、任务执行结果、运行时容量饱和度均不可观测，文档已自认缺口。
- 中间结果（目标形态）：四类新增低基数指标接入 `/metrics`；指标开关进入配置契约；Phase 2 的审计写失败快照转为可抓取指标。

## 依赖关系

- Phase 2 的 `AuditWriteFailureCounter` 快照接口。
- 既有契约：`MetricsRuntimeEnvelope`（1.0）、`RuntimeCapacityPolicy`、任务执行记录链。
- 既有文件：`prometheus_metrics_registry.py`、`shared_resource_lifecycle.py`、metrics_runtime TOML。

依据原始文档「阶段依赖关系」表，本阶段一行：

| 阶段 | 依赖 | 说明 |
|---|---|---|
| Phase 3 监控指标补齐 | Phase 1；与 Phase 2 的审计写失败信号对接 | 审计/日志缓冲指标需要 Phase 2 暴露的失败计数 |

## 模拟用法

```python
registry.record_security_event(SecurityEventMetric(
    event_type="rate_limit_blocked", decision="throttle", severity="warning",
))
registry.record_log_buffer_flush(LogBufferFlushMetric(
    reason="audit_critical", failed=False, batch_size=1,
))
registry.set_runtime_saturation(RuntimeSaturationMetric(
    resource="request_thread_pool", ratio=0.42,
))
```

## 阶段契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| SecurityEventMetric | 安全事件指标数据 | frozen dataclass：`event_type`、`decision`、`severity` 三个低基数标签，计入 `fastapi_security_event_total` |
| LogBufferFlushMetric | 日志缓冲刷盘指标数据 | `reason`（buffer_limit/interval/manual/shutdown/audit_critical）、`failed`、`batch_size`，计入 `fastapi_log_buffer_flush_total` 与 `fastapi_log_buffer_pending_items` |
| TaskExecutionMetric | 任务执行指标数据 | `task_name`（注册名，低基数）、`outcome`（success/failed/rejected），计入 `fastapi_task_execution_total` |
| RuntimeSaturationMetric | 运行时饱和度指标数据 | `resource`（request_thread_pool/db_pool/task_queue/log_buffer）、`ratio`（0-1 Gauge），计入 `fastapi_runtime_saturation_ratio` |
| PrometheusMetricsRuntimeDetail | Prometheus 指标运行时扩展模型 | 新增 `include_security_metrics`、`include_task_metrics`、`include_log_buffer_metrics`、`include_saturation_metrics` 布尔开关；`kind` 不变，`schema_version` 升 `1.1`，信封外内版本一致性校验同步更新 |

## 分步骤执行规划

1. `metrics_runtime_contract.py`：detail 扩展四个开关，版本升 1.1，外内一致性校验更新
2. `prometheus_metrics_registry.py`：新增四类指标与记录方法，标签白名单化
3. 安全事件落库路径挂接 `record_security_event`（与 Phase 2 门面同点位）
4. `log_buffer_dispatcher.py` 刷盘结果回调挂接 `record_log_buffer_flush` 与积压 Gauge
5. 任务执行记录链挂接 `record_task_execution`
6. `shared_resource_lifecycle.py`：容量策略快照周期性/事件式更新饱和度 Gauge
7. metrics_runtime TOML（base/production/test）补开关默认值

## 验收点

- 单测：每类指标记录后 `render()` 输出含对应样本；开关关闭时不注册。
- 脱敏测试：新增标签值全部来自枚举/注册名白名单，无自由文本。
- 契约测试：1.1 版本一致性、未知字段拒绝、1.0 配置文件升级路径明确报错。

## 关联的全局约束

- 日志：沿用脱敏约束——指标标签与日志只允许低基数值（方法、路由模板、状态码、reason_code、digest），禁止完整 URL、请求体、token、password、secret。

## 关联的全局验收标准

- 监控闭环：`/metrics` 新增 `fastapi_security_event_total`、`fastapi_log_buffer_flush_total`（含 failed 标签）、`fastapi_log_buffer_pending_items`、`fastapi_task_execution_total`、`fastapi_runtime_saturation_ratio`，标签全部低基数且通过脱敏契约测试。
