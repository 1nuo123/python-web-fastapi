# 后台授权与消息运行时 P1 整改执行方案

## 任务目标
交付 3 个 P1 问题的可执行整改方案，支撑后续真实改码、测试回归和文档收口。

完成判定是：内置授权 scope 不可被后台禁用且不会导致管理员自锁；生产环境可通过受控一次性 CLI 创建首个管理员；`runtime.message.backend=rabbitmq` 时挂载对象、资源状态、管理端展示和真实后端语义一致。

## 全局约束
- 以源码为准；若文档、图谱、历史执行方案与源码冲突，以源码执行结果为准，并在文档回归中说明旧文档可能过期。
- 内置 scope 属于系统保留能力，不按普通业务 scope 管理；后台接口只允许修改内置 scope 的名称、描述，禁止禁用或删除。
- 普通后台身份管理继续禁止把业务用户随意提升为 `admin`；生产首个管理员只能通过受控 CLI 初始化。
- `runtime.message.backend` 表示独立消息总线后端；RabbitMQ 后端必须挂载真实 `RabbitMqMessageBus`，不能只做探测或 Funboost broker 配置。
- API、CLI 结果、运行时资源状态、消息载荷等稳定契约采用“公共头字段 + 强类型扩展字段”规则。
- 扩展字段必须使用 Pydantic 判别联合，必须包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议。
- 外层类型与内层扩展类型必须一致，例如 `backend == backend_detail.kind`、`header.kind == detail.kind`。
- 权限、自锁、初始化和 RabbitMQ 测试必须隔离状态，不依赖测试顺序。
- RabbitMQ 实现遵循连接可关闭、交换机幂等声明、持久化消息、发布确认、超时控制、失败可观测的实践。

## 验收标准
- `PATCH /admin/scopes/auth:manage` 设置 `enabled=false` 返回失败；`auth:read`、`system:read`、`task:dispatch` 等路由授权依赖内置 scope 同样不可禁用。
- 自定义 scope 可正常禁用；禁用后鉴权快照过滤该自定义 scope，内置管理能力不受影响。
- 当前管理员不能通过角色 scope 替换、用户角色替换、用户停用、scope 禁用等路径移除自己继续管理所需权限。
- 修复后管理员仍可访问 `/admin/users`、`/admin/scopes`。
- 生产配置下 CLI 可创建首个 `admin`；重复执行不会创建第二个超级管理员；普通后台接口仍不能分配 `admin` 角色。
- `runtime.message.backend=rabbitmq` 时管理端资源状态明确显示 RabbitMQ 真实消息总线，挂载对象不是 `LocalMessageBus`。
- 相关单元、接口、初始化、路径和必要集成测试全部通过。

## Phase 1
### 目标
禁止后台接口禁用路由授权依赖的内置 scope，并补齐当前管理员自锁校验。

阶段完成后，内置 `auth:read`、`auth:manage`、`system:read`、`task:dispatch` 等系统能力不可被禁用；自定义 scope 仍可按业务需要启停。

### 依赖
- `src/domain/auth/auth_scope_code.py` 中的 `AuthScopeCode` 枚举。
- `src/api/admin_route_authorization.py` 中后台路由授权依赖。
- `AdminScopeUpdateCommand`、`AdminRoleScopeReplaceCommand`、`AdminUserRoleReplaceCommand` 已有命令边界。
- `auth_identity_repository_impl.py` 当前鉴权快照会过滤 disabled scope，此行为保留。

### 模拟用法
```bash
curl -X PATCH /admin/scopes/auth:manage \
  -H "Authorization: Bearer <admin-token>" \
  -H "Content-Type: application/json" \
  -d '{"header":{"kind":"scope_update","schema_version":"1.0"},"detail":{"kind":"scope_update","schema_version":"1.0","enabled":false}}'
```

预期：返回 409 或 422，错误语义为“内置授权 scope 不允许禁用”。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `AdminScopeUpdateCommand.actor_subject_id` | 操作者主体标识 | 后台 scope 更新必须携带当前管理员主体，用于自锁校验。 |
| `AdminScopeUpdateCommand.enabled` | 启用状态 | 自定义 scope 可修改；受保护内置 scope 禁止设置为 `false`。 |
| `ProtectedAdminScopeCode` | 受保护后台 scope 集合 | 从后台路由授权依赖集中推导，至少包含 `auth:read`、`auth:manage`、`system:read`、`task:dispatch`。 |
| `AdminScopeUpdateRequest` | scope 更新请求 | 继续使用现有公共头字段 + 强类型扩展字段；扩展字段含 `kind`、`schema_version`、`extra="forbid"`。 |
| `AdminScopeSnapshot.enabled` | scope 快照启用状态 | 反映持久化状态；内置 scope 在列表中仍显示为启用。 |

## Phase 3
### 目标
把 `runtime.message.backend=rabbitmq` 落成真实独立 RabbitMQ 消息总线，并让挂载对象、资源状态、管理端展示和初始化测试保持一致。

阶段完成后，`shared_message_bus` 在 RabbitMQ 后端下挂载 `RabbitMqMessageBus`；RabbitMQ 不再只是启动探测或 Funboost broker 配置。

### 依赖
- `task_runtime_contract.py` 已有 `MessageBackendDetailUnion` 判别联合和 `RabbitMqMessageBackendDetail`。
- `message_bus_contract.py` 中 `MessageBus.publish()` 抽象。
- `runtime_resource_bootstrapper.py` 当前统一创建 `LocalMessageBus()` 的装配点。
- `shared_resource_mount.py` 的资源状态、运行时装配、管理端读取入口。
- RabbitMQ 连接由 `amqpstorm` 和现有 `RabbitMqMessageGateway` 能力复用。

### 模拟用法

[runtime.message.backend_detail]

rabbitmq_url = "amqp://app:secret@rabbitmq:5672/%2F"
startup_probe_enabled = true
startup_probe_timeout_seconds = 5

task_exchange_type = "direct"

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `MessageBus` | 消息总线抽象 | 统一 `publish()`，新增关闭或后端标识能力时不得破坏本地实现。 |
| `RabbitMqMessageBus` | RabbitMQ 消息总线 | 独立后端对象，负责声明交换机、发布 `TaskMessageEnvelope`、发布确认和关闭连接。 |
| `RabbitMqMessageBackendDetail` | RabbitMQ 消息后端扩展 | 已是 Pydantic 判别联合扩展；保留 `kind`、`schema_version`、`extra="forbid"`，补齐字段消费。 |
| `TaskMessageEnvelope` | 任务消息信封 | 公共头 `header` 与强类型载荷 `payload` 的 `kind/schema_version` 必须一致。 |
| `RuntimeResourceState.detail` | 资源状态详情 | `shared_message_bus` 就绪详情必须说明真实后端为 local 或 rabbitmq。 |
| `MessageBackend` | 消息后端枚举 | 外层 `runtime.message.backend` 必须与内层 `backend_detail.kind` 一致。 |

### 关键代码片段
```python
def build_message_bus(detail: MessageBackendDetailUnion) -> MessageBus:
    if isinstance(detail, LocalMessageBackendDetail):
        return LocalMessageBus()
    if isinstance(detail, RabbitMqMessageBackendDetail):
        return RabbitMqMessageBus(detail=detail)
    raise TypeError("unsupported message backend detail")
```

### 校验
- `runtime.message.backend=local` 时挂载对象是 `LocalMessageBus`。
- `runtime.message.backend=rabbitmq` 时挂载对象是 `RabbitMqMessageBus`。
- RabbitMQ 配置无效或探测失败时资源状态进入失败路径并记录原因。
