# Codex 官方会话体验统一整改执行方案

## 任务目标

在现有 FastAPI 控制面、Windows Agent、Codex App Server `0.145.0` 冻结协议和 Nuxt 4 前端基础上，交付与官方 Codex App 信息架构一致的会话体验：

- 用户路径统一为“主机 -> 项目 -> 会话 -> 当前工作”，界面术语统一使用“会话”；源码与协议继续使用 `thread`。
- 根治空标题、点击后才出现标题、同步时间污染排序和同时间戳顺序漂移。
- 删除主页面与侧栏重复的“最近任务”，改为项目内完整会话列表、置顶、搜索、归档和稳定活动时间排序。
- 桌面端形成“项目栏 + 会话栏 + 会话正文 + 按需上下文栏”；移动端形成 Remote 主机、项目、会话逐层导航。
- 审批、Diff、测试和终端输出回到会话上下文；审批中心只保留为通知队列和集中处理入口。
- 不扩大消息正文持久化范围，不改变现有鉴权 Scope、Agent 本地 App Server 边界和生产数据卷。

完成判定：历史和新会话均有稳定标题；手工标题不会被同步覆盖；会话严格按置顶与 `recency_at` 排序；桌面与移动端没有重复列表和重叠控件；重命名、置顶、搜索、归档、恢复及会话内审批/审查闭环可用；自动化、Docker 生产更新和真实浏览器回归全部通过。

## 全局约束

- 当前源码、数据库模型、冻结的 `protocol/codex_app_server/0.145.0` 和可执行测试为事实源；旧文档中“任务”“最近任务”“按 `updated_at` 排序”和仅靠会话缓存保标题的描述可能过期。
- 官方公开资料确认项目侧栏、会话列表、审查面板、置顶、重命名、搜索、归档及 Remote 手机控制能力；官方未公开完整 Figma 和设计令牌，因此只对齐信息架构、交互和状态语义，不承诺像素级复制。
- App Server `0.145.0` 已冻结 `recencyAt`、`thread/name/set`、`thread/archive`、`thread/unarchive` 和标题搜索；其 schema 未提供 `isPinned`，会话/项目置顶必须由控制面持久化，禁止调用不存在的上游字段。
- 跨边界契约统一采用“公共头字段 + 强类型扩展字段”；扩展字段使用 Pydantic 判别联合，包含 `kind`、`schema_version`，启用 `extra="forbid"`，并校验外层类型/版本与内层一致。
- 禁止新增 `dict[str, Any]`、`metadata`、`extra_payload`、魔法字符串和魔法数字；封闭状态使用 `Enum`，稳定限制使用模块常量。
- Agent 只允许在本机把 `preview` 归一化为有界短标题；原始 `preview`、消息正文、Diff 正文不得进入线程索引、日志或搜索库。
- 标题优先级固定为：手工名称 -> App Server 名称 -> 第一条用户消息短标题 -> `新会话 · 创建时间`；低优先级来源不得覆盖高优先级来源。
- 会话排序固定为：`is_pinned DESC -> recency_at DESC -> created_at DESC -> upstream_thread_id DESC`；`last_synced_at` 仅表示同步时间，禁止参与排序。
- 搜索只覆盖会话标题、项目名称和默认分支；本轮不建立消息正文全文索引，不改变现有隐私边界。
- Python 日志、异常、注释和 Sphinx/reST 三级文档使用中文；禁止 `print` 和无意义异常捕获；资源由上下文管理器、UoW、测试夹具或显式清理负责释放。
- 前端继续使用 Pinia、纯 Reducer、运行时事件校验和现有同源 API；不换状态库，不把 WebSocket、Timer、Promise 或不可序列化对象放入 Pinia state。
- 生产回归先检查现有容器和数据卷，只更新受影响服务；禁止 `docker compose down -v`、删除卷或无必要的全量重建。

## 验收标准

- 可见会话不再显示“未命名任务”；缺少上游标题时显示稳定的“新会话 · 创建时间”，打开会话前后标题一致。
- 手工重命名跨刷新、重连、Agent 重启和重新同步保持不变；App Server 新名称只在没有手工名称时生效。
- 同一批次同步不会制造相同活动时间；排序在刷新、分页、搜索、归档恢复和实时事件后保持稳定。
- 会话和项目可置顶；会话可重命名、搜索、归档和恢复；归档会话不出现在默认列表。
- 桌面首屏只有一套项目/会话导航；会话正文为主区域，上下文栏仅在用户查看变更、终端、测试或审批时打开。
- 手机端先选主机，再按项目进入会话；会话正文全屏，输入框固定底部，审批和审查使用全屏页或底部弹层。
- 审批入口带待处理数量并可深链到对应会话；会话内可完成审批，集中审批页不再承担主要导航职责。
- 原始 `preview` 和消息正文不落入 PostgreSQL 线程索引、前端列表缓存或日志；所有新契约拒绝未知字段和类型/版本不一致。
- 后端定向与全量测试、Ruff、mypy、前端 `pnpm verify`、Docker 健康检查、桌面/移动真实浏览器回归全部通过，无新增 P0/P1。

## Phase 1

### 目标

class CodexTimelineItemEnvelope(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    header: CodexTimelineItemHeader
    detail: CodexTimelineItemDetail

    @model_validator(mode="after")
    def validate_detail_identity(self) -> Self:
        if self.header.detail_kind != self.detail.kind:
            raise ValueError("时间线条目头与扩展类型不一致。")
        if self.header.schema_version != self.detail.schema_version:
