# 应用端口隔离分步骤执行方案

## 1. 阶段目标
移除应用层对基础设施实现类型的直接依赖。

阶段完成后：`src/application/` 下用例只依赖应用层端口或核心契约，基础设施实现只在装配层和适配器层出现。

本阶段按硬迁移口径执行：一次性完成端口契约、用例构造参数、基础设施适配器和装配调用替换，不保留新旧依赖双轨。

## 2. 依赖关系
| 依赖项 | 说明 |
|---|---|
| Phase 3 | 需先固定资源访问边界，避免应用层继续直接读取 `SettingsStateHolder` 或基础设施资源对象。 |
| `issue_access_token_usecase.py` | 当前直接依赖 `AuthFailureThrottle`、`JwtTokenService`、`PasswordHasher`、`SettingsStateHolder`。 |
| `refresh_access_token_usecase.py` | 需纳入鉴权运行时端口，避免直接耦合基础设施服务。 |
| `revoke_access_token_usecase.py` | 需纳入鉴权运行时端口，保持令牌吊销行为不变。 |
| `health_probe_usecase.py` | 需通过配置读取端口读取当前配置快照。 |
| `dispatch_background_job_usecase.py` | 需通过任务运行时端口派发任务和读取默认配置。 |
| `SharedResourceMount` | 作为端口适配器或装配层入口，承接基础设施实现。 |

## 3. 契约
本阶段契约采用“公共头字段 + 强类型扩展字段”规则：

- 外层信封使用公共头字段。
- 扩展字段使用 Pydantic 判别联合。
- 扩展字段必须包含 `kind`、`schema_version`。
- 扩展模型必须启用 `extra="forbid"`。
- 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载扩展内容。
- 外层类型与内层扩展类型的 `kind`、`schema_version` 必须一致。

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `ApplicationPortHeader` | 应用端口公共头 | 承载 `kind`、`schema_version`、`port_name`。 |
| `AuthRuntimePortDetail` | 鉴权运行时端口扩展 | `kind="auth_runtime_port"`，声明签发、刷新、吊销令牌所需的最小能力。 |
| `SettingsReaderPortDetail` | 配置读取端口扩展 | `kind="settings_reader_port"`，声明读取当前配置快照的最小能力。 |
| `TaskRuntimePortDetail` | 任务运行时端口扩展 | `kind="task_runtime_port"`，声明任务注册、派发与默认配置读取能力。 |
| `ApplicationPortEnvelope` | 应用端口信封 | 外层公共头 + 判别联合扩展；扩展含 `kind`、`schema_version`，`extra="forbid"`。 |

## 4. 分步骤执行方案
### Step 1：新增应用层端口目录
新增 `src/application/ports/`，集中承载应用层可见的端口契约。

执行要求：
- 新增 `auth_runtime_port.py`。
- 新增 `settings_reader_port.py`。
- 新增 `task_runtime_port.py`。
- 端口只表达应用层需要的最小能力，不暴露基础设施类名。
- 端口契约采用 `Protocol` 或项目既有抽象方式，不引入运行时强耦合。

验收点：
- `src/application/ports/` 成为应用层依赖基础设施能力的唯一边界。
- 端口文件不 import `src.infrastructure.*`。

### Step 2：硬迁移鉴权运行时端口
将签发、刷新、吊销令牌所需能力抽象到 `auth_runtime_port.py`。

执行要求：
- 抽象 token 签发能力。
- 抽象 token 刷新能力。
- 抽象 token 吊销能力。
- 抽象密码哈希校验能力。
- 抽象失败限流能力。
- 抽象用户仓储工厂或用户读取能力。
- 修改 `issue_access_token_usecase.py`、`refresh_access_token_usecase.py`、`revoke_access_token_usecase.py`，只依赖鉴权运行时端口。

验收点：
- 鉴权用例不再 import `AuthFailureThrottle`、`JwtTokenService`、`PasswordHasher`、`SettingsStateHolder`。
- 现有 `/auth/*` 接口响应和业务行为不变。

### Step 3：硬迁移配置读取端口
将健康探针和系统概览所需的配置读取能力抽象到 `settings_reader_port.py`。

执行要求：
- 端口只暴露应用层需要的当前配置快照读取能力。
- 配置快照返回值使用稳定契约或已有只读模型。
- 用例不得直接持有 `SettingsStateHolder`。
- 基础设施侧通过适配器包装现有配置状态来源。

验收点：
- 健康探针和系统概览用例不直接 import `src.infrastructure.settings.*`。
- `/health/*`、`/system/info` 行为不变。

### Step 4：硬迁移任务运行时端口
将后台任务派发能力抽象到 `task_runtime_port.py`。

执行要求：
- 抽象任务注册读取能力。
- 抽象任务派发能力。
- 抽象默认任务配置读取能力。
- `dispatch_background_job_usecase.py` 只依赖任务运行时端口。
- 不把资源挂载对象直接传入应用层用例。

验收点：
- 任务派发用例不直接依赖基础设施任务运行时实现。
- 任务派发主链路行为不变。

### Step 5：替换装配层依赖注入
由 `SharedResourceMount` 或基础设施适配器实现应用层端口，并在装配层注入用例。

执行要求：
- 基础设施适配器可以 import `src.infrastructure.*`。
- 应用层用例只能看到端口类型。
- 现有测试工厂按新端口注入依赖。
- 不保留旧构造参数兼容层。

验收点：
- 生产装配、测试装配均使用端口适配器。
- 用例构造参数不再出现基础设施实现类型。

### Step 6：执行边界静态检查
使用 `rg` 固化应用层依赖边界。

执行要求：
- 对 `src/application` 执行基础设施 import 检查。
- 将检查加入单元测试或路径回归测试。
- 对确需跨层的核心契约依赖做白名单说明，白名单不得包含基础设施实现类。

验收点：
- `rg "from src\\.infrastructure" src/application -g "*.py"` 无命中。
- 鉴权、刷新、吊销、健康探针、任务分发单元测试通过。

## 5. 关键代码片段
端口契约骨架如下，最终实现需保持“公共头字段 + 强类型扩展字段”规则：

```python
ApplicationPortDetail = Annotated[
    AuthRuntimePortDetail | SettingsReaderPortDetail | TaskRuntimePortDetail,
    Field(discriminator="kind"),
]

class ApplicationPortEnvelope(BaseModel):
    model_config = ConfigDict(extra="forbid")
    header: ApplicationPortHeader
    detail: ApplicationPortDetail
```

## 6. 校验与验收点
- `rg "from src\\.infrastructure" src/application -g "*.py"` 无命中。
- 鉴权、刷新、吊销、健康探针、任务分发单元测试通过。
- 现有 HTTP 接口响应和业务行为不变。
- 基础设施实现类只出现在装配层、适配器层或基础设施层。
