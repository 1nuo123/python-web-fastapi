# 本地直启环境加载分步骤任务清单

## Step 1：新增 dotenv 配置来源模型与解析器
- [x] 新增 `dotenv_settings_loader.py`。
- [x] 使用标准库解析简单 `KEY=VALUE`。
- [x] 支持跳过空行。
- [x] 支持跳过注释行。
- [x] `.env` 不存在时返回空配置，不抛出启动异常。
- [x] 解析过程不记录变量值。
- [x] 为 dotenv 来源补齐 `DotenvSourceDetail` 强类型扩展模型。
- [x] 扩展模型包含 `kind`、`schema_version`。
- [x] 扩展模型启用 `extra="forbid"`。

## Step 2：固定配置来源优先级
- [x] 调整 `AppSettingsLoader.load()`，先解析有效 `AppEnvironment`。
- [x] 将配置合并顺序固定为 `process env > local .env > TOML`。
- [x] 保持进程环境变量最终覆盖。
- [x] 保持现有 TOML 文件层级收集逻辑不变。
- [x] 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载配置来源扩展。
- [x] 保证 `SettingsSourceEnvelope` 外层类型与内层扩展类型一致。

## Step 3：保持生产环境强安全约束
- [x] 生产环境显式跳过仓库 `.env`。
- [x] 生产环境缺失进程级 `JWT_SECRET` 时继续失败。
- [x] 保留生产环境 JWT 弱密钥校验。
- [x] 保留生产环境数据库连接配置校验。
- [x] 保留生产环境 Redis 连接配置校验。
- [x] 保留生产环境 RabbitMQ 连接配置校验。

## Step 4：补齐开发环境本地直启变量
- [x] 开发环境缺失 `JWT_SECRET` 时可由 `.env` 补齐。
- [x] 开发环境缺失 `AUTH_BOOTSTRAP_ADMIN_PASSWORD` 时可由 `.env` 补齐。
- [x] 不向基础 TOML 写入默认 `jwt_secret`。
- [x] 不降低 `config/runtime/auth_runtime/auth_runtime_base.toml` 安全基线。
- [x] 验证本地 `uvicorn src.main:app --reload` 不因缺少进程级认证变量失败。

## Step 5：更新 env 示例文档
- [x] `.env.docker.example` 补充本地直启变量说明。
- [x] `.env.production.example` 明确生产不读取仓库 `.env`。
- [x] 示例文件不得引导生产使用示例密钥。
- [x] 文档口径与源码实际加载顺序保持一致。

## Step 6：阶段校验
- [x] 清空进程级 `JWT_SECRET` 后，开发环境能从 `.env` 构建 `ApplicationSettings`。
- [x] `APP_ENV=production` 且缺失进程级 `JWT_SECRET` 时仍启动失败。
- [x] 日志不输出 `.env` 中的具体值。
- [x] 开发环境 `.env` 值低于进程环境变量优先级。
- [x] 生产环境不会从仓库 `.env` 补齐敏感配置。
