# 快速开发骨架整改硬迁移总览

## 来源与口径
- 原始文档：`docs/2026_5_23_1332_快速开发骨架整改执行方案.md`
- 输出目录：`docs/2026_5_23_1332_快速开发骨架整改硬迁移拆解/`
- 本拆解不删除、不修改原始文档，只新增结构化拆解文档。
- 本方案按硬迁移执行：一次性将相关模块迁移至最终最佳实践状态，不采用渐进式并存设计。
- 若文档、图谱、历史方案与源码冲突，以源码为准，并在文档回归中说明历史文档可能过期。

## 任务目标
交付一套面向后续真实改码与测试回归的骨架整改硬迁移方案，解决本地直启不顺、异常日志敏感信息风险、配置与资源装配过重、应用层依赖基础设施、Web 模块新增不够集中等问题。

完成判定：
- 本地 `uvicorn src.main:app` 可在开发环境下按明确规则读取本地 `.env` 或环境变量完成启动。
- 异常日志、数据库日志和降级日志不落明文密码、token、连接串凭据和完整敏感 traceback。
- 配置加载和资源挂载完成职责拆分，后续新增配置或资源无需继续堆入巨型文件。
- 应用层用例不再直接依赖基础设施实现类型。
- 新增 Web 模块有集中注册入口，不再必须改核心枚举与硬编码导入清单。

## 全局约束
- 不提交真实 `.env`、真实密钥、真实密码、真实 token、真实生产连接串。
- 生产环境禁止从仓库 `.env` 自动补齐密钥；生产敏感值只允许来自进程环境变量、Compose Secret 或外部 Secret Manager。
- 契约设计统一采用“公共头字段 + 强类型扩展字段”；外层公共字段承载稳定字段，扩展字段使用 Pydantic 判别联合。
- 所有扩展字段必须包含 `kind`、`schema_version`，必须启用 `extra="forbid"`。
- 禁止用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议字段。
- 外层类型与内层扩展类型必须一致，例如 `redaction.header.kind` 必须与 `redaction.detail.kind` 语义一致。
- 兼容现有接口响应结构、现有测试工厂、现有 Compose 开发路径。
- 拆分必须一次性落到最终职责边界，不保留新旧实现双轨。

## 验收标准
- 清空 `JWT_SECRET`、`AUTH_BOOTSTRAP_ADMIN_PASSWORD` 后，本地开发环境能按 `.env` 规则启动；生产环境仍因缺失外部密钥失败。
- 异常响应和结构化日志均不包含明文连接串密码、Bearer token、JWT、`password=`、`*_PASSWORD=` 等敏感值。
- `app_settings_loader.py` 不再承载 dotenv 读取、递归 merge、安全校验全部实现细节。
- `shared_resource_mount.py` 完成资源构建、释放、访问器刷新逻辑的独立模块提取。
- `src/application/*` 不再直接 import `src.infrastructure.auth.*` 或 `src.infrastructure.settings.*`。
- 新增一个示例 Web 模块时，只需在集中 manifest/registry 中登记，不需要改核心模块枚举。
- 单元、契约、异常、接口、路径和集成回归测试通过。
- 相关设计文档、使用说明和测试说明与源码一致。

- Phase 1 是本地启动基线，Phase 2 至 Phase 5 均依赖稳定配置加载入口。

- Phase 4 依赖 Phase 3 固定后的端口与资源访问边界。
