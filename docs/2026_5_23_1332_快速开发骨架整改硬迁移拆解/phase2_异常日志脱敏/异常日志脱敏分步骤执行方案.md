# 异常日志脱敏分步骤执行方案

## 迁移口径
本阶段按硬迁移执行：一次性将异常日志脱敏能力迁移至最终最佳实践状态，不保留新旧逻辑并存路径，不做渐进式开关兼容。

## 阶段目标
防止异常 `detail`、`traceback`、数据库日志降级输出落入明文敏感信息。

阶段完成后：响应侧和日志侧均具备敏感文本统一脱敏能力。

## 依赖关系
- 依赖 Phase 1 稳定测试环境启动。
- 依赖当前 `LogEventBuilder`、`DatabaseLogWriter`、异常呈现器。
- 依赖当前异常响应脱敏测试作为回归基础。

## 分步骤执行方案
### Step 1：建立统一敏感文本脱敏能力
新增 `SensitiveTextRedactor`，集中实现以下敏感文本脱敏规则：
- 连接串凭据脱敏。
- Bearer Token 脱敏。
- JWT 类文本脱敏。
- 密码类键值文本脱敏，例如 `password=...`、`*_PASSWORD=...`。

该能力作为日志侧唯一脱敏入口，避免各调用点散落正则或重复实现。

### Step 2：接入异常日志构建链路
修改 `LogEventBuilder.build_exception_event()`：
- 写入异常 `detail` 前必须调用 `SensitiveTextRedactor.redact()`。
- `exception.detail` 与 `str(exception)` 均不得以明文进入日志事件。
- 保持客户端异常响应不包含内部 `detail`。

### Step 3：接入 traceback 写入链路
修改 traceback 写入逻辑：
- 对 traceback 文本做二次脱敏。
- 确保堆栈中的数据库 URL、Bearer Token、JWT、密码键值不会明文持久化。
- 不改变现有 traceback 是否启用、是否写入的配置语义。

### Step 4：接入数据库日志降级输出链路
修改 `DatabaseLogWriter._fallback_stdout()`：
- 降级输出事件 JSON 前必须完成脱敏。
- 确保数据库日志写入失败时，stdout 中也不会泄漏敏感信息。
- 保持降级输出能力不变，仅改变输出前的敏感文本处理。

### Step 5：补齐误伤边界
增加脱敏规则边界用例：
- 覆盖数据库 URL、Bearer Token、JWT、密码键值。
- 覆盖普通业务文本，避免误删或过度替换。
- 保证日志事件结构不因脱敏而损坏。

## 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `LogRedactionHeader` | 日志脱敏公共头 | 承载 `kind`、`schema_version`、`rule_set_name`。 |
| `CredentialUrlRedactionDetail` | 凭据 URL 脱敏扩展 | `kind="credential_url_redaction"`，用于连接串用户名密码脱敏。 |
| `BearerTokenRedactionDetail` | Bearer Token 脱敏扩展 | `kind="bearer_token_redaction"`，用于 HTTP Authorization 与 JWT 类文本脱敏。 |
| `KeyValueSecretRedactionDetail` | 键值密钥脱敏扩展 | `kind="key_value_secret_redaction"`，用于 `password=...`、`*_PASSWORD=...` 等文本脱敏。 |
| `LogRedactionRuleEnvelope` | 日志脱敏规则信封 | 外层公共头 + 判别联合扩展；扩展含 `kind`、`schema_version`，`extra="forbid"`。 |

## 契约约束
- 脱敏规则必须采用“公共头字段 + 强类型扩展字段”结构。
- 扩展字段必须使用 Pydantic 判别联合。
- 扩展字段必须包含 `kind`、`schema_version`。
- 扩展字段必须启用 `extra="forbid"`。
- 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载扩展信息。
- 外层类型与内层扩展类型必须一致。

## 校验与验收点
- 构造含数据库 URL、Bearer token、`password=` 的异常，日志事件 `detail` 中只出现掩码。
- traceback 文本中的数据库 URL、Bearer token、JWT、密码键值只出现掩码。
- `DatabaseLogWriter._fallback_stdout()` 降级输出事件 JSON 前已完成脱敏。
- 500 响应体仍不包含 `detail` 字段和内部异常文本。
- 普通业务文本不会被误删、误替换。
