# 运行基础与交付闭环_分步骤执行方案

## 1. 阶段目标

补齐 P0 运行基础和交付闭环：CORS、生产 migration job、分页下推、测试与文档回归。完成后，改动可进入真实回归。

本阶段是硬迁移闭环，不引入渐进式迁移设计。

## 2. 全局约束

- 若文档、图谱、源码冲突，以当前源码为准；`docs/2026_5_26_1849_admin_server_execution_plan.md` 与 `docs/2026_5_27_1330_管理员身份CRUD执行方案.md` 的后台暴露范围已可能过期，回归时必须同步修正。
- 遵守 `docs/standard` 下编码、命名、测试规范；Python 使用 3.11+ 现代类型标注。
- 本轮优先改上游 API、模块清单、配置、应用用例与测试；除业务审计可能需要审计总线或查询适配外，不主动改动基建层核心代码。
- `/admin/*` 只表示业务管理后台；平台、运维、安全控制面后续如保留，必须迁移到默认关闭的 `/ops/*` 或 CLI。
- 默认 `config/app_base.toml` 不启用 `admin_task`、`admin_settings`、`admin_log`、`security_protection`、`system_overview` 作为业务后台模块。
- 通用任务派发、配置热重载、任意 scope CRUD、任意角色权限组合编辑、原始日志、安全事件、指标、IP 封禁、运行时资源不得暴露给业务管理员。
- 业务管理员只允许分配预定义业务角色；角色到后端 scope 的绑定由代码、seed、migration 或 bootstrap 初始化，不由业务后台编辑。
- 用户删除语义统一为停用用户并撤销会话，不做物理删除；接口、响应、文档不得再表达为物理删除。
- 所有 list API 必须具备分页契约，过滤、排序、分页下推 SQL；禁止只在内存中过滤后截断。
- P0 仍需补齐运行基础：CORS 运行时配置、生产一次性 migration job、分页契约。
- 契约必须使用“公共头字段 + 强类型扩展字段”：扩展字段使用 Pydantic 判别联合，扩展字段必须包含 `kind`、`schema_version`，必须启用 `extra="forbid"`。
- 禁止在契约中使用 `dict[str, Any]`、`metadata`、`extra_payload`；外层 `header.kind/schema_version` 必须与内层扩展类型一致。
- 日志、异常、注释和文档使用中文；响应、日志、审计不得泄漏密码、token、密钥、完整 IP、完整 user-agent 或底层任务 payload 原文。

## 5. 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| RuntimeCorsSettings | 运行时 CORS 配置 | 通过强类型配置控制允许源、方法、头、凭证，生产默认收紧 |
| MigrationJobResult | 迁移任务结果 | 生产启动前一次性 migration job 成功才允许 app 启动 |
| AdminListPageQuery | 后台分页查询 | 统一业务后台列表分页、过滤、排序输入 |
| AdminListPagePayload | 后台分页响应 | 统一分页响应结构，支持 `items`、`page_size`、`next_cursor` 或 `total` |
| AdminRegressionResult | 后台回归结果 | 记录测试入口、结果、失败修复与剩余风险 |

## 6. 分步骤执行

### 6.1 CORS 运行基础

- 在运行时配置中新增 CORS 强类型配置，并接入 `CORSMiddleware`。
- CORS 配置缺失或生产通配风险必须有明确校验。
- 接口测试覆盖 CORS 允许源与拒绝源行为。

### 6.2 生产 migration job

- 生产 compose 或部署流程增加一次性 migration job，`app` 依赖 migration 成功。
- migration job 成功后 app 启动；migration 失败时 app 不启动。
- migration job 失败时 app 不进入服务状态。

### 6.3 后台列表分页

- 所有后台 list API 补统一分页契约。
- 仓储层实现过滤、排序、分页 SQL 下推，并补必要索引或 migration。
- 所有后台 list API 拒绝非法分页参数。
- 分页测试能证明不是先取全量再内存截断。

### 6.4 测试更新

- 更新 smoke test，覆盖默认业务后台模块启动与禁用模块未挂载。
- 更新接口、契约、单元、集成测试。
- 本次测试覆盖新增行为、变更行为和回归行为。

测试要求：

- 契约测试：管理员身份信封 header/detail 一致性、未知字段拒绝、业务角色只读载荷。
- 契约测试：用户停用/启用请求与响应，不再表达物理删除。
- 契约测试：业务审计 `AdminAuditEnvelope` 判别联合、分页响应、敏感字段不出现。
- 单元测试：`WebModuleManifestRegistry` 默认业务后台模块集合不含 ops-only 模块。
- 单元测试：业务角色过滤拒绝技术角色和 ops-only 角色。
- 单元测试：用户停用、启用、密码重置、角色替换写业务审计并撤销会话。
- 单元测试：分页查询对象边界、排序白名单、SQL 下推查询参数。
- 接口测试：默认 OpenAPI 不暴露 `/admin/tasks/*`、`/admin/settings/reload*`、`/admin/scopes*` 写接口、`/admin/roles*` 写接口、`/admin/logs`、`/admin/security-events`。
- 接口测试：`GET /admin/roles` 只读可用，写接口返回 404 或未挂载。
- 接口测试：`/admin/audit-events` 权限、过滤、分页、脱敏。
- 接口测试：CORS 允许源与拒绝源行为。
- 集成测试：默认配置 `create_app + lifespan + /health/live` 通过，禁用模块未挂载。
- 集成测试：migration job 成功后 app 启动；migration 失败时 app 不启动。
- 回归测试：既有 auth、health、业务身份查询路径不被破坏。

## 8. 回归修复

真实测试失败后按失败类型修复源码、测试、文档，并回跑最小失败集与完整回归。

- 模块边界失败：修正 manifest、`app.modules.enabled`、route composer 和 OpenAPI 预期。
- 契约失败：修正 Pydantic 判别联合、`extra="forbid"`、`kind/schema_version` 一致性。
- 权限失败：修正业务后台授权常量、业务角色过滤和测试主体权限。
- 用户状态失败：修正停用/启用语义、会话撤销和审计写入。
- 业务审计失败：修正审计事件映射、白名单、脱敏和分页过滤顺序。
- 分页失败：修正仓储 SQL 查询、排序白名单、索引或迁移。
- CORS 失败：修正运行时配置解析、生产校验与中间件装配顺序。
- migration 失败：修正迁移入口、compose 依赖和失败传播。
- 修复后回跑对应失败测试文件。
- 最后回跑 `.\.venv\Scripts\python.exe -m pytest -q`。
