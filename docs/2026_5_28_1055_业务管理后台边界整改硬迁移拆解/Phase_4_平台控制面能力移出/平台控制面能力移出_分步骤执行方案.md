# 平台控制面能力移出_分步骤执行方案

## 阶段目标

把任务、配置、安全、系统运行时能力从业务后台移出，并为未来业务动作接口留下明确模式。完成后，业务管理员看不到底层任务系统、配置重载、安全策略和运行时资源。

## 全局约束

- 若文档、图谱、源码冲突，以当前源码为准；旧管理员服务端方案与管理员身份 CRUD 方案中的后台暴露范围已可能过期，回归时必须同步修正。
- `/admin/*` 只表示业务管理后台；平台、运维、安全控制面后续如保留，必须迁移到默认关闭的 `/ops/*` 或 CLI。
- 默认 `config/app_base.toml` 不启用 `admin_task`、`admin_settings`、`admin_log`、`security_protection`、`system_overview` 作为业务后台模块。
- 通用任务派发、配置热重载、任意 scope CRUD、任意角色权限组合编辑、原始日志、安全事件、指标、IP 封禁、运行时资源不得暴露给业务管理员。
- 业务管理员只允许分配预定义业务角色；角色到后端 scope 的绑定由代码、seed、migration 或 bootstrap 初始化，不由业务后台编辑。
- 契约必须使用“公共头字段 + 强类型扩展字段”；扩展字段使用 Pydantic 判别联合，包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止在契约中使用 `dict[str, Any]`、`metadata`、`extra_payload`；外层 `header.kind/schema_version` 必须与内层扩展类型一致。
- 响应、日志、审计不得泄漏密码、token、密钥、完整 IP、完整 user-agent 或底层任务 payload 原文。

## 阶段依赖关系

- Phase 1 是业务后台与 ops 控制面的边界基础，Phase 4 依赖 Phase 1。
- Phase 4 负责把任务、配置、安全、系统运行时能力从业务后台彻底移出。
- Phase 5 依赖 Phase 1 至 Phase 4，负责 CORS、migration、分页、测试与文档闭环。
- 本阶段依赖现有 `endpoint_admin_task`、`endpoint_admin_settings`、`endpoint_admin_log`、`endpoint_security_protection`、`endpoint_system_overview`。

## 模拟用法

未来业务重试、补偿、重发必须新增明确业务接口，由后端内部校验状态、权限、幂等后再派发任务，不接收任意任务 payload。

```text
POST /admin/orders/{order_id}/retry-sync
POST /admin/reports/{report_id}/regenerate
POST /admin/messages/{message_id}/resend
```

## 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| BusinessActionRequest | 业务动作请求 | 后续具体业务模块自定义强类型请求，不接收任意 `job_kind` 或任务 payload |
| BusinessActionResultPayload | 业务动作结果 | 返回业务动作是否受理、业务对象状态、幂等键或业务请求 ID |
| OpsOnlyRoutePolicy | ops-only 路由策略 | 平台控制面默认关闭，只能通过单独开关、权限与网络策略访问 |
| SettingsReloadCliCommand | 配置重载 CLI 命令 | 如保留热重载，仅作为内部 CLI 或 ops-only 能力，不进入业务后台 |

## 分步骤执行

### 步骤一：禁用任务运行时入口

- 默认禁用 `/admin/tasks/runtime`、`/admin/tasks/registrations`、`/admin/tasks/dispatch`、`/admin/tasks/executions`。
- 确认业务后台权限常量不再暴露 `task:dispatch`。
- 确认默认 OpenAPI 不出现通用任务派发接口。

### 步骤二：移出配置热重载入口

- 默认禁用 `/admin/settings/reload/candidate` 与 `/admin/settings/reload`。
- 如保留配置重载，新增或保留内部 CLI，不暴露前端页面。
- 确认内部 CLI 或 ops-only 入口不影响业务后台默认启动。

### 步骤三：移出原始日志、安全事件与 IP 封禁能力

- 默认禁用 `/admin/logs` 与 `/admin/security-events`。
- 默认禁用 `/security/ip-blocks*` 作为业务后台能力。
- 确认业务后台无法通过角色分配获得安全管理能力。

### 步骤四：移出系统运行时详情

- 默认禁用系统运行时详情页面能力。
- 只保留必要健康检查给部署或探针使用。
- 确认 `system_overview` 不进入业务后台默认模块。

### 步骤五：收敛业务身份授权面

- 默认禁用任意 scope CRUD，不挂载 `/admin/scopes*`。
- 默认禁用任意角色详情、角色写入和角色 scope 组合编辑，不挂载 `/admin/roles/{role_key}` 与 `/admin/roles/{role_key}/scopes`。
- 业务后台角色列表只暴露预定义业务角色，不返回后端 scope 组合。
- 用户角色分配只能选择预定义业务角色，不能通过角色分配获得 `task:dispatch`、`security:manage` 或系统运行时能力。

### 步骤六：写清未来 ops-only 与业务动作模式

- 为未来 `/ops/*` 写清默认关闭、独立权限、独立网络入口原则。
- 本轮不把 ops 当业务后台交付。
- 后续业务动作接口必须是明确业务接口，由后端内部校验状态、权限、幂等后再派发任务。

## 校验与验收点

- 默认配置启动后，业务后台模块清单只包含业务后台允许能力。
- 默认 OpenAPI 不出现通用任务派发和配置热重载接口。
- 默认 OpenAPI 不出现 `/admin/tasks/*`、`/admin/settings/reload*`、`/admin/logs`、`/admin/security-events`、`/security/ip-blocks*`、业务后台系统运行时详情。
- 业务后台无法通过角色分配获得 `task:dispatch` 或安全管理能力。
- 业务后台不挂载任意 scope CRUD、角色详情、角色写入和角色 scope 组合编辑；角色列表不返回后端 scope 组合。
- 内部 CLI 或 ops-only 入口不影响业务后台默认启动。
- 后续业务动作接口示例不接收任意任务 payload。
- 平台控制面默认关闭，只能通过单独开关、权限与网络策略访问。
