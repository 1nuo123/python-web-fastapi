## 全局约束

- 若文档、图谱、源码冲突，以当前源码为准；`docs/2026_5_26_1849_admin_server_execution_plan.md` 与 `docs/2026_5_27_1330_管理员身份CRUD执行方案.md` 的后台暴露范围已可能过期，回归时必须同步修正。
- 遵守 `docs/standard` 下编码、命名、测试规范；Python 使用 3.11+ 现代类型标注。
- 本轮优先改上游 API、模块清单、配置、应用用例与测试；除业务审计可能需要审计总线或查询适配外，不主动改动基建层核心代码。
- `/admin/*` 只表示业务管理后台；平台、运维、安全控制面后续如保留，必须迁移到默认关闭的 `/ops/*` 或 CLI。
- 默认 `config/app_base.toml` 不启用 `admin_task`、`admin_settings`、`admin_log`、`security_protection`、`system_overview` 作为业务后台模块。
- 通用任务派发、配置热重载、任意 scope CRUD、任意角色权限组合编辑、原始日志、安全事件、指标、IP 封禁、运行时资源不得暴露给业务管理员。
- 业务管理员只允许分配预定义业务角色；角色到后端 scope 的绑定由代码、seed、migration 或 bootstrap 初始化，不由业务后台编辑。
- 用户删除语义统一为停用用户并撤销会话，不做物理删除；接口、响应、文档不得再表达为物理删除。
- 所有 list API 必须具备分页契约，过滤、排序、分页下推 SQL；禁止只在内存中过滤后截断。
- P0 仍需补齐运行基础：CORS 运行时配置、生产一次性 migration job、分页契约。
- 契约必须使用“公共头字段 + 强类型扩展字段”：扩展字段使用 Pydantic 判别联合，扩展字段必须包含 `kind`、`schema_version`，必须启用 `extra="forbid"`。
- 禁止在契约中使用 `dict[str, Any]`、`metadata`、`extra_payload`；外层 `header.kind/schema_version` 必须与内层扩展类型一致。
- 日志、异常、注释和文档使用中文；响应、日志、审计不得泄漏密码、token、密钥、完整 IP、完整 user-agent 或底层任务 payload 原文。

## 阶段依赖关系

- Phase 1 是业务后台与 ops 控制面的边界基础，后续阶段均依赖它。
- Phase 2 依赖 Phase 1，并依赖现有 `admin_identity` 用户、角色、scope 数据模型。
- Phase 3 依赖 Phase 1 和 Phase 2，并依赖现有安全事件、日志或新增业务审计总线的最终选择。
- Phase 4 依赖 Phase 1，负责把任务、配置、安全、系统运行时能力从业务后台彻底移出。
- Phase 5 依赖 Phase 1 至 Phase 4，负责 CORS、migration、分页、测试与文档闭环。

## 阶段目标

收敛身份模块为业务用户管理与预定义业务角色分配。完成后，业务管理员无法创建 scope、编辑角色 scope、创建任意角色或删除角色。

依赖 Phase 1；依赖现有 `endpoint_admin_identity`、`AdminIdentityPort`、`AdminIdentityRepositoryImpl`、bootstrap admin 同步与角色/scope 表。

## 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| AdminBusinessRolePayload | 业务角色载荷 | 返回预定义业务角色 `role_key`、`role_name`，不返回无数据来源的 `description` 或技术 scope 编辑入口 |
| AdminBusinessRoleListPayload | 业务角色列表载荷 | 用户分配角色时使用的只读角色列表，带分页 |
| AdminUserPayload | 管理员用户载荷 | 返回 `subject_id`、`username`、`is_active`、`role_keys`，不暴露密码与技术 scope |
| AdminUserDisableRequest | 用户停用请求 | 强类型请求，表达停用原因，替代 `DELETE` 物理删除语义 |
| AdminUserEnableRequest | 用户启用请求 | 强类型请求，恢复被停用用户 |
| AdminUserRoleReplaceRequest | 用户业务角色替换请求 | 只能传预定义业务角色键，后端拒绝 ops-only 或技术角色 |
| PageQuery | 分页查询 | `page_size`、`cursor` 或 `offset`、排序字段，禁止内存截断 |
| PageResultHeader | 分页响应头 | 返回 `next_cursor`、`total` 可选值、`page_size` 等分页信息 |

## 分步骤执行

### 步骤 1：解绑 scope 写接口

从业务后台解绑 `POST/PATCH/DELETE /admin/scopes*`。

校验点：默认 OpenAPI 不包含 scope 写接口。

### 步骤 2：解绑 role 写接口与角色 scope 绑定接口

从业务后台解绑 `POST/PATCH/DELETE /admin/roles*` 与 `POST /admin/roles/{role_key}/scopes`。

校验点：默认 OpenAPI 不包含 role 写接口。

### 步骤 3：保留只读业务角色列表

保留 `GET /admin/roles` 只读业务角色列表。

校验点：`GET /admin/roles` 返回业务角色，不返回底层 scope 组合编辑字段。

### 步骤 4：限制用户角色分配范围

用户角色分配只允许预定义业务角色，拒绝 `admin`、`task_manager`、`security_manager` 等技术角色进入业务后台选择集。

校验点：给用户分配非业务角色返回 422 或业务错误码。

### 步骤 5：统一用户删除为停用语义

将当前 `DELETE /admin/users/{subject_id}` 收敛为停用语义；优先新增显式 `/disable`、`/enable`，并兼容旧接口时明确响应为 `disabled`。

校验点：停用用户后登录失败，历史审计引用不丢失。

### 步骤 6：补齐用户状态变更审计与会话撤销

用户停用、启用、密码重置、角色替换后写业务审计事件并撤销必要会话。

校验点：停用用户后登录失败，历史审计引用不丢失。

### 步骤 7：补齐列表分页契约与 SQL 下推

列表查询补分页契约，过滤、排序、分页下推到仓储 SQL。

校验点：用户列表分页结果稳定，分页发生在 SQL 查询层。

### 步骤 8：收敛身份契约联合成员

更新 `contract_admin_identity.py`，移除业务后台不再使用的 scope/role 写请求联合成员。

校验点：契约符合公共头字段 + 强类型扩展字段要求，未知字段拒绝，`kind/schema_version` 一致。
