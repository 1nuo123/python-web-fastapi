# Phase 1 业务后台模块边界收口分步骤执行方案

## 阶段目标

收口业务后台模块边界。完成后，默认业务后台不再装配平台、运维、安全、任务运行时和原始日志模块。

`/admin/*` 只表示业务管理后台；平台、运维、安全控制面后续如保留，必须迁移到默认关闭的 `/ops/*` 或 CLI。

## 全局约束

- 若文档、图谱、源码冲突，以当前源码为准；`docs/2026_5_26_1849_admin_server_execution_plan.md` 与 `docs/2026_5_27_1330_管理员身份CRUD执行方案.md` 的后台暴露范围已可能过期，回归时必须同步修正。
- 遵守 `docs/standard` 下编码、命名、测试规范；Python 使用 3.11+ 现代类型标注。
- 本轮优先改上游 API、模块清单、配置、应用用例与测试；除业务审计可能需要审计总线或查询适配外，不主动改动基建层核心代码。
- 默认 `config/app_base.toml` 不启用 `admin_task`、`admin_settings`、`admin_log`、`security_protection`、`system_overview` 作为业务后台模块。
- 通用任务派发、配置热重载、任意 scope CRUD、任意角色权限组合编辑、原始日志、安全事件、指标、IP 封禁、运行时资源不得暴露给业务管理员。
- 业务管理员只允许分配预定义业务角色；角色到后端 scope 的绑定由代码、seed、migration 或 bootstrap 初始化，不由业务后台编辑。
- 用户删除语义统一为停用用户并撤销会话，不做物理删除；接口、响应、文档不得再表达为物理删除。
- 所有 list API 必须具备分页契约，过滤、排序、分页下推 SQL；禁止只在内存中过滤后截断。
- P0 仍需补齐运行基础：CORS 运行时配置、生产一次性 migration job、分页契约。
- 契约必须使用“公共头字段 + 强类型扩展字段”：扩展字段使用 Pydantic 判别联合，扩展字段必须包含 `kind`、`schema_version`，必须启用 `extra="forbid"`。
- 禁止在契约中使用 `dict[str, Any]`、`metadata`、`extra_payload`；外层 `header.kind/schema_version` 必须与内层扩展类型一致。
- 日志、异常、注释和文档使用中文；响应、日志、审计不得泄漏密码、token、密钥、完整 IP、完整 user-agent 或底层任务 payload 原文。

## 阶段依赖关系

- Phase 1 是业务后台与 ops 控制面的边界基础，后续阶段均依赖它。
- Phase 2 依赖 Phase 1，并依赖现有 `admin_identity` 用户、角色、scope 数据模型。
- Phase 3 依赖 Phase 1 和 Phase 2，并依赖现有安全事件、日志或新增业务审计总线的最终选择。
- Phase 4 依赖 Phase 1，负责把任务、配置、安全、系统运行时能力从业务后台彻底移出。
- Phase 5 依赖 Phase 1 至 Phase 4，负责 CORS、migration、分页、测试与文档闭环。

## Phase 1 直接依赖

依赖当前 `WebModuleManifestRegistry`、`ApplicationModuleName`、`config/app_base.toml`、`WebBundleCatalog`、`FastApiAppAssembler`。

## 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| BusinessAdminModuleSet | 业务后台模块集合 | 默认可进入 `/admin/*` 的业务模块集合，只包含 `admin_identity`、`admin_audit` 与后续业务模块 |
| OpsOnlyModuleSet | 运维控制面模块集合 | `admin_task`、`admin_settings`、`admin_log`、`security_protection`、`system_overview` 等默认关闭模块 |
| WebModuleManifestEnvelope | Web 模块清单信封 | 沿用公共头 + 强类型扩展字段，`header.kind/schema_version` 与 `detail` 一致 |
| AdminBoundaryPolicy | 后台边界策略 | 约束模块是否允许进入业务后台、是否仅允许 ops-only 或 CLI |

## 分步骤执行

### 步骤 1：收口模块清单

修改 `src/api/web_module_manifest.py`，区分业务后台模块与 ops-only 模块。默认可进入 `/admin/*` 的业务模块集合只包含 `admin_identity`、`admin_audit` 与后续业务模块。

保留 `admin_task`、`admin_settings`、`admin_log`、`security_protection`、`system_overview` 等平台模块代码，但取消默认业务后台装配，避免误删影响后续 ops 迁移。

### 步骤 2：收紧默认配置

修改 `config/app_base.toml`，默认只启用业务后台允许模块。

默认 `app.modules.enabled` 不包含 `admin_task`、`admin_settings`、`admin_log`、`security_protection`、`system_overview`。

### 步骤 3：确认系统概览不再默认暴露

确认 `system_overview` 不再作为业务后台模块默认暴露。系统运行时详情、指标、运行时资源不得暴露给业务管理员。

### 步骤 4：收敛业务后台权限入口

修改 `src/api/admin_route_authorization.py`，业务后台权限不再引用 `task:dispatch`、`system:read` 作为业务页面入口权限。

业务后台不得通过角色分配获得通用任务派发、安全管理或系统运行时能力。

### 步骤 5：固定 OpenAPI 默认暴露面

更新 OpenAPI surface 测试，固定默认业务后台路径集合。

默认 OpenAPI 不出现平台控制面路径，包括 `/admin/tasks/*`、`/admin/settings/reload*`、`/admin/logs`、`/admin/security-events`、`/security/ip-blocks*`、业务后台系统运行时详情。

### 步骤 6：保留旧模块独立可测

禁用模块不被 FastAPI route composer 挂载，但旧模块代码仍可被单独测试，不因默认禁用被破坏。

## 校验与验收点

- 默认配置启动后，业务后台模块清单只包含业务后台允许能力。
- 默认 `app.modules.enabled` 不包含 `admin_task`、`admin_settings`、`admin_log`、`security_protection`、`system_overview`。
- 默认 OpenAPI 不出现平台控制面路径。
- 默认 OpenAPI 出现 `/admin/audit-events` 业务审计路径。
- 禁用模块不被 FastAPI route composer 挂载。
- 旧模块代码仍可被单独测试，不因默认禁用被破坏。
- `/admin/users*` 保留用户列表、详情、创建、更新、停用、启用、重置密码、分配预定义业务角色。
- `GET /admin/roles` 保留为只读业务角色列表，且不暴露技术 scope 组合编辑能力。
- 文档回归明确旧管理员服务端方案中的平台控制面暴露范围已过期。
