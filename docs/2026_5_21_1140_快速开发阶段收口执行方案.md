# 快速开发阶段收口执行方案

## 任务目标
- 交付一套可进入后续快速开发阶段的代码底座：热更新无半生效、测试可一键执行、任务 `payload_model` 强类型生效、核心热点完成首轮拆分。
- 完成判定：源码、测试、文档三者一致；若文档与源码冲突，已按“源码为准”完成文档回归说明。

## 全局约束
- 编码遵循 `docs/standard`。
- 若文档、图谱、源码冲突，以源码为准，并在文档回归中标注旧文档可能过期。
- 不允许以放宽断言、跳过测试、保留死代码替代真实修复。
- 新增或修改契约统一采用“公共头字段 + 强类型扩展字段”：
  - 外层结构固定为 `header + detail`
  - `detail` 必须使用 Pydantic 判别联合
  - 每个扩展模型必须包含 `kind`、`schema_version`
  - 每个扩展模型必须 `extra="forbid"`
  - 禁止 `dict[str, Any]`、`metadata`、`extra_payload`
  - 外层类型与内层扩展类型必须一致
- 保持现有统一错误码、统一日志结构、统一响应外壳不变。
- 不新增新的中心化超大文件；拆分后入口文件只负责装配与转发。
- 测试必须覆盖单测、路径/边界回归、至少一条真实集成链路。

## 验收标准
- 热更新失败后，配置快照、HTTP 资源、请求执行桥、任务注册状态保持同一成功版本，无半生效状态。
- `uv run python -m pytest` 可稳定收集测试，无 `ModuleNotFoundError: src`。
- 本地任务与 Funboost 任务在分发/消费前都按 `payload_model` 完成真实校验，禁止 `BaseModel` 占位注册。
- `TaskRegistrationRegistry` 无重复方法与静默覆盖死代码。
- `SharedResourceMount`、`AppSettingsLoader` 完成首轮职责拆分，新增功能不再继续堆入单文件。
- 设计文档、测试规范、执行方案文档与源码行为一致。

## 生命周期
执行修改 -> 新增或修改测试 -> 真实测试 -> 回归修复 -> 文档回归

## Phase 1
### 目标
- 修复热更新“先改现态、后重建资源”的半生效风险。
- 收口测试入口，使本地与 CI 都能一键收集并执行测试。

### 依赖
- 前置文件：`src/infrastructure/shared_resource_mount.py`、`src/infrastructure/settings/settings_reload_coordinator.py`、`pyproject.toml`
- 前置环境：本地 `uv` 可用，测试依赖已安装

### 模拟用法
```python
result = app.state.container.reload_coordinator.reload_from_mapping(
    environment=AppEnvironment.TEST,
    overrides={"runtime": {"web": {"max_request_body_bytes": 2048}}},
)
assert result.success in {True, False}
```

### 契约
| 英文名                           | 中文名            | 中文说明                                                     |
| -------------------------------- | ----------------- | ------------------------------------------------------------ |
| `SettingsApplyOperationHeader`   | 配置应用公共头    | 描述操作名、目标资源、候选版本，禁止裸字符串驱动切换流程     |
| `HttpResourceSwitchDetail`       | HTTP 资源切换扩展 | `kind/schema_version/extra="forbid"`，描述候选构建、切换、回滚策略 |
| `TaskRegistryReloadDetail`       | 任务注册切换扩展  | `kind/schema_version/extra="forbid"`，描述注册替换与恢复策略 |
| `SettingsApplyOperationEnvelope` | 配置应用操作信封  | 外层 `header + detail`，`detail` 使用 Pydantic 判别联合      |
| `SettingsApplyResultPayload`     | 配置应用结果载荷  | 返回 `success`、`rolled_back`、`active_snapshot_id`、`restored_resources` |

### 任务清单
- [ ] 新增热更新事务契约与原子切换执行器，先构建候选资源，再执行引用切换
- [ ] 重写 `SharedResourceMount.apply_settings`，禁止“先覆盖 current_settings 再销毁旧资源”
- [ ] 调整 `SettingsReloadCoordinator`，仅在资源切换成功后推进快照
- [ ] 为失败回滚补齐旧资源恢复逻辑，至少覆盖 HTTP client、async client、request bridge、task registry
- [ ] 在 `pyproject.toml` 收口 pytest 入口、`pythonpath`、`testpaths`
- [ ] 在 `test/conftest.py` 明确测试环境装配，消除 `src` 导入漂移

### 关键代码片段
```python
class SettingsApplyOperationEnvelope(BaseModel):
    header: SettingsApplyOperationHeader
    detail: HttpResourceSwitchDetail | TaskRegistryReloadDetail = Field(
        discriminator="kind"
    )
```

### 校验
- 热更新成功时，新配置与新资源同时生效。
- 热更新失败时，旧配置与旧资源同时保留。
- `uv run python -m pytest -q test/unit_test test/path_test -x` 可正常收集。

## Phase 2
### 目标
- 让 `payload_model` 从“占位字段”变成真实运行时约束。
- 清理任务注册与装配链中的死代码、重复定义与弱校验。

### 依赖
- 依赖 Phase 1 的稳定测试入口
- 前置文件：`src/infrastructure/task/*.py`、`src/core/task_contract/task_registration_contract.py`

### 模拟用法
```python
resource_mount.register_task_binding(
    RegisteredTaskBinding(
        job_kind="demo_task",
        payload_model=DemoTaskPayload,
        handler=DemoTaskHandler(),
    )
)
```

### 契约
| 英文名                           | 中文名                | 中文说明                                                     |
| -------------------------------- | --------------------- | ------------------------------------------------------------ |
| `TaskRegistrationHeader`         | 任务注册公共头        | 保留现有 `job_kind/backend/enabled` 主语义，继续作为任务注册唯一入口 |
| `LocalTaskRegistrationDetail`    | 本地任务注册扩展      | `kind/schema_version/extra="forbid"`，定义本地重试与执行约束 |
| `FunboostTaskRegistrationDetail` | Funboost 任务注册扩展 | `kind/schema_version/extra="forbid"`，定义队列、路由、消费约束 |
| `RegisteredTaskBinding`          | 已注册任务绑定        | `payload_model` 必须是具体 Pydantic 模型类，禁止 `BaseModel` 占位 |
| `TaskMessageEnvelope`            | 任务消息信封          | `payload_kind` 必须与 `payload_model` 对应，分发前先做 `model_validate_json` |

### 任务清单
- [ ] 修改 `register_task_handler` / `register_handler`，不再默认注入 `BaseModel`
- [ ] 让 `LocalTaskDispatcher` 在执行处理器前按 `payload_model` 解析消息载荷
- [ ] 让 `FunboostTaskBootstrapper` 在消费侧执行同样的强类型校验
- [ ] 在注册阶段拒绝无效 `payload_model`、重复 `job_kind`、缺失注册项绑定
- [ ] 删除 `TaskRegistrationRegistry` 中重复的 `build_bootstrap_snapshot`
- [ ] 保持现有 `TaskRegistrationEnvelope + detail 判别联合` 规则，不引入 `dict[str, Any]` 扩展字段

### 关键代码片段
```python
payload_model = resolved_binding.binding.payload_model
payload_model.model_validate_json(message.payload.payload_json)
resolved_binding.binding.handler.handle(message)
```

### 校验
- `BaseModel` 占位注册必须失败。
- 非法 payload 在本地分发与 Funboost 消费侧都必须早失败。
- `test/unit_test/test_task_registration_registry_unit.py` 全绿。

## Phase 3
### 目标
- 对 `SharedResourceMount` 与 `AppSettingsLoader` 做首轮职责拆分。
- 降低 Web 模块接入与依赖访问的中心化程度，减少后续并行开发冲突。

### 依赖
- 依赖 Phase 1 的原子切换能力
- 依赖 Phase 2 的任务契约稳定行为

### 契约
| 英文名                         | 中文名             | 中文说明                                                 |
| ------------------------------ | ------------------ | -------------------------------------------------------- |
| `SettingsSectionHeader`        | 配置节公共头       | 描述配置节名称、来源、版本，用于替代单大文件内联分支     |
| `ModuleSettingsSectionDetail`  | 模块配置节扩展     | `kind/schema_version/extra="forbid"`，负责模块区段解析   |
| `RuntimeSettingsSectionDetail` | 运行时配置节扩展   | `kind/schema_version/extra="forbid"`，负责运行时区段解析 |
| `SettingsSectionEnvelope`      | 配置节信封         | 外层 `header + detail`，`detail` 使用 Pydantic 判别联合  |
| `WebBundleProviderEnvelope`    | Web 模块提供者信封 | 外层 `header + detail`，用于去中心化装配路由提供者       |

### 任务清单
- [ ] 从 `SharedResourceMount` 抽离 HTTP 资源管理、任务运行时管理、鉴权/日志访问器
- [ ] 让 `FastApiAppAssembler` 面向拆分后的 manager/provider 装配，而不是继续直接堆字段
- [ ] 将 `AppSettingsLoader` 拆为根入口 + 模块/运行时分节解析器，保留对外加载 API
- [ ] 改造 `WebBundleCatalog` 为 provider/registry 形式，降低手工集中登记成本
- [ ] 收缩 `DependencyContextAccessor`，仅保留路由直接需要的依赖读取接口
- [ ] 保证对外接口、现有路由路径、错误码与响应结构不变

### 校验
- 新增 Web 模块时，不再必须修改多处中心化清单。
- `SharedResourceMount` 与 `AppSettingsLoader` 不再继续增长为单点热点。
- 现有路由与配置加载行为回归通过。
