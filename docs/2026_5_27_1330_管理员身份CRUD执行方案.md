# 管理员身份 CRUD 执行方案

## 边界回归说明

本方案中的全量身份 CRUD 后台暴露范围已被
`docs/2026_5_28_1055_业务管理后台边界整改执行方案.md`
收敛。当前业务后台保留 `/admin/users*` 用户管理、`GET /admin/roles`
只读预定义业务角色列表和 `/admin/users/{subject_id}/roles` 业务角色分配；
`/admin/scopes*` 写接口、`/admin/roles*` 写接口和
`/admin/roles/{role_key}/scopes` 不再进入默认业务后台。

角色到后端 scope 的绑定由代码、seed、migration 或 bootstrap 初始化维护，
业务管理员只能分配预定义业务角色；用户删除语义统一为停用并撤销会话。

## 任务目标

交付管理员端用户 CRUD、角色 CRUD、权限/scope CRUD 服务端能力，不实现前端页面。

完成判定：前端可基于新增 `/admin/users*`、`/admin/roles*`、`/admin/scopes*` 完成用户、角色、权限管理页面；后端具备契约、鉴权、事务、审计、安全保护、测试与文档回归。

## 全局约束

- 若文档、图谱、源码冲突，以当前源码为准；现有文档可能过期，回归时必须同步修正。
- 本方案按现有用户表、角色表、权限/scope 表均存在处理；执行时仍需以 ORM、迁移和真实数据库结构为准核验字段。
- 管理员身份管理独立为 `admin_identity` Web 模块，不混入登录、令牌、任务、日志等既有模块主流程。
- 应用层按目录收敛：`application/admin/identity/user/`、`application/admin/identity/role/`、`application/admin/identity/scope/`。
- HTTP 层统一放入 `src/api/endpoint_admin_identity/`，路由统一使用 `/admin/*`。
- 查询接口要求 `admin + auth:read`；新增、修改、删除接口要求 `admin + auth:manage`。
- 新增 `auth:manage` 作为封闭权限枚举值，并补充 bootstrap admin 默认授权。
- scope CRUD 只管理权限目录与角色绑定，不引入动态策略引擎；后端路由权限仍由代码显式声明。
- 内置 scope 不允许删除，不允许修改 `scope_code`；内置 `admin` 角色不允许删除。
- 用户删除采用停用并撤销会话，不做物理删除，避免破坏日志、任务记录、安全事件引用。
- 禁止操作者移除自己的最后一个 `admin + auth:manage` 能力。
- 密码只允许作为入参出现，不允许出现在响应、日志、异常详情或测试快照中。
- 所有写操作必须走 UoW 事务；Repository 不得自行 `commit()`、`rollback()`、`dispose()`。
- 契约统一使用“公共头字段 + 强类型扩展字段”模式：扩展字段使用 Pydantic 判别联合，包含 `kind`、`schema_version`，启用 `extra="forbid"`；禁止 `dict[str, Any]`、`metadata`、`extra_payload`；外层类型与内层扩展类型必须一致。
- 日志、异常、注释使用中文；业务代码沿用现有日志方案。

## 验收标准

- `/admin/users*` 支持列表、详情、创建、更新、停用、启用、重置密码、替换角色。
- `/admin/roles*` 支持列表、详情、创建、更新、删除、替换 scope。
- `/admin/scopes*` 支持列表、详情、创建、更新、删除，并保护内置 scope。
- 所有新增接口具备响应契约、权限校验、错误处理、接口测试、契约测试。
- `auth:manage` 已纳入 `AuthScopeCode`、bootstrap admin 和管理员授权常量。
- 用户角色变更、密码重置、用户停用后，该用户既有刷新令牌会话被撤销。
- 管理员身份变更写入结构化审计日志或安全事件，且不暴露敏感原文。
- Docker Compose 项目环境下定向测试与 `uv run pytest` 完整回归通过。
- 文档、契约、测试说明与最终源码一致。

### 依赖

### 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| AdminIdentityModuleName | 管理员身份模块名 | 新增 `admin_identity` Web 模块标识，用于 manifest 与 `app.modules.enabled` 校验 |
| AuthManageScopeCode | 鉴权管理权限 | 新增 `auth:manage`，用于用户、角色、scope 写操作授权 |

### 关键代码片段

```python
class AdminIdentityEnvelope(BaseModel):
    model_config = ConfigDict(extra="forbid")

    header: AdminIdentityHeader
    detail: AdminIdentityDetailUnion

    @model_validator(mode="after")
    def validate_detail_contract(self) -> "AdminIdentityEnvelope":
        if self.header.kind != self.detail.kind:
            raise ValueError("管理员身份 header.kind 必须与 detail.kind 一致。")
        if self.header.schema_version != self.detail.schema_version:
            raise ValueError("管理员身份 schema_version 必须一致。")
        return self
```

### 校验

- `WebBundleCatalog.validate_enabled_modules()` 能识别 `admin_identity`。
- 未启用 `admin_identity` 时不装配 `/admin/users*`、`/admin/roles*`、`/admin/scopes*`。
- 读取接口缺少 token 返回 401。
- 写接口缺少 `auth:manage` 返回 403。

### 权限说明

管理员身份查询接口统一要求 `admin + auth:read`；用户、角色、scope 的创建、更新、删除、密码重置和绑定替换统一要求 `admin + auth:manage`。`auth:manage` 已纳入 `AuthScopeCode`、管理员授权常量和测试/开发 bootstrap admin 默认角色绑定。

### 安全说明

密码只作为创建用户和重置密码请求入参进入系统，响应、异常详情、安全事件和测试断言均不暴露密码原文或密码哈希。内置 scope 和内置 `admin` 角色受删除保护；用户停用、密码重置、用户角色变更会撤销该用户既有刷新令牌会话；操作者不能移除自己的最后一个 `admin + auth:manage` 能力。

### 配置与实现回归说明

最终源码以独立 `auth_scope` 表承载权限目录，因此新增 `AuthScopeOrmModel` 和 `202605271330_create_auth_scope_catalog.py` 迁移，并在 bootstrap admin 同步时维护内置 scope 目录。该实现替代了方案中“权限/scope 表已存在”的前置假设，与当前数据库结构保持一致。
