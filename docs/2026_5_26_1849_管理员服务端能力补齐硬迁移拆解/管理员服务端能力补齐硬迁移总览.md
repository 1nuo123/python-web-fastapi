# 管理员服务端能力补齐硬迁移总览

## 原始文档

`docs/2026_5_26_1849_admin_server_execution_plan.md`

## 任务概览

交付管理员后台所需的服务端能力，不实现前端页面。完成后，前端可基于现有 `/auth/*`、`/system/info`、`/health/*`、`/security/ip-blocks*` 以及新增 `/admin/*` 接口开发管理员页面。

完成判定：管理员服务端具备任务记录查询、任务运行时查看、任务注册查看、手动任务派发、配置热更新、日志与安全事件查询能力；接口完成装配、鉴权、契约、测试和文档回归。

本拆解为硬迁移方案：目标是一次性将管理员服务端模块重构至最佳实践状态，不采用渐进式迁移设计。

## 基本约束

- 若文档、图谱、源码冲突，以源码为准；现有文档可能过期，回归时必须同步修正。
- 只做服务端能力，不新增任何前端目录、页面、样式、脚本。
- 遵守 `docs/standard` 下编码、命名、测试规范；Python 使用 3.11+ 现代类型标注。
- 管理员能力独立分层：HTTP 层使用 `endpoint_admin_*`，应用层使用 `application/admin`，查询端口放入 `application/ports`，不得把管理员编排逻辑混入业务用例或基础设施实现。
- 已有接口继续复用：`/auth/token`、`/auth/refresh`、`/auth/revoke`、`/auth/me`、`/system/info`、`/health/live`、`/health/ready`、`/security/ip-blocks*`。
- 新增 HTTP 路由统一放在 `/admin/*`，并通过 `WebModuleManifestRegistry` 与 `app.modules.enabled` 装配。
- 权限以后端校验为准；本轮不新增 scope，沿用现有 `admin`、`auth:read`、`system:read`、`security:manage`、`task:dispatch`。
- 管理员账号来自 bootstrap admin 同步；本轮不做用户 CRUD、角色 CRUD、scope CRUD。
- Prometheus `/metrics` 默认关闭，不作为管理员核心接口；非生产 OpenAPI `/docs` 只作为开发辅助入口。
- 契约必须使用“公共头字段 + 强类型扩展字段”：扩展字段使用 Pydantic 判别联合，必须包含 `kind`、`schema_version`，必须启用 `extra="forbid"`；禁止 `dict[str, Any]`、`metadata`、`extra_payload`；外层类型与内层扩展类型必须一致。
- 管理员手动任务派发只允许已注册、已启用、已绑定 handler 的任务；请求体中的业务 payload 以 `payload_json: str` 承载，并由后端按注册的 Pydantic payload model 校验。
- 默认配置不得启用需要业务 handler 的任务；当前 `demo_task` 注册项保持 `enabled=false`，测试如需派发任务必须显式注入测试 handler。
- 日志与安全事件查询必须脱敏，不暴露 refresh token、密码、密钥、完整客户端 IP、完整 user-agent 等敏感值。

## 验收标准

- 现有鉴权、系统、健康、安全 IP 封禁接口可作为管理员页面后端能力复用。
- `/admin/tasks/*` 支持任务记录列表/详情、运行时信息、注册信息、手动派发。
- `/admin/settings/reload/*` 支持候选版本读取和热更新执行，结果包含成功、回滚、原因、恢复资源、当前快照。
- `/admin/logs` 与 `/admin/security-events` 支持受控查询，返回脱敏后的结构化结果。
- 所有新增接口具备响应契约、权限校验、错误处理、接口测试、契约测试。
- `create_app + lifespan + GET /health/live` smoke test 通过。
- `uv run pytest` 完整回归存在通过记录。
- 文档、契约、测试说明已按真实源码与真实测试结果同步。

## 文档回归说明

### 管理员服务端接口清单

已有复用接口：`/auth/token`、`/auth/refresh`、`/auth/revoke`、`/auth/me`、`/system/info`、`/health/live`、`/health/ready`、`/security/ip-blocks*`。

本轮新增接口：`GET /admin/tasks/executions`、`GET /admin/tasks/executions/{task_id}`、`GET /admin/tasks/runtime`、`GET /admin/tasks/registrations`、`POST /admin/tasks/dispatch`、`GET /admin/settings/reload/candidate`、`POST /admin/settings/reload`、`GET /admin/logs`、`GET /admin/security-events`。

后续管理员身份接口：`GET /admin/scopes`、`GET /admin/scopes/{scope_code}`、`POST /admin/scopes`、`PATCH /admin/scopes/{scope_code}`、`DELETE /admin/scopes/{scope_code}`、`GET /admin/roles`、`GET /admin/roles/{role_key}`、`POST /admin/roles`、`PATCH /admin/roles/{role_key}`、`POST /admin/roles/{role_key}/scopes`、`DELETE /admin/roles/{role_key}`、`GET /admin/users`、`GET /admin/users/{subject_id}`、`POST /admin/users`、`PATCH /admin/users/{subject_id}`、`POST /admin/users/{subject_id}/password`、`POST /admin/users/{subject_id}/roles`、`DELETE /admin/users/{subject_id}`。

### 配置说明

默认配置已启用 `admin_task`、`admin_settings`、`admin_log` 与 `admin_identity` Web 模块；默认 `demo_task` 与 `demo_task_funboost` 注册项保持 `enabled=false`。业务环境启用任务派发前，必须同时声明任务注册项并显式提供 handler 绑定。测试与开发 bootstrap admin 默认角色绑定包含 `auth:manage`，用于管理员身份写接口。

### 安全说明

管理员查询类接口统一要求 `admin + system:read`，任务派发接口要求 `admin + task:dispatch`。管理员身份查询接口要求 `admin + auth:read`，用户、角色和 scope 写接口要求 `admin + auth:manage`。2026-05-27 回归复验确认，`/admin/logs` 与 `/admin/security-events` 在缺少 `admin` 但具备 `system:read` 时返回 403。日志接口不返回原始 `detail_json`，写入构造器路径与查询侧历史强类型详情都会执行脱敏。安全事件只暴露摘要、决策、类型和 digest 字段；管理员身份写操作会记录安全事件，不暴露密码原文和密码哈希。

### 测试说明

已新增管理员契约、单元、接口与冒烟集成测试。2026-05-27 在 Docker Compose 项目环境中完成回归复验：`python -m compileall src test -q` 通过；管理员契约、单元、接口、冒烟集成和既有关联接口定向测试均通过；管理员身份 CRUD 回归后，单次完整执行 `uv run pytest -q` 结果为 `482 passed, 71 warnings`。

### 实现回归说明

为遵守应用层边界，配置热更新用例通过 `AdminSettingsReloadPort` 访问热更新能力，由 `AdminSettingsReloadAdapter` 在基础设施层适配 `SettingsReloadCoordinator`。另修复请求执行桥接器在热更新过程中关闭当前线程池时可能触发的自 join 问题。
