# 管理员服务端边界与模块装配分步骤执行方案

## 阶段目标

建立管理员服务端隔离边界与模块装配基础。完成后，新增管理员 HTTP provider 可以被 manifest 发现，并按配置装配到 FastAPI。

## 阶段依赖

依赖现有 `WebBundleCatalog`、`WebModuleManifestRegistry`、`FastApiAppAssembler`、`DependencyContextAccessor`、`AuthorizationGuard`、`ResponseEnvelope`。

## 契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| AdminTaskModuleName | 管理员任务模块名 | 新增管理员任务 HTTP 模块标识，用于 manifest 与 `app.modules.enabled` 校验 |
| AdminSettingsModuleName | 管理员配置模块名 | 新增管理员配置热更新 HTTP 模块标识 |
| AdminLogModuleName | 管理员日志模块名 | 新增管理员日志/安全事件 HTTP 模块标识 |
| AdminRouteAuthorizationRequirement | 管理员路由授权要求 | 复用 `RouteAuthorizationRequirement`，要求 `admin` 角色和对应 scope |
| AdminApplicationUsecaseSet | 管理员应用用例集合 | 由 `FastApiAppAssembler` 注入，避免路由直接拼装基础设施对象 |

## 分步骤执行方案

### 步骤 1：补充管理员模块名

在 `ApplicationModuleName` 增加管理员任务、配置、日志模块名，使管理员服务端模块可以进入统一模块名校验体系。

### 步骤 2：注册管理员 Web provider

在 `web_module_manifest.py` 增加三个管理员 provider import path、route tag 和 manifest entry，使新增管理员 HTTP provider 可以被 manifest 发现。

### 步骤 3：启用管理员服务端模块配置

在 `config/app_base.toml` 的 `app.modules.enabled` 增加管理员服务端模块，使配置可以驱动 FastAPI 装配对应路由。

### 步骤 4：扩展应用容器边界

在 `ApplicationContainer` 增加管理员用例字段，保持管理员应用能力与业务用例隔离。

### 步骤 5：扩展依赖读取入口

在 `DependencyContextAccessor` 增加管理员用例、`reload_coordinator`、`resource_mount` 的显式读取入口，避免路由直接拼装基础设施对象。

### 步骤 6：定义管理员路由授权常量

为管理员路由定义统一授权常量：

- 任务查询：`admin + system:read`
- 任务派发：`admin + task:dispatch`
- 配置热更新：`admin + system:read`
- 日志/安全事件查询：`admin + system:read`

### 步骤 7：确认默认任务配置不依赖业务 handler

确认默认 `demo_task` 注册项保持 `enabled=false`，不依赖业务 handler 启动。

## 校验与验收点

- `WebBundleCatalog.validate_enabled_modules()` 能识别新增管理员模块名。
- 未启用管理员模块时不装配对应路由。
- 启用管理员模块但未登录时返回 401。
- 缺少要求 scope 时返回 403，并写入授权拒绝安全事件。
