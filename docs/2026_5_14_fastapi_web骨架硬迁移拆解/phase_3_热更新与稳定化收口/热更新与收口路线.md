# Phase 3 热更新与稳定化收口

## 阶段目标
完成配置热更新治理、观测性可选接入、资源装配收口和整体工程稳定化。

当前阶段完成后的中间结果：
- 配置快照、预检查、回滚链路可运行。
- OTel 为可选接入，不阻塞默认启动。
- 共享资源、任务执行、异常治理、启动/关闭链路形成完整闭环。

## 依赖关系
- 依赖 Phase 1 的配置加载器与生命周期编排。
- 依赖 Phase 2 的数据库、缓存、消息、任务、鉴权运行时对象。
- 源码现状说明：当前 `src` 仅有包目录与空的 `main.py`，`config` 目录与 Phase 3 对应实现文件尚未落地，因此这里的依赖目前仍停留在骨架预留状态。

## 契约表
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| SettingsSnapshot | 配置快照 | 已验证通过的配置快照，供回滚使用 |
| ReloadCandidatePayload | 热更新候选扩展体 | `kind="reload_candidate"`，承载候选配置版本和摘要 |
| ReloadResultPayload | 热更新结果扩展体 | `kind="reload_result"`，承载是否成功、失败原因、回滚结果 |
| RuntimeResourceState | 运行时资源状态 | 共享资源的启动、就绪、关闭状态契约 |
| TelemetryBridgeState | 观测桥接状态 | OTel 是否启用、是否 no-op 的状态契约 |

## 分步骤执行方案

### 步骤 1：完成配置热更新治理闭环
- 目标：实现配置快照存储、候选配置构造、预检查、原子切换、失败回滚，并明确哪些配置允许热更新、哪些配置必须重启生效。
- 依赖：Phase 1 的配置加载器；Phase 1 的生命周期编排。
- 执行内容：实现配置快照存储、候选配置构造、预检查、原子切换、失败回滚；识别允许热更新的配置项与必须重启生效的配置项。
- 对应验收点：非法候选配置不会污染当前运行配置；高风险配置项变更会被拒绝热更新并给出明确原因。

### 步骤 2：完成共享资源装配与释放顺序编排
- 目标：把共享资源的装配、启动、就绪、释放收口到统一编排链路中。
- 依赖：Phase 2 的数据库、缓存、消息、任务、鉴权运行时对象；Phase 1 的生命周期编排。
- 执行内容：完成共享资源装配与释放顺序的统一编排。
- 对应验收点：资源初始化失败时应用不会进入 ready；共享资源、启动/关闭链路形成完整闭环。

### 步骤 3：完成 OTel 可选桥接与 no-op 兜底
- 目标：让观测性能力可接入但非强依赖，不阻塞默认启动。
- 依赖：Phase 1 的生命周期编排；运行时资源装配链路。
- 执行内容：实现 OTel 可选桥接和 no-op 兜底。
- 对应验收点：OTel 关闭时应用仍可正常启动。

### 步骤 4：补齐异常治理、日志语义与应用状态收口
- 目标：把资源初始化失败、热更新失败、任务失败的统一错误与日志语义补齐，并完成 OpenAPI、启动事件、关闭事件、ready 状态收口。
- 依赖：步骤 1 至步骤 3 的实现结果；Phase 2 的任务运行时对象。
- 执行内容：为资源初始化失败、热更新失败、任务失败补齐统一错误与日志语义；收口 OpenAPI、启动事件、关闭事件和应用 ready 状态。
- 对应验收点：资源初始化失败时应用不会进入 ready；任务执行、异常治理、启动/关闭链路形成完整闭环。
