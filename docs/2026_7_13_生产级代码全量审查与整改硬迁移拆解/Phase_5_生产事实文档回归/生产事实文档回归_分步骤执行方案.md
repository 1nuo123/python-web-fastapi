# 生产事实文档回归：分步骤执行方案

> 2026-07-16 最终复核：项目手册、回归报告、性能报告、DocumentationRecord 和统一索引已同步当前基线与 `fixed=14, verified=12` 的真实 finding 状态；Phase 4 和生产就绪结论保持未完成。

## 一、阶段目标与完成边界

将最终源码、契约、测试和生产运行事实一次性同步到 `docs/project_manual/`，并生成最终生产级审查回归报告，使文档可直接支持后续快速开发、部署、排障和再次审查。Phase 5 是硬迁移收口：同一批次完成全部事实替换、入口切换、交叉链接校验和过期状态标注，不保留渐进迁移、双写、双入口或长期兼容文档。

完成时必须同时满足：

- Phase 4 已完成，P0/P1 与真实测试阻断项清零；最终代码、迁移 head、配置键、OpenAPI、测试计数、覆盖率、镜像和性能报告已冻结。
- 项目手册、API/OpenAPI、配置样例、迁移说明、安全与运维说明、最终回归报告与源码及真实测试结果一致。
- 历史方案仅作背景；与当前源码冲突的内容明确标记 `deprecated` 或 `archived`，并给出当前替代路径。
- 文档内所有路径、类名、配置键、命令、迁移 head、测试计数和结论均有可追溯事实来源；`blocked`、`skip`、`xfail` 不记为通过。
- 不修改阶段拆解之外的需求语义，不以历史文档、日志或 mock 结果替代当前源码和真实执行证据。

## 二、事实优先级、硬迁移约束与依赖

### 2.1 事实优先级

固定按“当前源码与迁移 > 可执行配置与测试 > 当前项目手册 > 历史方案”裁决冲突。`logs/**` 只能作为历史现象参考；生产告警、日志聚合和 Grafana dashboard 若不在代码中固定，只能标注为部署环境决定。

### 2.2 阶段依赖

| 依赖项 | 输入证据 | 阻断条件 |
|---|---|---|
| Phase 4 最终状态 | P0-P3 状态、修复证据、剩余风险 | P0/P1 或真实测试阻断项未清零 |
| 代码与契约冻结 | 源码基线、OpenAPI、公共契约、配置键、迁移 head | 存在未声明的公共行为变化 |
| 真实验证冻结 | 测试计数、覆盖率、扫描结果、镜像摘要、负载与 autotuner 报告 | 结果不可复现或仅有 mock/历史记录 |
| 文档入口现状 | `docs/project_manual/README.md` 及全量索引 | 新旧入口并存且未声明状态 |

Phase 5 完成后必须再执行一次源码、契约、测试、OpenAPI、项目手册五方一致性检查；发现冲突时回退到对应事实责任方修正后重做文档回归，不以改写事实口径掩盖冲突。

### 2.3 硬迁移规则

1. 先冻结证据清单，再在一个文档变更批次内更新全部受影响主题和入口。
2. 不设计渐进迁移、兼容窗口、双版本教程或“新旧均可”的模糊表述；当前入口只指向最终事实。
3. 旧文档仍有审计价值时仅标记 `deprecated/archived` 并指向替代路径；不得继续作为当前操作入口。
4. 不删除原始审查方案；文档回归的实际变更范围仅是项目手册、配置样例、必要的当前说明和新增回归报告。
5. 文档中的代码片段和注释必须从冻结源码逐字提取；不得为简洁而省略、改写关键语义。示例若是教学性伪代码，必须显式标注，不能伪装成当前实现。
6. 所有新增示例遵循 Python 3.11+、现代类型标注、稳定结构强类型建模、明确分层和中文注释；不得引入开放的 `dict[str, Any]` 协议。

## 三、阶段契约

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `DocumentationHeader` | 文档公共头 | 记录文档主题、适用版本、源码基线和最后验证时间。 |
| `DocumentationDetailUnion` | 文档扩展联合 | 以 `kind` 判别 `architecture`、`api`、`configuration`、`migration`、`testing`、`security`、`operations`、`performance`；均含 `schema_version` 并禁止额外字段。 |
| `TruthSource` | 事实来源 | 固定指向源码、迁移、配置、OpenAPI 或真实测试报告；历史文档不能作为唯一完成证据。 |
| `DocumentationStatus` | 文档状态 | 固定为 `current/deprecated/archived`，过期入口必须给出替代路径。 |
| `kind` | 文档类型判别值 | 外层主题声明必须与 `DocumentationDetailUnion` 内层具体类型一致。 |
| `schema_version` | 文档契约版本 | 每种文档扩展类型必须显式给出版本，用于校验当前结构而非维持渐进兼容。 |
| `model_config` | 模型约束 | 公共头、扩展模型和外层对象统一使用 `ConfigDict(extra="forbid")`，拒绝未知字段。 |

文档契约采用“公共头字段 + 强类型扩展字段”，扩展字段使用 Pydantic 判别联合；禁止 `metadata`、`extra_payload`、`dict[str, Any]` 等开放扩展字段。若契约落地为代码或机器可读清单，必须同步 contract 测试，校验判别值、版本、未知字段拒绝、序列化往返和外内类型一致性。

## 五、分步骤执行方案

### 步骤 1：冻结文档回归证据与影响面

代码现状：以 Phase 4 冻结后的工作区为唯一当前代码基线；在源码基线、迁移 head、配置键、OpenAPI、测试和生产验证结果未齐备前，不把项目手册现有表述判定为当前事实。

目标形态：形成一份覆盖 `docs/project_manual/README.md` 全量索引的事实映射，每个文档结论都能追溯到当前源码、迁移、配置、OpenAPI 或真实测试报告。

修改路径：先读取项目手册索引并建立“文档主题 → 事实来源 → 受影响文件 → 验证状态”映射，再进入各主题文档的局部事实替换；本步骤只冻结证据和影响面，不提前改写结论。

目标与规划：建立单一事实索引，记录源码基线、最后验证时间、OpenAPI、配置键、迁移 head、测试计数、line/branch 覆盖率、静态与安全扫描、镜像摘要、性能基线及 autotuner 最优/失败配置。以 `docs/project_manual/README.md` 的全量索引为文档清单，逐项映射事实来源和受影响文件。

依赖关系：仅消费 Phase 4 已冻结证据；缺少证据的条目标记 `blocked`，不得推断为通过。

验收点：每项结论至少指向源码、迁移、配置、OpenAPI 或真实测试报告之一；历史方案不作为唯一证据；敏感值只记录变量名或摘要，不写入密钥、令牌、密码和生产连接串。

### 步骤 2：回归架构与模块边界事实

代码现状：以冻结源码中的实际包结构、组合根、依赖导入和资源生命周期实现为准；项目手册中的架构图、类名或职责在完成源码定位前仅视为待核验内容。

目标形态：架构文档准确表达最终分层、依赖方向、组合根、管理员身份模块边界和资源生命周期，且每个路径、类名、调用链及释放责任均可在当前源码中定位。

修改路径：按 `00_project_overview/` → `01_architecture/` → `02_backend/` → `03_application_domain/` → 相关 `04_infrastructure/` 的顺序局部同步事实，并同步 README 导航、仓库地图、术语表和设计决策中的同一引用。

目标与规划：更新 `00_project_overview/`、`01_architecture/`、`02_backend/`、`03_application_domain/` 和相关 `04_infrastructure/` 文档，覆盖架构总览、依赖方向、组合根、请求与资源生命周期、配置系统、管理员身份 scope/role/user 模块边界。明确 `core/domain/application` 不依赖 `api/infrastructure`、`infrastructure` 不依赖 API 路由常量，以及资源启动、热重载、原子交换、退休释放和幂等 shutdown 的最终事实。

依赖关系：使用冻结源码、import-linter 结果、契约测试和关键路径测试；类名、路径或职责发生变化时同步仓库地图、术语表、设计决策和 README 导航。

验收点：架构图、依赖表、类名、调用链和资源释放责任均可在当前源码定位；不保留被硬迁移淘汰的旧模块边界作为当前路径。

### 步骤 3：回归开发、API、配置与迁移指南

依赖关系：以冻结 OpenAPI、路由、契约模型、配置模型/样例、迁移文件和真实迁移结果为准；代码片段与对应注释从源码原样提取。

验收点：示例可解析或可执行，字段名称、类型、必填性、枚举、错误码、迁移命令及 head 均与工作区一致；禁止开放字典扩展、过期配置键和未验证命令。

依赖关系：以最终 Compose、Dockerfile、配置、安全测试、镜像验证、真实负载和 autotuner 报告为准；生产平台未在仓库固化的能力明确写为部署环境决定。

验收点：生产说明默认 fail closed，示例不含真实密钥；容量配置仅采用多轮稳定且已晋升结果；无把单轮最优、未执行扫描或环境假设写成生产事实。

目标形态：形成一份可追溯的最终报告，完整展示发现、处置、淘汰方案、验证结果、性能参数对比、剩余风险和生产就绪结论。

修改路径：新增 `docs/2026_7_13_*_生产级代码审查回归报告.md`，按发现与处置、质量与测试、迁移与镜像、性能晋升、剩余风险和最终结论组织证据索引，并从项目手册 README 建立唯一入口。

目标与规划：新增 `docs/2026_7_13_*_生产级代码审查回归报告.md`，汇总发现及 P0-P3 处置、被淘汰方案、整改证据、命令返回码、测试计数、覆盖率、安全扫描、迁移与镜像摘要、最优/失败参数对比、剩余风险和生产就绪结论。报告采用可追溯的 `DocumentationHeader`、`TruthSource` 和状态口径。

验收点：P0/P1 为零才可给出生产就绪结论；任何 `failed/blocked/skip/xfail` 明确展示且不记为通过；性能至少包含已晋升配置与失败配置对比及复验结论。

### 步骤 7：全量一致性核验与入口切换

代码现状：步骤 2-6 完成后的源码、契约、测试、OpenAPI 和项目手册构成待核验的最终候选状态；任何一方尚有冲突时不得切换入口或宣告完成。

目标形态：五方事实一致，当前入口唯一，历史入口状态和替代路径明确，不存在失效链接、幽灵路径、错误配置键、API、迁移 head 或命令。

修改路径：先执行自动链接/路径检查，再人工抽查核心语义与源码片段，随后按 `current/deprecated/archived` 标记状态并一次性切换 README、角色导航、高频任务和专题交叉链接；发现冲突则回退事实责任方修正后重做本步骤。

目标与规划：检查项目手册全部链接、目录、路径、类名、配置键、API/OpenAPI、迁移版本、命令和 README 索引；按 `current/deprecated/archived` 标记文档状态。一次性把 README、角色导航、高频任务和专题交叉链接切换到最终文档，不保留并行入口。

依赖关系：步骤 2-6 全部完成后执行；自动链接/路径检查与人工语义抽查结合，核心链路额外做源码、契约、测试、OpenAPI、文档五方对照。

验收点：无失效链接、幽灵路径、过期配置键、错误 API、错误迁移 head 或无依据命令；所有过期入口均有替代路径；最终差异只包含可解释的事实同步和回归报告。

## 六、最终验收与失败处理

| 验收面 | 通过标准 | 失败处置 |
|---|---|---|
| 路径与命名 | 文档路径、类名、配置键、命令、迁移 head 均可由当前工作区验证 | 回到对应事实文件修正并重跑全量链接/路径检查 |
| 契约一致性 | 源码、契约、OpenAPI、测试、文档无未说明冲突 | 按事实优先级裁决；涉及公共行为则回退相应阶段验证 |
