# 局部异步化与同步主干保留执行方案

## 任务目标
最终要交付一套符合当前架构的“局部异步 + 同步主干保留”改造方案，用于消除 `async` Web 入口直接调用同步阻塞链路的问题，并仅在真正有收益的高并发 I/O 边界引入异步实现。

完成判定是：当前项目不再把“全量改 async”作为目标；Web 入口、共享资源、运行时配置、测试与文档统一收口为“同步用例主干 + 显式执行桥接 + 选择性异步资源”的稳定设计。

## 全局约束
- 以当前源码为准；若 `docs`、图谱、历史方案与源码冲突，以源码为准，并在文档回归中说明历史文档可能过期。
- 严格保持当前分层：`src/core` 只定义契约，`src/application` 保持业务编排，`src/infrastructure` 落地执行桥接与资源适配，`src/infrastructure/shared_resource_mount.py` 仍是统一装配入口。
- 不做“全量 async 改造”；领域层、契约层、用例层默认保持同步，只有明确的高并发 I/O 边界才允许异步化。
- 当前优先治理的阻塞边界是：`async` 路由直接调用同步 usecase / 同步数据库 / 同步缓存 / 同步任务派发 / 同步外部 HTTP。
- `SQLAlchemy`、`RedisCacheStore`、`funboost + RabbitMQ` 当前均视为既有同步栈；本次不直接迁移到 async 版本，只通过显式桥接避免阻塞事件循环。
- 新增或修改的运行时契约必须采用“公共头字段 + 强类型扩展字段”模式；扩展字段必须使用 Pydantic 判别联合，包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止在新增契约中使用 `dict[str, Any]`、`metadata`、`extra_payload`；外层类型与内层扩展类型必须一致。
- 禁止魔法字符串、魔法数字；稳定值与封闭集合必须收敛为常量或枚举。
- 所有日志、异常、注释保持中文；业务日志仍沿用现有日志方案，不引入第二套日志体系。
- 测试必须遵循 `docs/standard/测试规范.md`；所有真实测试必须做资源回收。

## 验收标准
- `async` 路由不再直接执行同步阻塞链路；同步调用必须统一经执行桥接或改为明确的同步入口策略。
- 同步主干仍可稳定工作；`DispatchBackgroundJobUsecase`、鉴权用例、系统概览用例、健康探针用例不因本次治理被强制改为 async。
- 共享 HTTP 资源支持显式区分同步与异步能力，异步资源只在真正需要的调用点接入。
- `SharedResourceMount` 能统一初始化、暴露并关闭新增执行桥接与异步资源，不引入悬挂连接或生命周期泄漏。
- 受影响 contract、unit、path、initialization、integration、convention usage 测试通过。
- 设计文档、执行方案、运行时配置说明与最终源码一致，并明确“当前不是全异步架构”。

## Phase 1
### 目标
先解决当前最直接的问题：`async` 路由函数内部直接执行同步阻塞链路，导致事件循环被数据库、缓存、任务派发和同步 HTTP 调用占用。

当前阶段完成后的中间结果是：Web 入口拥有显式执行策略，所有同步 usecase 或同步资源调用都通过统一桥接收口，应用主干仍保持同步，不向下游层级扩散 async。

### 依赖
- 依赖当前 `src/api/endpoint_*` 路由目录、`DependencyContextAccessor`、既有同步 usecase。
- 依赖当前 `SharedResourceMount`、`SettingsStateHolder` 与 `app_settings_loader.py` 作为统一配置与装配入口。
- 依赖当前源码事实：路由函数多数为 `async def`，但下游数据库、缓存、任务队列、共享 HTTP 客户端基本都是同步实现。

### 模拟用法
```toml
[runtime.web.request_execution]
envelope_kind = "request_execution_envelope"
schema_version = "1.0"

[runtime.web.request_execution.header]
execution_name = "default_sync_usecase"
enabled = true
mode = "threadpool"
schema_version = "1.0"

[runtime.web.request_execution.detail]
kind = "threadpool"
schema_version = "1.0"
offload_timeout_seconds = 15
```

```python
payload = await request_execution_bridge.run_sync(
    execution_name="issue_access_token",
    callable_object=issue_access_token_usecase.execute,
    command=credential_input,
)
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| RequestExecutionEnvelope | 请求执行策略信封 | 描述某类 Web 入口调用链应走 `threadpool` 还是 `native_async`，外层 `mode` 与内层扩展 `kind` 必须一致。 |
| RequestExecutionHeader | 请求执行策略公共头 | 包含 `execution_name`、`enabled`、`mode`、`schema_version`，用于统一索引与启停控制。 |
| RequestExecutionDetailUnion | 请求执行策略扩展体判别联合 | 仅允许强类型扩展体；所有扩展体必须包含 `kind`、`schema_version` 且 `extra="forbid"`。 |
| ThreadpoolExecutionDetail | 线程池执行扩展 | 表达 `kind="threadpool"` 的同步阻塞卸载策略，包含 `offload_timeout_seconds`。 |
| NativeAsyncExecutionDetail | 原生异步执行扩展 | 表达 `kind="native_async"` 的异步安全调用路径，包含取消传播开关等最小必要字段。 |
| RequestExecutionMode | 请求执行模式枚举 | 封闭集合，至少包含 `THREADPOOL`、`NATIVE_ASYNC`，用于消除裸字符串。 |

## Phase 2
### 目标
在 Phase 1 的稳定执行边界上，只对真正有收益的高并发 I/O 边界引入异步资源，优先处理共享外部 HTTP 客户端；继续明确哪些同步基础设施暂不迁移。

当前阶段完成后的中间结果是：项目具备“同步 HTTP 客户端 + 异步 HTTP 客户端”双资源能力；新接入的高并发外部调用可以走原生 async，而数据库、缓存、任务基建仍可保持既有同步实现。

### 依赖
- 依赖 Phase 1 的 `RequestExecutionEnvelope` 与 `RequestExecutionBridge`。
- 依赖当前 `SharedHttpClient`、`SharedResourceMount` 与现有资源生命周期编排。
- 依赖当前源码事实：`SharedHttpClient` 基于 `httpx.Client`，项目尚未形成独立的 outbound HTTP 运行时配置目录。

### 模拟用法
```toml
[runtime.web.outbound_http_client]
envelope_kind = "outbound_http_client_envelope"
schema_version = "1.0"

[runtime.web.outbound_http_client.header]
client_name = "default_outbound_http"
enabled = true
mode = "async_http"
schema_version = "1.0"

[runtime.web.outbound_http_client.detail]
kind = "async_http"
schema_version = "1.0"
timeout_seconds = 5
max_connections = 100
max_keepalive_connections = 20
```

```python
client = resource_mount.get_async_http_client().get_client()
response = await client.get(target_url)
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| OutboundHttpClientEnvelope | 外部 HTTP 客户端信封 | 描述共享外部 HTTP 客户端应走 `sync_http` 还是 `async_http`，外层 `mode` 与内层 `kind` 必须一致。 |
| OutboundHttpClientHeader | 外部 HTTP 客户端公共头 | 包含 `client_name`、`enabled`、`mode`、`schema_version`，用于统一索引与启停控制。 |
| OutboundHttpClientDetailUnion | 外部 HTTP 客户端扩展体判别联合 | 仅允许强类型扩展体；所有扩展体必须包含 `kind`、`schema_version` 且 `extra="forbid"`。 |
| SyncHttpClientDetail | 同步 HTTP 客户端扩展 | 表达 `kind="sync_http"` 的同步客户端参数，如 `timeout_seconds`。 |
| AsyncHttpClientDetail | 异步 HTTP 客户端扩展 | 表达 `kind="async_http"` 的异步客户端参数，如 `timeout_seconds`、`max_connections`、`max_keepalive_connections`。 |
| OutboundHttpClientMode | 外部 HTTP 客户端模式枚举 | 封闭集合，至少包含 `SYNC_HTTP`、`ASYNC_HTTP`，避免裸字符串分支。 |
