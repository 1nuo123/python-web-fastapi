# 身份管理后台联调阻塞项整改执行方案

## 任务目标
交付一套后端 P1 阻塞项与运维一致性问题的整改方案，支撑后续真实改码、测试回归和最小前端联调。

完成判定是：登录、`/auth/me`、管理员用户管理、预设业务角色下拉、审计列表、健康检查可稳定联调；完整身份管理后台所需的 scope/role/user 管理接口契约闭合；任务幂等、封禁 TTL、测试隔离和持久化 schema 一致性问题完成回归。

## 全局约束
- 以源码为准；若文档、图谱、历史执行方案与源码冲突，以源码执行结果为准，并在文档回归中标注旧文档可能过期。
- 优先修复 P1 阻塞项，再处理非阻塞但会影响运行一致性的收口项。
- API 响应、请求和内部跨层对象采用“公共头字段 + 强类型扩展字段”规则。
- 扩展字段必须使用 Pydantic 判别联合，必须包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议。
- 外层类型与内层扩展类型必须一致，例如当前身份管理契约中的 `header.kind == detail.kind`，并在模型校验或装配入口统一校验。
- 权限变更测试必须隔离数据库状态，不依赖测试执行顺序。
- 数据库迁移必须兼容已有测试库和开发库；新增约束前必须先清理或兜底历史脏数据。
- 并发幂等、缓存 TTL、生命周期释放必须以可重复测试验证，不只依赖人工复跑。
- 日志、错误码和审计事件沿用现有中文语义与错误体系，不新增孤立风格。

## 验收标准
- `admin_identity` 的 scope、role、user、business role 路由与契约完整暴露，OpenAPI 和接口测试一致。
- 非管理员业务角色登录后可通过 `/auth/me` 自省当前用户、角色、scope 和菜单初始化所需信息。
- 非集成、接口、集成、全量测试在干净测试库与重复执行场景下结果稳定。
- 相同任务 `job_kind + deduplication_key` 并发提交不会抛出未处理唯一键异常，并返回同一幂等记录。
- IP 封禁缓存 TTL 不超过数据库封禁剩余有效期。
- ORM、Alembic migration、实际数据库约束在鉴权、审计、日志、任务执行记录关键表上保持一致。
- Docker healthcheck、任务 worker、日志 flush、生命周期 shutdown、运行时安全配置消费行为有测试或文档闭环。

## 阶段依赖关系
- Phase 1 是前端身份管理联调的主阻塞修复，必须最先完成。
- Phase 2 依赖 Phase 1 的身份契约边界，解决非管理员登录自举。
- Phase 3 依赖 Phase 1 和 Phase 2 的权限路径固定，保证后续回归基线稳定。
- Phase 4 可与 Phase 1 至 Phase 3 并行改码，但真实测试必须在 Phase 3 后执行。
- Phase 5 依赖 Phase 4 的任务执行记录语义，统一修复安全缓存和 schema 漂移。
- Phase 6 依赖前五个阶段的主链路稳定，收口非阻塞运维一致性问题。

## Phase 1
### 目标
修复 `admin_identity` 路由和契约断裂，使 scope、role、user、business role 管理能力完整可被前端调用。

阶段完成后，身份管理前端可基于同一套 `AdminIdentityEnvelope` 访问 scope 列表/详情/创建/更新/删除、role 列表/详情/创建/更新/删除/替换 scope、user 管理和预设业务角色下拉。

### 依赖
- `src/api/endpoint_admin_identity/route_admin_identity.py`
- `src/api/endpoint_admin_identity/contract_admin_identity.py`
- 现有 `AdminIdentityDetailUnion`、`AdminIdentityOperation`、管理员鉴权依赖。
- 现有 scope/role/user usecase 和 repository 实现。

### 模拟用法
```http
GET /admin/scopes
GET /admin/scopes/{scope_code}
POST /admin/scopes
PATCH /admin/scopes/{scope_code}
DELETE /admin/scopes/{scope_code}

GET /admin/roles
GET /admin/roles/{role_key}
POST /admin/roles
PATCH /admin/roles/{role_key}
PUT /admin/roles/{role_key}/scopes
DELETE /admin/roles/{role_key}
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `AdminIdentityHeader` | 身份管理公共头 | 外层公共头，包含 `kind`、`schema_version`、`operation_name`，必须与内层扩展类型一致。 |
| `AdminIdentityDetailUnion` | 身份管理扩展判别联合 | 使用 `Field(discriminator="kind")`，纳入 scope/role/user/business role 的读写请求和响应扩展。 |
| `AdminScopeCreateDetail` | scope 创建扩展 | 当前源码名称为 `AdminScopeCreateRequest`，包含 `kind="admin_scope_create"`、`schema_version`、`scope_code`、`scope_name`、`description`、`enabled`，`scope_kind` 由服务端派生且请求禁止额外字段。 |
| `AdminScopeUpdateDetail` | scope 更新扩展 | 包含 `kind="admin_scope_update"`、`schema_version`、可更新字段，路径 `scope_code` 为准。 |
| `AdminRoleCreateDetail` | role 创建扩展 | 包含 `kind="admin_role_create"`、`schema_version`、`role_key`、`role_name`、`scope_codes`。 |
| `AdminRoleUpdateDetail` | role 更新扩展 | 包含 `kind="admin_role_update"`、`schema_version`、`role_name`，路径 `role_key` 为准。 |
| `AdminRoleScopeReplaceDetail` | role scope 替换扩展 | 包含 `kind="admin_role_scope_replace"`、`schema_version`、`scope_codes`，用于全量替换角色 scope。 |
| `AdminIdentityRouteBinding` | 身份管理路由绑定 | 路由绑定清单必须覆盖 `_bind_scope_routes()`、完整 `_bind_role_routes()` 和 user routes。 |

## Phase 2
### 目标
修复 `/auth/me` 只允许 `ADMIN + auth:read` 的问题，使已登录的非管理员业务角色可完成当前用户自省。

阶段完成后，`customer_service`、`business_operator` 等业务角色登录后可读取自身 subject、roles、scopes 和前端菜单初始化所需信息，但不能因此获得管理员管理接口权限。

### 依赖
- Phase 1 的身份角色和 scope 契约固定。
- `src/api/endpoint_auth_access/route_auth_access.py`
- `src/core/auth_contract/authenticated_principal_contract.py`
- `src/api/endpoint_auth_access/contract_auth_access.py` 仅承载 token 请求模型，不承载 `/auth/me` 响应载荷。
- 现有认证中间件、权限守卫、访问令牌解析链路。

### 模拟用法
```http
GET /auth/me
Authorization: Bearer <access_token>
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `AuthenticatedPrincipal` | 当前用户自省载荷 | 当前源码 `/auth/me` 返回 `ResponseEnvelope[AuthenticatedPrincipal]`，包含 `kind="authenticated_principal"`、`schema_version`、`subject_id`、`username`、`roles`、`scopes`、`is_admin`，禁止额外字段。 |
| `AuthMeAccessPolicy` | 自省访问策略 | 要求“已认证即可自省”，不要求管理员角色；管理接口仍由各自 scope 和 role 控制。 |
| `MenuBootstrapScopeSet` | 菜单自举 scope 集 | 前端只根据返回 scope 计算菜单，不通过 `/auth/me` 放大权限。 |
