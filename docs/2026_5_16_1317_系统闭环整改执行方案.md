# 2026_5_16_1317_系统闭环整改执行方案

## 任务目标
交付一套已整改的系统底座，完成以下闭环：
1. 鉴权改为“会话校验 + 当前权限真值”模式，消除旧 access token 持续沿用过期权限的问题。
2. bootstrap 管理员同步改为“角色定义”与“用户绑定”分离，消除 RBAC 污染。
3. `app.modules.enabled` 真实参与模块装配，配置声明与运行行为一致。
4. 运行时配置补齐强约束校验，加载期即可失败。
5. 装配层职责收敛，系统可维护性提升，保持后续快速开发可用。

完成判定是：审查报告中的 5 个问题均被关闭、降级为明确设计取舍，或被源码与文档显式约束。

## 全局约束
- 统一遵守 `docs/standard`；若文档、图谱、源码冲突，以当前源码与冻结契约为准，文档可能过期。
- 禁止 `print`、禁止顶层函数、禁止弱类型兜底，稳定取值统一收敛为常量或 Enum。
- 新增或修改契约统一采用“公共头字段 + 强类型扩展字段”模式；扩展字段使用 Pydantic 判别联合，必须包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止 `dict[str, Any]`、`metadata`、`extra_payload`；外层类型与内层扩展类型保持一致。
- 不做额外兼容层；未显式要求兼容时，直接迁移到新设计。
- 日志、异常、注释、文档统一中文；文档采用 Sphinx / reST 风格三级说明。

## 验收标准
- 访问令牌鉴权以数据库当前角色与 scope 为准，同时保留主体、会话、吊销、停用校验。
- bootstrap 管理员不会再把同一组 scope 回写到所有角色，角色定义与用户绑定行为可预测。
- `app.modules.enabled` 能真实控制路由装配，系统概览输出与实际已装配模块一致。
- 关键运行时配置的非法值会在配置加载阶段直接失败，并返回明确中文错误。
- 全量测试、编译检查、文档回归通过；实现、测试、文档三者一致。

## Phase 1
### 目标
完成鉴权一致性整改，并消除 bootstrap 管理员对全局角色定义的污染。阶段完成后，请求内主体必须来自“已校验会话 + 数据库当前授权快照”，bootstrap 角色同步必须按角色显式定义。

### 依赖
依赖现有认证表、refresh token 会话表、JWT `sub/sid`、现有授权守卫入口。

### 模拟用法
```toml
[[modules.auth.bootstrap_admin.role_bindings]]
kind = "bootstrap_role_binding"
schema_version = "v1"
role_key = "admin"
scope_codes = ["auth.read"]
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| AuthenticatedPrincipal | 认证主体 | 运行时主体以数据库当前角色与 scope 为真值，不再直接信任 JWT 内嵌权限快照 |
| AuthIdentityAuthorizationSnapshot | 当前授权快照 | 描述主体当前启用状态、角色集合、scope 集合，供中间件构造主体 |
| BootstrapRoleBinding | 引导角色绑定契约 | 公共头字段 + 判别联合入口，统一承载 bootstrap 角色定义 |
| BootstrapRoleBindingV1 | 引导角色绑定 V1 | `kind/schema_version` 固定，字段含 `role_key`、`scope_codes`，`extra="forbid"` |

### 任务清单
- [x] 为身份仓储新增“当前授权快照”查询能力。
- [x] 调整认证中间件：先校验 access token、主体、会话，再从数据库回读当前角色与 scope 构造主体。
- [x] 保留 `sid`、主体、吊销、停用校验，停止把 JWT 内嵌 `roles/scopes` 当作授权真值。
- [x] 新增 bootstrap 角色绑定强类型契约，替换当前 `roles + scopes` 平铺配置。
- [x] 拆分 bootstrap 角色定义同步与用户角色绑定同步，避免全局角色污染。

### 关键代码片段
```python
snapshot = auth_identity_repository.get_authorization_snapshot_by_subject_id(subject_id)
token_session = refresh_token_repository.get_token_session_status(token_session_id)
principal = AuthenticatedPrincipal.from_authorization_snapshot(snapshot)
authorization_guard.assert_requirement(principal=principal, requirement=requirement)
```

### 校验
- 使用同一 access token，在数据库撤销 scope 后，轻量校验主体 scope 已随请求变化。
- bootstrap 配置加载成功，且多角色场景下每个角色只同步自己的 scope。

## Phase 2
### 目标
让模块开关真实生效，并收敛装配层职责。阶段完成后，`app.modules.enabled` 必须直接影响路由装配，`SharedResourceMount` 只保留容器与资源协调职责。

### 依赖
依赖 `Phase 1` 完成后的主体契约、bootstrap 同步协作者与最终授权链路。

### 模拟用法
```toml
[app.modules]
enabled = ["health_probe", "system_overview", "auth_access"]
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| ApplicationModuleName | 应用模块名枚举 | 约束可装配模块集合，禁止裸字符串模块名 |
| WebBundle | Web 模块清单 | 增加强类型模块标识，供路由装配按开关过滤 |
| EnabledModuleSnapshot | 已启用模块快照 | 系统概览输出使用的实际装配结果，确保与路由一致 |

### 任务清单

- [x] 扩展 `WebBundle`，补齐模块标识字段。

- [x] 调整 `SystemOverviewUsecase`，输出实际已装配模块而不是纯配置回显。
- [x] 从 `SharedResourceMount` 下沉 bootstrap 同步细节，保留资源生命周期、工厂与协调职责。

### 关键代码片段
```python

```

### 校验

- 系统概览返回的模块集合与实际挂载路由一致。
- `SharedResourceMount` 初始化与关闭流程仍可正常执行。

## Phase 3
### 目标

### 依赖
依赖 `Phase 2` 的模块枚举、模块装配规则与 `Phase 1` 的 bootstrap 新契约。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| WebRuntimeSettings | Web 运行时配置 | 对请求体大小等关键字段增加正数校验 |
| AuthRuntimeSettings | 鉴权运行时配置 | 对 token TTL、频控窗口、锁定时长增加正数校验 |
| DatabaseRuntimeSettings | 数据库运行时配置 | 对连接池、回收、超时增加正数校验，并继续强制 PostgreSQL |
| ApplicationModuleSwitchSettings | 模块开关配置 | 对未知模块、重复模块做加载期校验 |
