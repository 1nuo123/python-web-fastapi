## 全局约束
- 编码遵守 `docs/standard/编码规范.md`、`docs/standard/测试规范.md`、`docs/standard/命名规范.md`。
- 若文档、图谱、历史方案与源码冲突，以源码为准，并在文档回归中说明旧文档可能过期。
- 公共函数、公共类属性、返回值必须完整类型标注，使用 Python 3.11+ 现代类型语法。
- Repository 只负责读写和抛出无法处理的数据库异常，事务提交、回滚、释放仍由 UoW 边界负责。
- 查询函数不得隐藏写副作用；命令函数必须显式表达副作用。
- 配置、API、缓存、消息、安全事件、运行时状态等稳定协议必须采用“公共头字段 + 强类型扩展字段”模式。
- 扩展字段必须使用 Pydantic 判别联合，必须包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载稳定协议。
- 外层类型与内层扩展类型必须一致，例如 `backend == backend_detail.kind`、`header.kind == detail.kind`、`header.schema_version == detail.schema_version`。
- RabbitMQ、缓存、数据库等真实依赖测试必须显式标记环境要求；未启用时只能显式 skip，不能假通过。

## 验收标准
- 最后一个具备 `active admin + auth:manage` 能力的管理员不能被停用、禁用、剥离角色或剥离关键 scope。
- `security:manage` 与所有后台受保护路由依赖 scope 都进入中心化 protected scope registry，后台不能禁用。
- `worker_enabled=false` 的 producer-only 节点仍可派发任务，且不会启动本节点 consumer。
- 启动期 handler 完整性校验只作用于实际消费或本地执行节点。
- RabbitMQ 任务发布在无可达 binding 时失败可观测，不把未路由消息当成功。
- `runtime.task.backend=local` 与外部 RabbitMQ message bus 的重复执行风险被配置校验或明确幂等契约阻断。
- 已封禁 IP 命中记录为 `ip_block` 事件，`Retry-After` 不超过真实剩余封禁时间。
- task binding、日志 flush、admin audit operation、distributed lock failure policy 的公开契约与源码行为一致。
- 所有新增或修改测试按最小失败集、阶段相关集、依赖型集成、全量回归顺序通过。
- 相关设计文档、运行说明、测试说明与最终源码和测试结果一致。

## Phase 1
### 目标
收口后台授权事实源，防止管理员控制面自锁。

阶段完成后，系统始终至少保留一个 `active admin + auth:manage` 管理员；`security:manage` 等受保护 scope 不能被后台禁用。

### 依赖
- `admin_route_authorization.py` 的后台路由授权 requirement。
- `route_security_protection.py` 当前安全防护路由的 `security:manage` requirement。
- `admin_identity_repository_impl.py` 的 `update_user()`、`replace_user_roles()`、`disable_user()`、scope 更新写路径。
- 现有管理员身份 API 契约与 RBAC 集成测试。

### 模拟用法
```bash
curl -X PATCH /admin/scopes/security:manage \
  -H "Authorization: Bearer <admin-token>" \
  -H "Content-Type: application/json" \
  -d '{"header":{"kind":"admin_scope_update","schema_version":"1.0"},"detail":{"kind":"admin_scope_update","schema_version":"1.0","enabled":false}}'
```

预期结果：返回业务冲突错误，`security:manage` 保持启用。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `ProtectedAdminScopeRegistry` | 受保护后台 scope 注册表 | 后台非公开路由依赖的系统 scope 事实源，包含 `security:manage`，禁止后台禁用或删除。 |
| `AdminAccessInvariant` | 管理员存活不变量 | 任意写操作提交后，系统仍必须存在至少一个 active admin 且具备 `auth:manage`。 |
| `AdminScopeUpdateDetail` | scope 更新扩展体 | Pydantic 判别联合扩展字段，含 `kind`、`schema_version`，启用 `extra="forbid"`。 |
| `AdminConflictDetail` | 后台冲突错误扩展体 | 使用公共头字段 + 强类型扩展字段表达 `protected_scope_disabled`、`last_admin_blocked` 等冲突原因。 |
| `RouteAuthorizationRequirement` | 路由授权需求 | 所有后台路由授权需求从中心 registry 暴露，不在路由内部临时创建隐式 scope。 |

## Phase 2
### 目标
收口任务运行时 producer/consumer 拓扑，修复 producer-only 部署、handler 校验、RabbitMQ 未路由发布和本地重复执行风险。

阶段完成后，`worker_enabled` 只表示当前节点是否消费或执行任务；任务发布、任务消费、本地 inline 执行、RabbitMQ 路由可达性各自有清晰契约。

### 依赖
- Phase 1 完成后台任务管理权限事实源收口。
- `local_task_dispatcher.py`、`funboost_task_dispatcher.py` 当前派发入口。
- `task_runtime_manager.py`、`task_registration_registry.py` 当前启动装配与 handler 校验。
- `rabbitmq_message_bus.py` 当前发布确认实现。
- `runtime_resource_bootstrapper.py` 当前 task/message backend 组合装配。

### 模拟用法
```toml
[runtime.task]
backend = "funboost"
worker_enabled = false

[runtime.message]
backend = "rabbitmq"
```

预期结果：API 节点允许派发任务到 RabbitMQ/Funboost，不启动本节点 consumer，不要求本节点绑定 handler。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `worker_enabled` | 工作节点开关 | 仅表示当前节点是否启动 consumer 或本地执行，不阻断 producer 发布。 |
| `inline_execute_enabled` | 本地内联执行开关 | 本地 backend 是否同进程执行 handler 的显式开关，避免复用 `worker_enabled`。 |
| `TaskBackendDetailUnion` | 任务后端扩展联合 | Pydantic 判别联合，所有扩展含 `kind`、`schema_version`、`extra="forbid"`。 |
| `MessagePublishResult` | 消息发布结果 | 强类型结果对象，表达 published、routed、message_id、failure_reason，不返回弱布尔值。 |
| `RabbitMqPublishPolicy` | RabbitMQ 发布策略 | 关键任务发布使用 `mandatory=True`，处理 returned message 与 publisher confirm。 |
| `TaskTopologyPolicy` | 任务拓扑策略 | 禁止或显式约束 `task=local + message=rabbitmq` 的重复执行风险。 |
| `TaskBindingPolicy` | 任务绑定策略 | 未声明 binding 按严格配置 fail-fast，不保留失活过滤分支。 |

## Phase 3
### 目标
收口安全可观测事件事实源，修复 IP 封禁命中事件分类和缓存命中 `Retry-After` 不准确。

阶段完成后，已封禁 IP 的请求被记录为 `ip_block` 事件；缓存命中时根据真实解封时间动态计算 `Retry-After`。

### 依赖
- Phase 1 完成 `security:manage` protected scope 收口。
- `ip_block_guard.py` 当前 DB 命中和缓存命中逻辑。
- `security_protection_guard.py` 当前事件构建分支。
- `security_event_builder.py` 当前 rate limit 与 ip block 事件构建函数。
- 安全防护接口、事件查询和 IP 封禁集成测试。

### 模拟用法
```bash
curl -i /api/protected-resource \
  -H "X-Forwarded-For: 203.0.113.10"
```

预期结果：若该 IP 已被封禁，响应包含不超过真实剩余时间的 `Retry-After`，安全事件类型为 `ip_block`。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `SecurityEventEnvelope` | 安全事件信封 | 公共头字段 + 强类型事件扩展字段，header 与 detail 的 `kind/schema_version` 必须一致。 |
| `IpBlockEventDetail` | IP 封禁事件扩展体 | `kind="ip_block"`，含 `schema_version`、`ip_digest`、`blocked_until_epoch`、`retry_after_seconds`，启用 `extra="forbid"`。 |
| `RateLimitEventDetail` | 限流事件扩展体 | `kind="rate_limit"`，仅表达限流超限或首次触发封禁，不承载已封禁命中语义。 |
| `IpBlockCacheEntry` | IP 封禁缓存项 | 强类型缓存值，保存 `blocked_until_epoch` 和封禁原因，不再只保存 `"active"`。 |
| `RetryAfterSeconds` | 重试等待秒数 | 根据当前时间与 `blocked_until_epoch` 计算，不超过真实剩余封禁时间。 |

- [x] 保留限流超限首次封禁的 `rate_limit` 事件语义。

## Phase 4
### 目标
收口剩余 P2 运行时契约心智：task binding 严格语义、日志 flush interval、admin audit operation、distributed lock failure policy。

阶段完成后，公开配置、端口枚举、运行时状态和实际源码行为一致，不再暴露“看起来支持但实际未实现”的能力。

### 依赖
- Phase 2 固定 task binding 和任务运行时语义。
- Phase 3 固定安全事件事实源。
- `log_buffer_dispatcher.py` 当前懒刷盘实现。
- `admin_audit_query_port.py` 与 `log_record_repository_impl.py` 当前审计查询实现。
- `distributed_lock_contract.py` 与 `distributed_lock_provider.py` 当前固定 fail-closed 行为。

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `LogFlushPolicyDetail` | 日志刷盘策略扩展体 | 若承诺定时刷盘，则引入后台 flush loop；否则契约明确为 lazy flush，扩展体含 `kind/schema_version/extra="forbid"`。 |
| `AdminAuditOperationKind` | 后台审计操作类型 | 只暴露已有数据源和仓储实现支持的 operation；未实现业务审计不出现在公开枚举。 |
| `AuditEventRegistry` | 审计事件注册表 | 若新增业务审计，必须由业务模块注册 event kind、operation、object_type 后才能查询。 |
| `DistributedLockFailurePolicy` | 分布式锁故障策略 | 固定 fail-closed，不再暴露可配置但无实现分支的 `failure_mode`。 |
| `RuntimeContractMigration` | 运行时契约迁移 | 旧配置字段被迁移、拒绝或明确忽略时必须有可测试错误语义。 |

### 校验
- 单条日志写入后超过 interval 的行为与冻结契约一致。
- admin audit 接口不再暴露永远查不到数据的 operation。
- 旧 `distributed_lock_runtime.failure_mode` 配置被迁移或拒绝，行为可测试。
- 分布式锁依赖不可用时仍固定 fail-closed。
- 任务 binding 默认路径与显式传入路径均按严格配置处理。

## 回归修复
真实测试失败后按失败类型修复源码、测试或文档，并回跑对应最小测试集。

- [x] 任务运行时失败：优先检查 producer/consumer 开关、handler 校验触发条件、RabbitMQ mandatory、拓扑配置校验，再回跑 Phase 2 测试。
- [x] 安全事件失败：优先检查事件 kind、缓存值结构、retry_after 计算、事件查询映射，再回跑 Phase 3 测试。
