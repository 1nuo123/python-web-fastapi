# 资源挂载生命周期门面收口执行方案

## 任务目标
交付一套可真实改码与回归的整改方案：将 `runtime_resource_bootstrapper.py`、`runtime_resource_releaser.py`、`runtime_accessor_refresher.py` 中对 `SharedResourceMount` 内部字段的直接修改，收口为 `SharedResourceMount` 显式生命周期方法。

完成判定是：helper 只编排资源构建与释放，不再直接写入 mount 私有运行时字段；启动、热更新、关闭、访问器刷新行为与现有外部门面保持一致。

## 全局约束
- 以源码为准；若历史文档、图谱与源码冲突，以源码执行，并标注文档可能过期。
- 保持当前分层：`src/infrastructure/resource_mount/` 负责 helper 编排，`SharedResourceMount` 负责资源门面、内部状态持有与生命周期写入。
- 禁止 helper 直接赋值 `mount._http_runtime_accessor`、`mount._runtime_states`、`mount._session_factory`、`mount._db_session_manager`、`mount._task_execution_store`、`mount._cache_store`、`mount._cache_service`、`mount._task_runtime_accessor`、`mount._auth_accessor`、`mount._logging_accessor` 等生命周期字段。
- 新增或调整契约必须采用“公共头字段 + 强类型扩展字段”。
- 扩展字段必须使用 Pydantic 判别联合，包含 `kind`、`schema_version`，并启用 `extra="forbid"`。
- 禁止新增 `dict[str, Any]`、`metadata`、`extra_payload` 承载扩展数据。
- 外层类型与内层扩展类型必须一致，并通过模型校验保证 `kind`、`schema_version` 一致。
- 不改变现有对外读取方法，例如 `get_http_client()`、`create_unit_of_work()`、`get_task_dispatcher()`、`get_runtime_states()`。

## 验收标准
- `runtime_resource_bootstrapper.py`、`runtime_resource_releaser.py`、`runtime_accessor_refresher.py` 不再直接写入 mount 私有生命周期字段。
- 启动后 HTTP、数据库、日志、缓存、消息、任务资源状态仍与现有语义一致。
- 关闭后 HTTP、数据库、缓存、任务、日志资源被释放，访问器刷新后不暴露失效资源。
- 配置热更新提交、回滚、任务绑定变更仍保持原有行为。
- 契约测试、初始化测试、路径测试与全量回归通过。
- 设计文档说明 helper 不再拥有 mount 内部字段写权限；历史拆分方案中旧描述如与源码冲突，标注可能过期。

## Phase 1
### 目标
在 `SharedResourceMount` 中建立显式生命周期方法，集中管理资源挂载、状态写入、访问器刷新与资源释放后的清空动作。

当前阶段完成后，helper 可以通过稳定方法完成状态切换，不需要知道 mount 内部字段布局。

### 依赖
- 现有 `SharedResourceMount` 内部字段与读取门面。
- 现有 `RuntimeResourceState`、`RuntimeResourceStatus`。
- 现有 `HttpRuntimeAccessor`、`TaskRuntimeAccessor`、`AuthSupportAccessor`、`LoggingSupportAccessor`。

### 模拟用法
```python
mount.attach_http_runtime(resource_set)
mount.mark_runtime_resource_ready(RESOURCE_DATABASE)
mount.install_database_runtime(
    session_factory=session_factory,
    db_session_manager=db_session_manager,
    task_execution_store=task_execution_store,
)
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `RuntimeResourceMountOperationEnvelope` | 资源挂载操作信封 | 外层统一操作模型，包含公共头 `header` 与判别联合 `detail`，校验外层与内层 `kind`、`schema_version` 一致。 |
| `RuntimeResourceMountOperationHeader` | 资源挂载操作公共头 | 承载 `kind`、`schema_version`、`operation_name`、`target_resource`、`resource_name`。 |
| `RuntimeResourceMountOperationDetail` | 资源挂载操作扩展联合 | 使用 `Field(discriminator="kind")` 的 Pydantic 判别联合，禁止裸字典扩展。 |
| `HttpRuntimeAttachedDetail` | HTTP 运行时挂载扩展 | 描述 HTTP 资源集已挂载，包含同步/异步客户端状态来源，不承载客户端对象本身。 |
| `DatabaseRuntimeAttachedDetail` | 数据库运行时挂载扩展 | 描述会话工厂、会话管理器、任务执行存储已完成绑定。 |
| `CacheRuntimeAttachedDetail` | 缓存运行时挂载扩展 | 描述缓存存储、缓存服务、鉴权节流器已完成绑定。 |
| `TaskRuntimeAttachedDetail` | 任务运行时挂载扩展 | 描述注册中心、消息总线、dispatcher、bootstrap snapshot 已完成绑定。 |
| `RuntimeAccessorsRefreshedDetail` | 运行时访问器刷新扩展 | 描述鉴权与日志访问器快照已由 mount 内部刷新。 |
| `RuntimeResourceStateChangedDetail` | 资源状态变更扩展 | 描述指定资源进入 `created`、`starting`、`ready`、`failed`、`stopping`、`stopped` 中的某一状态。 |

### 关键代码片段
```python
RuntimeResourceMountOperationDetail = Annotated[
    HttpRuntimeAttachedDetail
    | DatabaseRuntimeAttachedDetail
    | CacheRuntimeAttachedDetail
    | TaskRuntimeAttachedDetail
    | RuntimeAccessorsRefreshedDetail
    | RuntimeResourceStateChangedDetail,
    Field(discriminator="kind"),
]
```

### 校验
- `SharedResourceMount` 新方法均只修改自身字段，不改变现有 public getter 返回语义。
- 契约模型拒绝额外字段。
- 构造外层与内层 `kind`、`schema_version` 不一致的信封时快速失败。

## Phase 2
### 目标
改造 `runtime_resource_bootstrapper.py`、`runtime_resource_releaser.py`、`runtime_accessor_refresher.py`，让 helper 只调用 mount 显式方法，不再直接修改 mount 内部字段。

当前阶段完成后，资源生命周期写入点集中在 `SharedResourceMount`，后续快速开发不容易绕过释放顺序与状态刷新规则。

### 依赖
- Phase 1 的显式生命周期方法。
- 现有资源构建器、释放器、日志生命周期事件。
- 现有启动顺序：HTTP、数据库、日志、缓存、消息、任务。
- 现有关闭顺序：日志 flush、任务、缓存、数据库、HTTP、消息、日志。

### 模拟用法
```python
resource_set = mount.build_http_resource_set(settings)
mount.attach_http_runtime(resource_set)
mount.emit_runtime_lifecycle_log(
    resource_name=RESOURCE_HTTP_CLIENT,
    lifecycle_action=ResourceLifecycleAction.STARTUP,
    resource_status=RuntimeResourceStatus.READY,
    detail_text=None,
)
```

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `RuntimeResourceBootstrapEnvelope` | 资源启动信封 | 沿用启动操作外层契约，继续使用公共头与 `ResourceBootstrapDetail` 判别扩展。 |
| `ResourceBootstrapDetail` | 资源启动扩展 | 描述启动顺序，包含 `kind="resource_bootstrap"`、`schema_version`，启用 `extra="forbid"`。 |
| `RuntimeResourceReleaseEnvelope` | 资源释放信封 | 沿用释放操作外层契约，继续使用公共头与 `ResourceReleaseDetail` 判别扩展。 |
| `ResourceReleaseDetail` | 资源释放扩展 | 描述释放顺序，包含 `kind="resource_release"`、`schema_version`，启用 `extra="forbid"`。 |
| `RuntimeAccessorRefreshDetail` | 访问器刷新扩展 | 描述访问器刷新动作，刷新结果由 mount 内部字段生成，helper 不再直接写 `_auth_accessor`、`_logging_accessor`。 |

def _release_cache(self, mount: "SharedResourceMount") -> None:
