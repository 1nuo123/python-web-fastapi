## 4. 背压与退化

- 突发和过载场景未出现 Locust failure 或未处理 5xx。
- Redis 退化时完成的 23 个请求全部按 503 fail closed，退化请求 p95 为 4.6 秒，负载按契约退出 0。
- Redis 恢复后应用无需重启即可恢复健康。
- 双实例分别使用相同只读镜像和共享外部依赖，均返回 0 未预期错误；辅助实例在测试后删除。
- 健康探针路径不进入业务数据库连接池和任务队列，因此池等待和队列深度不适用；本报告不把这两个空值推断为零。
- 原始 CSV、HTML、逐命令日志、33 条命令证据、资源采样和 autotuner 记录均位于 `docs/evidence/load/current-final/`，`phase3-final-load` TestRunRecord 已进入统一证据索引。

## 6. 结论与边界

冻结场景通过：稳定复验无 p95 劣化，突发和过载按 429 背压，Redis 退化按 503 关闭请求并恢复，双实例无未预期错误。该结果足以验证运行时与安全边界，但健康探针不是具体业务容量模型；业务发布前仍需按真实数据量、认证主体分布和 SLO 复用同一晋升规则。
