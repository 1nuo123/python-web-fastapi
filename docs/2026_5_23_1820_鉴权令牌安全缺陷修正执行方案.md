# 鉴权令牌安全缺陷修正执行方案

## 任务目标
交付一组针对鉴权链路的安全修正方案，优先修复：
1. `authentication_binding_middleware.py` 异常捕获过宽，避免数据库或资源故障被伪装成 `401`。
2. `refresh_access_token_usecase.py` 检测到 refresh token reuse 时，强制撤销整个 `token_session_id`。
3. `jwt_token_service.py` 令牌过期边界改为 `now >= exp` 即过期。

完成判定：源码、测试、文档均体现上述语义，相关真实测试和全量回归通过。

## 全局约束
- 若文档、图谱、历史方案与源码冲突，以源码为准；历史文档可能过期，文档回归时必须说明。
- 不改变 `/auth/token`、`/auth/refresh`、`/auth/revoke`、`/auth/me` 的外部响应结构，只修正状态语义。
- 鉴权中间件只收敛已知 `HttpFaultException`；数据库、仓储、资源挂载、线程桥接等未预期异常必须进入统一异常链路。
- refresh token reuse 必须先持久化撤销同一 `token_session_id` 下全部活跃刷新令牌，再返回 `auth.token.reused`。
- JWT 过期语义统一为半开区间：`issued_at_epoch <= now < expires_at_epoch` 才有效。
- 契约设计遵循“公共头字段 + 强类型扩展字段”：扩展字段使用 Pydantic 判别联合，必须有 `kind`、`schema_version`，启用 `extra="forbid"`。
- 禁止使用 `dict[str, Any]`、`metadata`、`extra_payload` 承载安全、鉴权、令牌失效扩展字段。
- 外层类型与内层扩展类型必须一致；例如 `RefreshTokenInvalidationHeader.mode.value == detail.kind`。
- 日志不得记录明文 access token、refresh token、密码、JWT secret、连接串密码。

## 验收标准
- 鉴权绑定阶段的资源或数据库故障不再返回 `auth.token.invalid`，应表现为统一 `500` 系统异常响应。
- 无效、过期、撤销的访问令牌仍按既有鉴权错误码返回 `401`。
- refresh token reuse 返回 `401/auth.token.reused`，同时撤销整个会话；复用后，同会话新 access token 访问 `/auth/me` 返回 `401/auth.token.revoked`。
- 复用后，同会话当前 refresh token 再刷新返回 `401/auth.token.revoked`。
- `current_epoch == expires_at_epoch` 时，access token 与 refresh token 均判定为 `auth.token.expired`。
- 相关契约、单元、边界、异常、路径、接口、端到端测试均通过；全量 `pytest -q` 通过。
- 文档与最终源码、契约、测试入口一致。

## Phase 1
### 目标
修正 `AuthenticationBindingMiddleware.dispatch` 的异常边界。阶段完成后，已知鉴权业务异常仍写入 `request.state.auth_fault`，未预期基础设施异常继续向上抛出，不再被包装为 `401/auth.token.invalid`。

### 依赖
- `src/infrastructure/middleware_chain/authentication_binding_middleware.py`
- `HttpFaultException`
- 统一异常呈现链路与现有 `request.state.auth_fault` 使用方式

### 契约
本阶段不新增对外响应模型，只修改鉴权绑定行为契约。

| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `AuthBindingKnownFault` | 已知鉴权故障 | 仅 `HttpFaultException` 可被中间件收敛为 `request.state.auth_fault`。 |
| `AuthBindingUnexpectedFailure` | 未预期绑定故障 | 数据库、仓储、资源挂载、线程桥接等异常必须向上抛出，交由统一异常链路处理。 |
| `HttpFaultPayload` | HTTP 故障载荷 | 保持既有 `kind`、`schema_version`、`status_code`、`error_code` 强类型字段，不新增任意扩展字段。 |

### 任务清单
- [x] 删除或改造 `dispatch` 中的宽泛 `except Exception` 分支。
- [x] 保留 `except HttpFaultException`，继续记录安全警告并写入 `request.state.auth_fault`。
- [x] 调整 `_normalize_auth_fault`，避免继续把任意异常转换为 `TOKEN_INVALID`。
- [x] 确认非法 JWT、过期 JWT、已撤销 session 仍按鉴权异常处理。
- [x] 确认仓储或资源故障不会污染 `request.state.auth_fault`。

### 关键代码片段
```python
try:
    token_payload = token_service.decode_token(token, expected_use=TokenUse.ACCESS)
    principal = await bridge.run_sync(...)
    request.state.authenticated_principal = principal
except HttpFaultException as exc:
    request.state.auth_fault = self._normalize_auth_fault(exc)
```

### 校验
- `dispatch` 中不存在会把任意 `Exception` 包装为 `AuthErrorCode.TOKEN_INVALID` 的路径。
- 构造非法 access token 时 `/auth/me` 仍返回 `401/auth.token.invalid`。
- 模拟仓储抛 `RuntimeError` 时 `/auth/me` 不返回 `401/auth.token.invalid`。

## Phase 2
### 目标
修正 refresh token reuse 处理。阶段完成后，旧 refresh token 被重复使用时，系统返回 `auth.token.reused`，并强制撤销同一 `token_session_id` 下所有活跃刷新令牌，使该会话下 access token 失效。

### 依赖
- Phase 1 异常边界已稳定。
- `src/application/refresh_access_token_usecase.py`
- `RefreshTokenRepository.revoke_token_session`
- `RefreshTokenInvalidationCommand` 及其 `TokenSessionInvalidationDetail`

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `RefreshTokenInvalidationCommand` | 刷新令牌失效命令 | 已有信封契约，外层包含公共头 `header` 与强类型扩展 `detail`。 |
| `TokenSessionInvalidationDetail` | 指定令牌会话失效扩展 | `kind="token_session"`，包含 `schema_version` 与 `token_session_id`，`extra="forbid"`。 |
| `RefreshTokenRepository.revoke_token_session` | 撤销令牌会话 | 按 `token_session_id` 撤销全部 `revoked_at is None` 的刷新令牌记录。 |
| `AuthErrorCode.TOKEN_REUSED` | 令牌复用错误码 | reuse 场景对外仍返回 `401/auth.token.reused`，但撤销操作必须已提交。 |

### 任务清单
- [x] 在 `rotated_to_token_id is not None` 分支中调用 `revoke_token_session`。
- [x] 使用 `current_epoch` 构造 UTC `revoked_at`，保证测试可确定。
- [x] 调整事务流，确保 reuse 撤销已 `commit` 后不会被 `except HttpFaultException` 回滚。
- [x] 保持 missing、subject mismatch、session mismatch、revoked、account disabled 分支原有回滚语义。
- [x] 保持 reuse 对外状态为 `401/auth.token.reused`。
- [x] 确认 reuse 后同会话 access token 通过中间件校验时返回 `auth.token.revoked`。

### 关键代码片段
```python
reuse_revocation_committed = False
try:
    if refresh_token_session.rotated_to_token_id is not None:
        revoked_at = datetime.fromtimestamp(current_epoch, tz=UTC)
        refresh_token_repository.revoke_token_session(
            token_session_id=token_session_id,
            revoked_at=revoked_at,
        )
        unit_of_work.commit()
        reuse_revocation_committed = True
        raise HttpFaultException(..., error_code=AuthErrorCode.TOKEN_REUSED, ...)
except HttpFaultException:
    if not reuse_revocation_committed:
        unit_of_work.rollback()
    raise
```

### 校验
- 第一次 `/auth/refresh` 成功并生成新 access/refresh token。
- 第二次使用旧 refresh token 返回 `401/auth.token.reused`。
- reuse 后使用第一次刷新得到的 access token 访问 `/auth/me` 返回 `401/auth.token.revoked`。
- reuse 后使用第一次刷新得到的 refresh token 再调用 `/auth/refresh` 返回 `401/auth.token.revoked`。

## Phase 3
### 目标
修正 JWT 过期边界。阶段完成后，`current_epoch == expires_at_epoch` 被判定为过期，只有 `current_epoch < expires_at_epoch` 才有效。

### 依赖
- `src/infrastructure/auth/jwt_token_service.py`
- `TokenPayload.expires_at_epoch`
- `AuthErrorCode.TOKEN_EXPIRED`

### 契约
| 英文名 | 中文名 | 中文说明 |
|---|---|---|
| `TokenPayload` | 令牌载荷 | 保持 `kind`、`schema_version`、`token_use`、`issued_at_epoch`、`expires_at_epoch`，`extra="forbid"`。 |
| `expires_at_epoch` | 过期时间戳 | 作为排他上界：`now >= expires_at_epoch` 时令牌过期。 |
| `AuthErrorCode.TOKEN_EXPIRED` | 令牌过期错误码 | access token 与 refresh token 在过期边界均返回该稳定错误码。 |

### 任务清单
- [x] 将 `_validate_payload` 的过期判断由 `now_epoch > expires_at_epoch` 改为 `now_epoch >= expires_at_epoch`。
- [x] 同步修改测试名称、注释和断言，移除“等于过期点仍有效”的旧语义。
- [x] 保持 `jwt.decode(..., options={"verify_exp": False})`，继续由本服务统一做手动边界判断。
- [x] 确认 `current_epoch=expires_at_epoch - 1` 仍可解码。

### 关键代码片段
```python
if now_epoch >= token_payload.expires_at_epoch:
    raise HttpFaultException(
        status_code=HTTPStatus.UNAUTHORIZED,
        error_code=AuthErrorCode.TOKEN_EXPIRED,
        message="令牌已过期。",
    )
```

### 校验
- `current_epoch == exp` 解码抛出 `HttpFaultException`，错误码为 `auth.token.expired`。
- `current_epoch == exp - 1` 解码成功。
- access token 与 refresh token 共用同一边界语义。
